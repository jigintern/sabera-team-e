## 決まったこと

実機で動かして確定したもの。**理由は右のリンク先にある。**

| 論点 | 決定 | 詳細 |
|---|---|---|
| 星図の出し先と大きさ | キャンバスに **528×330**。等級は「明るさ ＋ 点の大きさ」で表し、**点は丸く打つ** | [glass-output](02_glass-output.md) |
| 星座名 | 画像に焼かず**キャンバスのテキストで重ねる**。**画像を送ってから名前を送る** | [glass-output](02_glass-output.md) |
| 描き直しの条件 | **首が止まってから送る**（0.18 秒静止 ＋ 6° 以上）。減速に入ったら「止まる先」へ 1 枚 | [glass-output](02_glass-output.md) |
| 姿勢と方位 | 相対値はグラス、絶対方位の基準はスマホ。**十字とマーカーを重ねてもらう** | [coordinate-system](03_coordinate-system.md) |
| 精度と UX | **方位合わせは最初の 1 回だけ。±20°（星座の同定）で足りる** | [alignment-accuracy](14_alignment-accuracy.md) |
| 確定操作 | **押させない。** 精度条件が 2 秒続いたら自動で進む（**押す動作が頭とスマホを動かす**） | [app-flow](05_app-flow.md) |
| 観測地 | スマホの測位（融合 → GPS → 基地局）。取れないときだけ手入力 | [coordinate-system](03_coordinate-system.md) |
| パーミッション | `ACCESS_FINE_LOCATION` ＋ `ACCESS_COARSE_LOCATION` を起動時にまとめて聞く | — |
| 星表 | 自前計算。データは同梱の `data/`（d3-celestial / XHIP。帰属は `NOTICE`） | [coordinate-system](03_coordinate-system.md) |
| 星座判定 | 解説の主役は**グラスに出したラベルの先頭**。IAU 境界表は代用に格下げ | [narration](06_narration.md) |

## 未決定事項

決まったらこのファイルを更新する。**エージェントは勝手に埋めない。**

### ジェスチャーと入力

- **3 枠（`SINGLE_TAP` / `DOUBLE_TAP` / `HOLD`）がすべて埋まっている**（解説・一口メモ・声の質問）。
  ガイド中だけ意味を入れ替えている（[guide](16_guide.md)）。**枠を増やす手立ては無いまま**
- **「触れている間だけ録音」は SDK 0.6.0 では不可。** `HOLD` しか届かず、押下開始・指を離したイベントが無い。
  代わりに **`HOLD` で開始し、`SINGLE_TAP` で送信**する
- **暗騒音から決めたしきい値が屋外で足りるか**。ログの「暗騒音○→しきい値○」と「声○ms」を突き合わせる
- **マイクと星図が同じ BLE を食い合う**（録っている間は星図を送らない、で回避中）

### 星座と衛星

- **パス予報の下限を 20° で足りるか**（街中の建物と木で見えない高さ）
- **星が無い空で方角の手がかりが足りるか**（衛星モードは星を描かない）
- **ガイド 1 本の長さと段の数**（いまは 3〜5。実機で首がどれだけ疲れるか分かっていない）
- **toB の台本をどう配るか**（旅行会社が配るにはファイルか QR の口が要る）
- **案内矢印の64px・約10Hzが実機で読みやすく、星図や6DoFの転送を妨げないか**

### 出力とファーム

- **`FEATURE_VERSION` が読めないので、退路への切り替えをどう判定するか**
- **0.6.0 のキャンバス画像 8 枚を使うか**（分割しても総量は減らない）
- **首を振っている間に漏れるドリフト**（2 秒の首振りで 1.5°）を詰めるか
- **消灯時間・通知の抑止**をアプリが書き換えるか、ユーザーに任せるか
- 明るさのキャンバスでの反映は **team-e 実機で確認待ち**

### アプリ

- **BGM と読み上げのつり合いを実機で詰める**（合わせたのは Mac のスピーカー。本番は屋外のスマホ）
