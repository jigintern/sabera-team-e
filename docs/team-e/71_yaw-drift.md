# ヨードリフトと機体座標の実測記録

- **グラスのヨーは磁力計が無いので絶対方位を持たず、静止中も流れる**
- どう測って何を採ったかの記録
- 結論と使い方は [座標変換パイプライン ④](20_coordinate-system.md)
- 実機の手順は[実機確認の手順](60_field-check.md)

- **ここは「なぜその式なのか」の証拠置き場**で、読まなくても実装は追える
- ただし**数字を変えるときは必ずここへ戻る**（どれも実機で測った値で、机の上では再現しない）

## 生の加速度の軸（実測・2026-08-21）

- **ロールを出すには「どの軸が上か・どの軸が前か」が要る**
- SDK は生の加速度の軸を文書化して
いない。**うなずきのジャイロと重力から解けば約 40 秒で決まる**ことを実機で確かめた
（実装は main に入れていないが、**測った値は捨てない**。戻すときはここから始める）。

| | 結果 |
|---|---|
| 上の軸 | **+X** |
| 前の軸 | **−Y**（仮定していた「上 = −X・前 = +Z」は軸も符号も外れていた） |
| 標本 | 静止 865 件（水平 353 件）・ピッチ幅 76° |

- 仮定のままロール追従を入れると**ロールが 180° 反転する**（実機のログで −177° と出た）。
  **判定が済むまでスイッチを押せないようにしていたので実害は無かった**

### 加速度だけでは前方が決まらない（実測でつまずいた）

はじめは「静止時の前方成分は `sin(ピッチ)` になる」ことから、ピッチに対する傾きで前方を出した。
**これは首の傾きと分離できない。** 静止時の加速度は

```
a = 1000 ( sinθ·前 + cosθ·cosφ·上 − cosθ·sinφ·右 )      θ=ピッチ φ=ロール
```

なので、**見上げるときに首を傾ける癖があると、その分が前方の推定に入り込む**。
実機では同じ人・同じ機体で **−0.31 → +0.87** まで振れ、取付のずれとして読むと 15° → 42° に
なった。**セッションごとに変わる値は取付ではない。**

### ジャイロと組み合わせて解く（採用）

**うなずきは「右の軸まわりの回転」そのもの。** ジャイロは回転軸を直接返すので、
重力と違って首の傾きが混ざらない。

| 量 | 出し方 |
|---|---|
| **右** | ピッチが動いている間のジャイロの向き。ヨーが混ざった動きは落とす |
| **上・前** | 静止サンプルから解く。`Σcosθ·a` と `Σsinθ·a` を貯めると上と前について線形になる |
| **ロールの混入** | **右方向にしか出ない。** 右が確定しているので、解から右成分を落とせば消える |
| 前の符号 | 解から直に出る。勘で決める場所が無い |
| ジャイロの手系 | 確定した基底と突き合わせて**結果として**分かる（`右 = 前 × 上` と一致するか） |

- 残る誤差は `cosφ` の 2 次項だけで、**首を 18° 傾ける癖があっても 1° 以下**（JVM テストで固定）
- ピッチに幅が無いと上と前が分離できない（行列式が立たない）ので、**見上げ下ろしが必要**

### 符号が合っているかもアプリが確かめる

**人に「どちらに傾けたか」を覚えてもらう必要はない**（実機で実際に忘れた）。

- ロールは重力から出しているが、**首を右に傾けるのは前方軸まわりの正の回転**なので、
  ジャイロの前方成分が同じ角速度を返す。**出処の違う 2 つの傾きが +1 なら符号も倍率も正しい**
  （検査のしかたは実機で通した。実装は main に入れていない）
- 拾えるのは「ジャイロの手系の取り違え」と「`atan2` の符号ミス」。
  **前方を 180° 取り違えた場合はこの検査では見えない**が、そこはうなずきの回転軸で決まっている。
  役割が分かれているので両方要る
- **実機で通した**（2026-08-21・Pixel 9a）。首を左右に 15° ほど 3 往復して
  **傾き = 1.00（20 件）→ 0.99（68 件）→ 0.91（89 件）**。符号も倍率も正しい。
  **ただし「符号が正しい」と「視野端が合う」は別の話**で、後者は夜の屋外で測る

### 確定は取り消さない（実機で見つけた）

**一致（うなずきの回転軸のそろい具合）はうなずき全体の平均なので、確定したあとも下がり続ける。**
首を傾ける・左右を見るたびに落ち、実機では確定の 30 秒後に **0.84 → 0.76** まで下がって
「判定中」へ戻っていた。**同じ区間で基底そのもの（上=+X 90% / 前=-Y 89%）は動いていない。**

- **条件は「確定してよいか」の入口としてだけ使い、そのあとは解き続けた基底を渡す**
- 取り消していた頃は、そのあいだロールが**古い値のまま**星図に焼かれていた
  （首が水平でも −12° 回った絵が出る）。**符号を確かめる B2 の手順そのものが確定を壊していた**

## ヨードリフト率は **約 44°/分（0.73°/秒）**（実測）

グラスを机に置いて 3 分測った。**3 通りの独立した数字が一致している**（Pixel 9a、2026-08-20）。

| 出処 | 結果 |
|---|---|
| 1 分刻みのヨーの差 | **−44.1 / −44.2 °/分** |
| `sendNaviCourse` 実験中のランプ（8 秒） | −43.5 °/分 |
| 送信ログの方位（2 分 26 秒） | −44.4 °/分 |

計測中はピッチが 5° に張り付いていたので、**グラスは動いていない**。方位だけが動いている。

**想定より 1〜2 桁大きい。** 精度要求（[⑧](20_coordinate-system.md#-方位合わせ)）に当てると：

| 用途 | 破れるまで |
|---|---|
| 星図を空に重ねる（±2〜3°） | **4 秒** |
| ラベルを方向に置く（±5〜10°） | 8〜14 秒 |
| 星座の同定（±20°） | **27 秒** |

- **「経過時間で信頼度を落とす」作りは成立しない。** 数秒で落ちきる
- **ドリフトだけで星図が再送され続ける。** `REDRAW_DEG`（6°）を 0.74°/秒 で割ると 8.1 秒で、
  実測の送信間隔（約 8.5 秒）と一致する。**動かしていないのに 8.5 秒ごとにグラスが 0.7 秒消える**
- `要確認` **符号が安定するか。** 一度だけ同じ大きさで **+44°/分**が出た（動かしていた区間かもしれない）

## バイアスを引く案は否定された（実測）

**`gyroZDps` の平均はヨーのドリフト率と一致しない。** 静止した 2 分ぶんで：

| | 2 分目 | 3 分目 |
|---|---|---|
| ヨーのドリフト | −0.737 °/秒 | −0.737 °/秒 |
| **`gyroZDps` の平均** | **−0.059 °/秒** | **−0.058 °/秒** |

**12.7 倍ちがう。** ファームは**報告してこない何か**を 0.74°/秒 分ヨーに足している。
報告されるジャイロのバイアスを引いても直らない。

グラスを水平に保って 90° ずつ 7 回まわし、ヨーの変化と 3 軸の積分を比べた。

| 回転（ヨー） | 積分X | 比率 |
|---|---|---|
| −92.6° | −91.5° | 0.988 |
| −83.0° | −73.3° | 0.883 |
| −93.4° | −91.8° | 0.983 |
| −89.8° | −82.0° | 0.913 |
| −93.2° | −78.4° | 0.841 |
| **+74.4°** | **+69.1°** | 0.929 |
| **+89.4°** | **+75.4°** | 0.843 |

- **`gyroXDps` が鉛直軸。符号もヨーと同じ**（両方向で確認）。Y と Z は明確に小さい

### ここから「ヨーは方位と逆に回る」が出る（2026-08-21 に実機で確認）

実測 3 つを並べると符号が決まる。

| 実測 | 出どころ |
|---|---|
| 上 = 加速度の **+X** 軸 | 加速度軸の自動判定 |
| ジャイロは**右手系** | 同上（基底と回転の向きを突き合わせ） |
| `gyroXDps` とヨーは**同符号** | 上の 90°×7 回 |

右手系で回転軸が上を向いていれば、正の角速度は**上から見て反時計回り＝左**。
ヨーがそれと同符号なので、**左を向くとヨーが増える**。方位は右を向くと増えるので、**逆**。

```
方位 = オフセット − ヨー          （オフセット = 方位 ＋ ヨー）
```

- **実機での症状：** 誘導が「左へ 30°」と出ている状態で左を向くと、
  **30 → 40 → 50 と増えて目標が逃げた**。右を向かないと視野に入らない
- **足し算のままだと、首を振った分だけ 2 倍の速さでずれる。**
  合わせた瞬間だけ正しく、そこから動くと壊れる
- **符号は `sky/Coordinates.kt` の `azimuthFromYaw` / `headingOffsetFor` だけに置く。**
  4 箇所に散らすと、また取り違える
- **比率は平均 0.91、一度も 1.0 を超えない。** 減る方向にしか出ないので
  **10Hz のサンプリング損失**で確定（回転が速い・カクついたときに落ちる）
- **自前積分は回転 90° あたり 5〜15° 足りない。** スケール係数では直らない（速さで変わる）

## 採った方法 —「動いている間だけファームのヨーを足す」

**両方の弱点が逆なので組み合わせる。**

| 方式 | 静止中 | 回転 90° あたり |
|---|---|---|
| `yawDegrees` をそのまま | **44°/分** | 正確 |
| ジャイロの自前積分 | ほぼ 0 | **5〜15° 足りない** |
| **採用：動いている間だけ Δ`yawDegrees`** | **0°/分（実測）** | **正確** |

```
ジャイロの大きさ > 2°/秒  →  Δ(yawDegrees) を足す   （スケールが正しい）
それ以下                 →  何も足さない            （ドリフトを入れない）
```

- **「動いているか」はジャイロの大きさで決める。** ヨーの変化で判定すると
  ドリフトそのものを「動いている」と読む。静止中のノイズは 0.1°/秒、
  首振りは 10〜100°/秒 なので間は広い（しきい値 2°/秒）
- **スケール校正が要らない**のが効きどころ

## 動いている間のドリフトも引く

静止中を捨てるだけだと、漏れる量が**「動いている時間 × 0.74°/秒」**になる。
**符号が一定なので右に振って左に戻しても打ち消さず**、動いた割合に比例して溜まる
（動作 5% で 2.2°/分、10% で 4.4°/分）。

**ドリフト率は静止中にそのまま測れる**ので、動いている間もそれを引く。

```
静止が合計 5 秒たまったら  →  ドリフト率 = ヨーの変化 / 静止していた時間（0.3 で平滑化）
動いている間              →  方位 += Δ(yawDegrees) − ドリフト率 × dt
```

**「合計」なのは実機の症状から**（下の #132）。連続 5 秒を待つと、
星を見ている人は一度も測れない。

アプリが自分で測った値は**−0.735〜−0.744 °/秒**で、手計算の −0.737 °/秒 と一致した（3 回）。

## 実機で確かめた結果

**静止 4 分＋その間に 90° の回転を 8 回**はさんで測った（Pixel 9a、2026-08-20）。

| | 生の `yawDegrees` | **星図が使う方位** |
|---|---|---|
| 静止中のドリフト | **−44.5 °/分** | **+0.0 °/分** |

回転ごとの追従（生のヨーの変化 → 描いた方位の変化）：

| 生のヨー | 描いた方位 | 引かれた量 |
|---|---|---|
| −92.7° | −90° | 2.7 |
| −93.7° | −92° | 1.7 |
| −87.2° | −86° | 1.2 |
| −94.2° | −90° | 4.2 |
| +89.7° | **+95°** | 5.3 |
| +80.0° | **+82°** | 2.0 |
| +79.1° | **+80°** | 0.9 |
| +84.4° | **+88°** | 3.6 |

**マイナス方向では小さく、プラス方向では大きくなる。** ドリフト（常に負）を引いた結果として
向きが正しい。**補正が効いていなければ両方向で同じだけずれる**ので、これが効いている証拠になる。
引かれた量 1〜5° は「首振り 1.5〜2 秒 × 0.744°/秒」の見込みと合う。

- **ドリフトによる星図の再送が完全に止まった**（以前は 8.5 秒ごと。4 分で 0 回）
- 設定パネルのスイッチで生のヨーに戻せる（比較用）

## 静止が続かないと一度も測れなかった（#132・2026-08-27）

**症状 — 方位合わせのあとしばらくすると、星図の `S` が左へ流れていって元の位置に無い。**

原因は補正の式ではなく、**ドリフト率を測る条件**だった。

| | 測り直す条件 |
|---|---|
| 前 | **連続 5 秒**の静止（首を動かすたびに窓を捨てる） |
| いま | **静止していたサンプルの合計**（動いている間は足さないが、捨てもしない）。**1 回目は 2 秒・2 回目からは 5 秒** |

- **星を見ている人は 5 秒続けて止まらない。** 3〜4 秒おきに首を動かすと窓が毎回捨てられ、
  `driftRateDps` が **0 のまま**になる。0 のあいだは「動いている間だけ Δヨーを足す」ぶんに
  ドリフトがそのまま乗るので、**動いていた時間 × 0.74°/秒**が溜まり続ける
- ドリフト率は「静止中の変化 ÷ 静止していた時間」なので、**間に首振りが挟まっても足し直せる**
  （動いている間のぶんを足さなければ、連続で測ったのと同じ値になる）

### 症状の向きが計算と合う

| | |
|---|---|
| 補正後のヨーの誤差 | **負**（ドリフトが引かれずに残る。生のヨーは負に流れる） |
| 方位 = オフセット − ヨー | ヨーが負にずれる ＝ **方位が正にずれる** |
| 方位が正 ＝ 右を向いていると思い込む | 星図は右の空を描くので、**方位 180° の `S` は中央より左に出る** |

**報告どおり「S が左へ流れる」。** 式の符号ではなく、引く量が足りていなかった。

### 何度ずれるか（10Hz・3 分・首振り 30°/秒 で計算）

| 動作の割合 | 前 | いま |
|---|---|---|
| 静止 9 秒 / 首振り 1 秒（10%） | 0.0° | 0.0° |
| 静止 6 秒 / 首振り 1 秒（14%） | 0.0° | 0.0° |
| **静止 3 秒 / 首振り 1 秒（25%）** | **−33.3°** | **−0.7°** |
| 静止 2 秒 / 首振り 1 秒（33%） | −44.3° | −1.5° |
| 静止 0.5 秒 / 首振り 1 秒（67%） | −88.7° | −8.9° |

- **静止 6 秒以上なら前の作りでも合っていた。** 実機で 0.0°/分 と出たのは
  「静止 4 分＋90° 回転 8 回」で測ったからで、**測り方が症状を隠していた**
- **動いた直後の 1 サンプルは測定に使わない。** その差分にはしきい値 2°/秒 を
  下回るまでの減速ぶんが残っている
- **JVM テストで固定した**（`YawDriftCorrectorTest`）

### 1 回目の推定を待つぶんが残っていた（実機・2026-08-27）

**「さっきより良くなったけど少しだけ左にずれてる」。** 合計で数えるようにしても、
**率が 0 のあいだ補正はまったく効かない**ので、1 回目の推定を待つぶんが最初のずれとして残る。

| 動作の割合 | 1 回目を 5 秒待つ | **1 回目を 2 秒で出す** |
|---|---|---|
| 静止 3 秒 / 首振り 1 秒（25%） | −0.81° | **−0.07°** |
| 静止 2 秒 / 首振り 1 秒（33%） | −1.55° | −0.81° |
| 静止 1.5 秒 / 首振り 1 秒（40%） | −2.29° | −0.81° |

- **1 回目だけ短くする。** 2 回目からは 5 秒へ戻す。
  **恒久的に短い窓は採らない** — ヨーのノイズがそのまま率に乗り、±0.5° のノイズで
  2 秒窓のままにすると率が **−1.007°/秒**（1.4 倍）に太って 3 分で **+18.9°** ずれた
- 1 秒まで詰めても 2 秒より良くならない（ノイズ ±0.2° で −0.62° 対 −0.46°）
- **これで残るのは「増えない数度のずれ」だけ**になる見込み。
  それでも増え続けるなら**別の出どころ**（下の表）。**実機未確認**

### 実機のログを読んだら、前提のドリフト率が合っていなかった（2026-08-27）

**2 回のセッション（13:01〜13:16 と 13:19〜13:22）を `ドリフト監視` の行で読んだ。**

| 見たもの | 値 |
|---|---|
| `止めた量`（静止中に捨てたヨーの合計） | 9 分で **−18°**／3 分で **−14°** |
| `推定`（窓ごとのドリフト率） | **−0.014 〜 −0.396 °/秒**（10 倍以上振れる） |
| 同じ目印へ戻ったときの描画方位 | 1 分で **183° → 198°**（**＋15°／分**） |
| 台帳（2026-08-20・[70](70_measurements.md)） | **−0.74 °/秒（−44°/分）** |

- **方位が正へずれる ＝ S が左へ流れる。** 報告と一致する（向きの導出は上の表）
- **`止めた量` が小さすぎる。** 台帳の −0.74°/秒 なら、静止が半分あるだけで
  9 分に **−200°** 近く溜まるはずが **−18°** しかない。
  → **静止と判定できている時間が短いほうだった**（1 分のうち 26 秒）。
  率そのものも **−0.34 °/秒**で、台帳の半分（下の内訳）
- **`推定` が振れすぎている。** ドリフトはハードとファームの性質で、
  1 セッションのあいだに 10 倍動くものではない。**窓（5 秒）が短すぎて、
  しきい値 2°/秒 より遅い首振りが混ざっている**

### 内訳をログへ出したら、漏れの出どころが 1 つに決まった（実機・2026-08-27）

**「引くべき量」と「引いた量」を並べて出したら、その場で分かった。**

```
経過=1.0分 … 止めた量=-5°  推定=-0.048°/秒 通算=-0.333°/秒 静止計=26s 動作計=27s 補正計=+1°
経過=2.0分 … 止めた量=-10° 推定=-0.142°/秒 通算=-0.357°/秒 静止計=53s 動作計=55s 補正計=+4°
```

| | |
|---|---|
| **通算のドリフト率** | **−0.333 / −0.357 °/秒。** 1 分目と 2 分目でほぼ同じ ＝ **セッション中は動かない** |
| 窓ごとの推定 | −0.048 / −0.142 °/秒。**通算の 1/7 〜 1/2.5** |
| 引くべき補正（通算 × 動作計） | 0.357 × 28 秒 = **+10°/分** |
| 実際に引いた補正 | **+3°/分** |
| **漏れ** | **7°/分**（方位が正へずれる ＝ S が左へ流れる） |

**原因は窓と重みだった。** 窓ごとに測って重み 0.3 で平滑化していたので、
**4 分ぶん静止しないと率が追いつかない**。そのあいだずっと 1/3 しか引けていなかった。

### 率そのものが観測の最初の 2 分で上がっていた（実機・2026-08-27）

**通算平均に直したら 7°/分 → 0.6°/分 まで落ちたが、まだ「最後は目に見えて左」だった。**
ログを**分ごとに割り直す**と理由が出た。

| | 1 分目 | 2 分目 | 3 分目 |
|---|---|---|---|
| **その 1 分間の真の率**（`止めた量` の増分 ÷ `静止計` の増分） | **−0.214** | **−0.333** | **−0.348** |
| 使っていた率（通算平均） | −0.183 | −0.212 | −0.245 |

- **率が一定ではない。** 観測の最初の 2 分（静止 50 秒ぶん）で **−0.21 → −0.35** へ上がり、
  そこで落ち着く。落ち着いた値は前のセッションの **−0.333 / −0.357** と一致する
- **通算平均では追いつかない。** 最初の低い値をいつまでも引きずるので **0.1°/秒 足りず**、
  首を振るたびに漏れて積もる。**「最初はほぼ同じ、最後は目に見えて」はこの形**

### 採った方法 — 同じ比に**指数の重み**を掛ける

```
静止したサンプルごとに:
    薄める係数 f = exp(−その間の秒数 / 20秒)
    分母 = 分母 × f + その間の秒数
    分子 = 分子 × f + その間のヨーの変化
率 = 分子 ÷ 分母                            （静止 2 秒たまってから使う）
```

- **分母と分子を同じ係数で薄める**ので、**率が一定の間は薄めても値が変わらない**
  （既存の JVM テストの数値が 1 つも動かない）。変わったときだけ追いかける
- **薄めるのは静止しているサンプルのときだけ。** 首を振っている時間の長さで
  率が動いてしまわないように、動いている間は止める
- **時定数は静止 20 秒。** 30 分回した計算で、誤差が **±5° に収まる**。
  通算平均は **−7〜−11°** で増え続け、**10 秒**まで詰めるとノイズを拾って引きすぎる（+7°）
- **静止 2 秒たまるまでは 0 のまま。** 測れていないのに引くと、それ自体がずれになる

| 経過 | 通算平均 | **τ=20 秒** | τ=10 秒 |
|---|---|---|---|
| 3 分 | −7.0° | −4.6° | −3.4° |
| 5 分 | −7.2° | **−1.7°** | −0.1° |
| 10 分 | −7.6° | **+1.0°** | +2.7° |
| 20 分 | −10.9° | **−0.3°** | +1.3° |
| 30 分 | −9.2° | **+5.3°** | +7.0° |

**残るのは最初の 1〜2 分ぶん（2〜4°）だけ。** 率が本当に低い区間なので、
ここは測ってからでないと引けない。**方位合わせ時の地磁気（±5〜15°）より小さい。**

### サンプルの欠落も引けるようにした

**1 分のうち 5 秒（8%）がサンプルとして届いていない**（`静止計 + 動作計` が 55 秒しかない）。
星図の転送が 1 枚 0.3〜0.5 秒 かかるので、そのあいだの穴だと思われる。

- 1 サンプルとして数える時間の上限を **0.5 秒 → 2.0 秒** へ広げた。
  0.5 秒で切っていたころは**穴のあいだのドリフトを引けずに漏らしていた**（最大で 1.8°/分）
- 上限そのものは残す。`enterNavigationPage()` でヨーの原点が飛ぶので、
  そのときの巨大な差分をドリフトとして引かないため

### まだ残っているかもしれない出どころ

| 出どころ | 増えるか | 大きさ | 見分け方 |
|---|---|---|---|
| **方位合わせ時の地磁気** | **増えない** | **±5〜15°** | `補正計` が `要` とほぼ同じなのに左へずれている |
| 率を使い始めるまでの 2 秒 | 増えない | 0〜1° | 同上 |
| しきい値 2°/秒 より遅い首振り | 増えない（左右で相殺） | — | `止めた量` が実際の首振りに対して大きい |
| サンプルの欠落（2 秒の上限を超える穴） | **増える** | 欠落ぶん × 率 | `静止計 + 動作計` が経過時間に対して短い |

## 残っている誤差

**ボトルネックはドリフトから地磁気に移った。**

| 出どころ | 大きさ | 増えるか |
|---|---|---|
| **方位合わせ時の地磁気** | **±5〜15°** | **増えない** |
| パネルの取り付け誤差 | 未測定 | 増えない |
| 補正の残差 | 実測で 0.0°/分 | ほぼ増えない |

| 用途 | 要求 | 判定 |
|---|---|---|
| **星座の同定・解説** | ±20° | **成立する** |
| ラベルを方向に置く | ±5〜10° | **ギリギリ**（地磁気しだい） |
| 星図を空に重ねる | ±2〜3° | **足りない。ここは追わないと決めた**（[理由](74_alignment-accuracy.md)） |

## `sendNaviCourse` は答えにならない（実測）

**補正後の方位は `imuData` の `yawDegrees` に返らない。** 実機で確かめた（同上）。

- `course = 32.0°` を 2 秒おきに 5 回送っても、ヨーは **−58° → −66.7° と離れる方向**へ
  0.73°/秒 の等速で動いた ＝ ただのドリフト
- ナビページに入って `sendNaviStatus(START)` にしても同じ
- **`enterNavigationPage()` でヨーの原点がリセットされる**（−66.7° → −2.0° に 3 秒で飛んだ）。
  上流ドキュメントに無い挙動

そもそも**送る値を作る工程がキャリブレーションそのもの**なので、
返っていたとしてもこれ自体は答えにならなかった。
