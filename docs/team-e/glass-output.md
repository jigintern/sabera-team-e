# グラス出力の制約

グラスに何をどれだけ出せるか。**星座モードと衛星モードで共通の土台**なので、
他の文書はここを参照する。

## 表示面

| 項目 | 値 |
|---|---|
| パネル | **576×360**（キャンバスの座標系。左上が原点） |
| 画像 1 枚の実用最大 | **528×330**（16:10。バッファ上限から決まる） |
| 階調 | **緑の 8 階調**（3bit）。API に渡すのはグレースケール 0-255 |
| 黒 | **透明**（波導ディスプレイ。光る画素だけが肉眼の空を邪魔する） |
| スピーカー | **無い**（ハードとして存在しない。音はスマホから鳴らす） |

**画角は未確認。** 画素数が分かっても視野の何度を占めるかは別問題。

## 使う API

```kotlin
fun sendCanvasImage(id: Int, x: Int, y: Int, width: Int, height: Int, grayscale: ByteArray)
fun sendCanvasElements(elements: List<CommandManager.CanvasElement>)   // 差分更新
fun sendCanvas(elements: List<CommandManager.CanvasElement>)           // 全消去して並べ直す
fun removeCanvasImage(id: Int) / clearCanvas() / closeCanvas()
```

- **送るだけで画面が切り替わる。** 先にページを開かなくてよい
- **テキストは画像の手前に描かれる。** 星図とラベルが同じ画面に共存できる
- 同じ id に送ると座標ごと差し替わるので、星図は **id 固定の 1 枚**でよい
- 終わるときは `closeCanvas()` か `enterHomePage()`。送らないと星図が出たまま残る
- **リモコンの戻る操作でキャンバスは閉じられる。** 0.5.0 でリスナーが撤去されたので
  閉じられたことに気づけない。**いつでも送り直せる作りにする**

## 上限

### 画像（バッファ 380,000 バイト）

SDK が `IllegalArgumentException` で弾く条件（0.6.0 のソースで確定）：

| 条件 | |
|---|---|
| `0 <= id < 8` | 8 枚まで |
| `x >= 0` / `y >= 0` / `width > 0` / `height > 0` | |
| `x + width <= 576` / `y + height <= 360` | |
| **`width * height * 2 + 圧縮後サイズ <= 380,000`** | **置いてある全画像の合計** |

- **枚数より先にバッファが尽きる。** 設計は枚数ではなく**面積**で考える
- **576×360 は画素だけで 414,720 になり 1 枚でも入らない**（実機で確認）
- 16:10 で実用最大は **528×330（348,480）**。圧縮後に 23,899 バイト残る
  （12 方位 × 高度 5 段 × 季節 4 点の最悪値。544×340 では 2,055 バイトしか残らず弾かれる）
- 圧縮は **1 バイトに `(値3bit shl 5) or (連長 - 1)`**、連長 32 まで。
  **同じ数え方をすれば送る前に上限を判定できる**
- **ナビ表示中は使えない**（全体ルート画像とバッファを共有）

### テキスト（8 要素・190 バイト）

- `CanvasElement(id, x, y, width, height, text)`。**id 0..7 の 8 個・合計 190 バイト程度**
- はみ出した矩形は端で切られ、外に出た要素は描かれない
- `sendCanvasElements` は差分更新。**空文字を送るとその id が消える**
- 矩形は文字数から取る（120×22 では「みなみのかんむり座」が切れて読めなかった）
- 星座名は平均 **14.8 バイト**なので 8 個で約 118 バイト。
  FOV 40° の視野に入る星座は**平均 5.2 個・最大 11 個**で、**8 枠はちょうど足りる**

## 転送量と時間

実機（528×330・5 等・星座線あり）で測った圧縮後サイズは **6,000〜7,500 バイト**。

| 中身 | バイト |
|---|---|
| 真っ黒な背景の下限（面積 / 32） | 5,445 |
| 星と星座線 | 600〜2,000 |

- **8 割が背景の下限。** 面積を変えない限り転送量は減らない（星座線を切っても 1 割）
- 送るのは 200 バイトずつ。**1 本の実時間は測れていない**ので、
  20ms/本を見積りに使っている（`PACKET_MS_DEFAULT` の定数。**変えるなら再ビルド**）
- **0.6.0 で SDK が分割送信を直列化した。** 続けて送ってもチャンクは混ざらない。
  ただし呼び出しは積むだけで返るので、**転送が追いつかないと古いフレームが順番待ちで残る**
- **マイクを流すと毎秒 32,000 バイトが同じ BLE を通る**ので、星図の転送と食い合う
- `cancelPendingPackets()` で積んだフレームを捨てられそうだが `要確認`

## 描き直しの条件 —「首が止まったら 1 枚」

**転送中、グラスは前の絵を捨てて何も出さない。** 528×330 で 1 枚 1 秒近くかかるので、
動きに追従して送ると点いては消えるだけになる（実機のログ：1.2 秒周期・転送 1.0 秒で、
絵が出ているのは 0.2 秒だけ）。

| 条件 | 値 |
|---|---|
| 「動いている」とみなす角速度 | 0.1 秒で 1° 以上 |
| 止まったと判断するまで | **0.4 秒** |
| 送り直すずれ | **前に送った絵から 6° 以上** |

- **姿勢が動かなくても更新は要る。** 星は日周運動で **15″/秒**（4 分で 1°）動く
- **画像を送ってから名前を送る。** 逆順だと名前だけが 1 秒近く先に浮く
- 名前は差分更新なので毎フレーム送ってよい。**余った id は空文字で消す**
- **「なめらかに動かす」は原理的に無理。** 全画面を毎回送り直す方式なので、
  頭に追従する登録済みオーバーレイは名乗れない

## ファーム要件と退路

| 出すもの | 必要な `FEATURE_VERSION` | 2.1.0 台の実機での結果 |
|---|---|---|
| 分割レイアウト（`sendLayout`） | 2.0.0 | — |
| キャンバスのテキスト（`sendCanvas`） | 2.1.0 | 出た |
| **キャンバスの画像（`sendCanvasImage`）** | **2.2.0** | **出なかった** |
| `enterImageDisplayPage` ＋ `sendImage`（196×196） | 要件なし | 出た |

- SDK チームからは「使える」と聞いていたが**実機が追いついていなかった**。
  伝聞で確定させず送って確かめる価値があった
- **退路 = `enterImageDisplayPage` ＋ `sendImage`。** 196×196 で星図だけなら古いファームでも出せる
- **`FEATURE_VERSION` の読み出し経路が不明**なので、切り替えの判定方法は未決定

## 夜空で使うためのグラス設定

`sendSetting(name, value)` でグラス本体の設定を書き換えられる。キー一覧は上流ドキュメントに無く、
`sources.jar` の `CommandManager.SettingKey`（17 個）から読み取ったもの。**値の範囲と意味は未確認。**

| キー | なぜ効くか |
|---|---|
| `BRIGHTNESS_LEVEL` / `BRIGHTNESS_AUTO` | **暗順応。** 明るいまま出すと肉眼の空が見えなくなる |
| `SCREEN_OFF_TIME` | **見上げたまま何分も止まる**使い方。途中で消えると成立しない |
| `MESSAGE_DISPLAY_MODE` / `NOTIF_CONTENT_MASK` | **通知が出ると星図が消える**（同時には出せない） |
| `FONT_SIZE` | 星座名の大きさ＝入る文字数が変わる |
| `FEATURE_VERSION` | ファームの機能バージョン（読み出し経路が不明） |

- `sendWakeupTiltThreshold(degrees)` は**見上げでグラスが起きるしきい値**。
  星を見る姿勢と正面衝突するが、噛み合わせれば「空を見上げた瞬間に星図が出る」入り口になる
- `requestSystemStatus()` で**バッテリー・装着状態・充電状態**を要求できる。
  装着状態が取れれば外している間の送信を止められるが、**応答は `parseResponse` 経由で経路が不明**

## 実測しないと決められないこと

優先順に：

1. **パネルが視野の何度を占めるか** — FOV が決まる
2. **200 バイト 1 パケットの実時間** — 描き直しの間隔が決まる
3. **屋外での適正な明るさ** — 屋内で決めた値は暗闇では確実に明るすぎる
4. **ラベルの読みやすさ** — 8 個並べて重ならないか、緑 8 階調で読めるか

SDK チームへの質問：**`FEATURE_VERSION` の読み方**、**`SettingKey` の値の意味と範囲**、
**`parseResponse` の読み出し経路**、**`cancelPendingPackets` の挙動**、**パネルの表示画角**。
