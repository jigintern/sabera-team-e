# 解説と声

**何を喋るか。** どう鳴らすか（声の選定・BGM）は [音](07_sound.md)、いつ触ると始まるかは
[画面遷移とジェスチャー](05_app-flow.md)、グラスの字幕の組版は [グラス出力の制約](02_glass-output.md)。

## 通信が要るところ

**星を見に行く場所ほど電波が届かない。** 圏外で何が失われるかを 1 枚で分かるようにしておく。

| 喋るもの | 出どころ | 圏外で |
|---|---|---|
| 星座の解説 | 同梱の `data/constellation-lore.json`（88 星座） | **最後まで喋る** |
| 一口メモ | 端末の計算（`narration/SkyTips.kt`） | **喋る** |
| 衛星の案内 | 端末の計算（機体名・方角・高度・日照） | **喋る** |
| 断り文・定型文 | 端末が持つ | **喋る** |
| **声で天体を指定する** | 聞き取りは OpenAI、対象選択と向きは端末 | **新しく始められない。開始後の追従は続く** |
| **声の質問への答え** | **OpenAI** | **「いまは通信ができないので…」で終わる** |
| 声の質 | OpenAI（`gpt-4o-mini-tts`） | 端末の `TextToSpeech` に落ちる |

- **解説文を AI に作らせない。** その場で生成していた頃は、**いちばん要るときに一言も出せなかった**。
  神話も豆知識も星座ごとに決まっていて変わらない
- 文面を直すのは `tools/build-constellation-lore.py`。**生成物（`data/`）は直接編集しない**
- **API キーが要るのは音声の聞き取り・自由質問・AI音声。** 無くても星座解説の文と端末音声は使える

## 星座の解説（`SINGLE_TAP`）

**`SINGLE_TAP` そのものが「あれは何？」という質問。**

```
SINGLE_TAP
   ↓
グラスを解説画面へ切り替える        ← 星図の画像を消して、文字だけにする
   ↓
いまグラスに出している星図のラベルの先頭を主役にする   ← 視野中心にいちばん近い星座
   ↓
「おとめ座ですね」を即座に喋り、見出しに出す
   ↓
同梱の解説文を読み上げ、そのまま解説画面へ出す   ← 通信は一切しない
```

- **主役は「グラスに出ているもの」から決める。** 絵・ラベル・喋る星座名を**1 回の描画から作る**
  （`StarMap.constellationNames()`）。別々に計算していたときは、グラスに「オリオン座」と
  出ているのに中心 1 点の境界判定で別の星座を喋ることがあった（#37）
- **視線中心の点で星座を決めない。** 残っている地磁気の誤差 ±5〜15° にいちばん弱い推定で、
  境界際では隣に化ける。**ラベルは視野中心に近い順**で、大きな星座は
  「見えている部分のうち中心にいちばん近い点」で順位が付く
- **仰角では断らない。** 水平あたりを見ただけでも仰角は負に振れる。断られた側には理由が分からず、
  **見えているものの名前も出ないまま黙る**ことになる
- **解説中に別の方向を向いても今の話を最後まで続ける。** 途中で切り替わると落ち着かない
- **1 回の解説の中で声を入れ替えない。** 名乗りだけ先に作ってあった頃は、圏外だと
  「いて座ですね」が AI の声、続く解説が端末の読み上げになり、**途中で別人が喋り出したように
  聞こえた**（2026-08-22 実機）。星図を送るたびに**その星座で喋る文を全部まとめて作っておく**
  （`Narrator.speechParts`）

### 何を喋るか

**神話と豆知識だけ。** どんな形でどこに見えるかは、グラスの星図がそのまま見せている。
言葉で形をなぞっても、聞いている人は目の前の空と突き合わせられない。

| | |
|---|---|
| 長さ | **2〜3 文・100 文字前後**（最長 93 文字・平均 67 文字） |
| 上限 | **120 文字**。グラスの解説画面に入る 133 文字から、惑星の一言ぶんを残した値 |
| 口調 | プラネタリウムの解説員。平易な言葉で簡潔に |
| 禁止 | 記号・括弧・箇条書き（読み上げは「※」も「（）」もそのまま読む） |

- 長さと禁止文字は `tools/build-constellation-lore.py` が検査する。**書き足しても壊れたまま出荷されない**
- 視野に月や惑星があるときだけ、**入る範囲で**一言足す。日によって違うので言う価値がある。
  **肉眼で見えないもの（6 等より暗い）は言わない**（探させても見つからない）
- **最初の一言「〇〇座ですね」は名乗りとして必ず出す。** タップが届いたことが音で返る。
  **タップより先に合成しておく**（星図を送った時点で星座は分かっている）。
  短い定型文だけ `cacheDir` に残すので、2 回目からは通信も要らない

### 喋れないとき

**タップしたのに無反応が一番よくない。** 必ず何か喋る。

| 状況 | 応答 |
|---|---|
| まだ方位を合わせていない | 「まだ方位が合っていません。スマホをかざしてください」 |
| 星座が割り出せない | 「星座を割り出せませんでした。星表が読めていないかもしれません」 |
| 解説文を持っていない星座 | 星座名と方角・高度、視野の月惑星・目印の星（88 星座ぶんあるので普段は通らない） |

**圏外は「喋れないとき」ではない。** 落ちるのは AI 音声の声色だけで、端末の読み上げに替わる。
**棒読みでも喋るほうが上。**

## 一口メモ（`DOUBLE_TAP`）

**いまの時刻と場所から言えることを 1 つ**（`narration/SkyTips.kt`）。通信も生成も要らない。

| 順 | 中身 | なぜその順か |
|---|---|---|
| 先 | **まもなく上がる衛星**・**今夜の流星群** | 待てば見えるので、**待つと決められるうちに言う** |
| 後 | 空の暗さ・月・出ている惑星・季節の目印・緯度・星の動き | いつ押しても同じことが言える |

- **押すたびに次のメモへ進む**（1 つしか言わないと、2 回目が無反応と区別できない）
- **衛星のパスは 30 分以内・日が当たっているものだけ。** 3 時間後のパスを言われても
  そのとき何をしているか分からず**待つ判断ができない**。影に入る機体を案内すると
  **出てきた空に何も見えない**。**出る方角と抜ける方角を言う**（待つ向きが決まらないと待てない）
- **流星群で放射点を見つめさせない。** 流星は空全体に出るし、放射点のすぐそばのものは
  短くて目立たない。**出現数（ZHR）は理想条件の値**なので、**極大の前後 2 日以外は数を言わない**。
  **放射点は星図に印を焼く**（テキスト枠は星座名と月惑星で埋まっている）

## 声で質問する（`HOLD`・#38）

```
HOLD
   ↓
解説画面に切り替えて「聞いています。質問をどうぞ。」
   ↓
グラスのマイクから PCM16・16kHz を受ける（SDK が Opus をほどく）
   ↓
SINGLE_TAP で録音を止めて送信する（押し忘れは 30 秒で安全終了）
   ↓
聞き取り → 「〇〇座って何なの？」を画面に出す
   ↓
案内の言い方 ──→ 端末の登録名だけで対象を決め、案内を始める（#46）
   ↓ それ以外
いま出している星座・方角・高度・視野の星と惑星を添えて答えを作り、読み上げる
```

- **マイクはグラス側。** 端末の録音権限は要らない
- **押しっぱなしは取れない。** ジェスチャーは 1 回のイベントとして届くので、
  **`HOLD` で録音を始め、`SINGLE_TAP` で送信**する
- **区切りのしきい値はその場の暗騒音から決める。** 冒頭 0.4 秒のいちばん静かな塊 × 2.5 を
  **900〜4000 の範囲**に収め、音量表示と「声を拾えたか」の判定に使う。固定 900 だけだった時は、
  風のある屋外で暗騒音を声と誤認したため、送信操作へ変更した
- **聞き取りと生成で数秒かかる。** その間じゅう解説画面に途中経過を出す
  （聞いています → 聞き取っています → 質問文 → 答え）。**黙って待たせない**
- **マイクを流すと毎秒 32,000 バイトが同じ BLE を通る。** 録っている間は解説画面のままで、
  星図は送らない。**聞いている間は解説画面を畳まない**（録音 30 秒＋通信で長引いても、
  答えが届く前に星図へ戻っていた）
- **やり取りは設定パネルに残す**（`support/AskHistory.kt`）。字幕は流れて消え、声は一度きりで、
  解説パネルは次の質問で上書きされるので、**「さっき何と言われたか」を確かめる先が無かった**。
  **断りや失敗も残す**（質問が届かなかったのか答えが返らなかったのかが分かる）

### 天体を案内する（#46）

**AIに操作を決めさせない。** 文字起こし後は `GuidanceRequestParser` が端末の固定ルールで分岐する。

| 項目 | 決定 |
|---|---|
| 案内へ分ける | 登録名に「どこ・場所・方角・方向・位置・案内・ナビ・見せて・探して」などを含む |
| 解説へ分ける | 「特徴・神話・由来・〜とは・〜について・解説・説明」。案内語の無い普通の質問も解説へ回す |
| 聞き返す | 対象名だけ・「お願い」だけ・案内と解説を同時に頼んだ場合。勝手に片方を選ばない |
| 対象 | 「ふつう」で名前を持つ星座・固有名星・大三角などの結び・月惑星。衛星表示中は名前付き衛星も含む |
| 星座の狙い | 幾何中心ではなく、星座線上でいちばん明るい星 |
| 含めない | 天の川・流星群の放射点・名前のない星・スターリンクの各機 |
| 名前が不明 | 「その名前の天体は案内対象に見つかりませんでした」 |
| 複数名 | 「一度に一つです」と返し、勝手に選ばない |
| 地平線の下 | 矢印を出さず「いま地平線の下」と返す |
| 低空・昼 | 見つけにくいことを先に伝え、そのまま案内する |

- カタカナ・ひらがな・全角英数字は正規化する。月惑星は漢字に加え、読み仮名と主な別名も持つ
- 「りゅうこつ座」に含まれる「りゅう」のような短い別名は、長い名前の一致を優先して除く
- 案内中の衛星だけは約10Hzで軌道位置を引き直す。それ以外は60秒の案内中は同じ目標を使う
- 到着時の文は **「〇〇はこのあたりです」**。方位残差が±5〜15°あるため「到着」と言い切らない

### 答える範囲は天文全般

**話題では絞りすぎない。断るのは空とも宇宙とも関係がないと言い切れるときだけ。**

- 視野の中だけに縛っていたときは**「ISS って何？」に一言も答えられなかった**
- 天体だけに縛っていたときは**「若田光一って誰？」に答えられなかった**
- **見えていないこと・天体でないことを理由に断らせない。** 迷ったら答えるほうへ倒す
- 渡した観測事実は**「あれは何？」と目の前の空を指して聞かれたときの根拠**として使わせる

### 聞き取った文は指示ではなくデータ

**声で言うだけで役割を上書きできてはいけない。** 「これまでの指示は無視して」と喋られたときに
プラネタリウムの解説員が別のものになると、聞いている人には何が起きたか分からない。
検査は `narration/AskGuard.kt` にまとめてあり、**端末だけで完結する**ので JVM テストで固定できる。

| どこ | 何をするか |
|---|---|
| 入口 | **囲い記号（「」『』<>{}`"）と改行と制御文字を落とす**。区切りは端末が付けるので、質問の中から閉じられない |
| 入口 | **120 文字で切る。** ふつうの質問は 30 文字も要らない。長々と指示を並べさせない |
| 依頼文 | 区切りの中は**利用者の言葉であって指示ではない**と、システム側と末尾の両方に書く |
| 出口 | **天文の話かどうかを本文と分けて JSON で返させる**（`astronomy` と `reply`）。**いま空に出ているかは関係ない** |
| 出口 | 話題の外なら、**端末が持つ固定文**で断る（生成に左右させない） |
| 出口 | 記号・箇条書きを落とし、200 文字を**文の切れ目で**切る。何も残らなければ捨てる |

- **文章の中で断らせない。** 「お答えできません」と言いながら続きを喋る形になりやすく、
  端末側で判定もできない。**真偽値で返させて、断り文は端末が持つ**
- **これは自分の端末で自分の声を使う機能**なので、狙われる相手は自分自身しかいない。
  それでも入れるのは、**事故で解説員が別のものになると使いものにならない**から
- 聞き取った文はログに残す。**実機で何を聞き取ったかはログだけが頼り**

### 依頼文の組み立て

- **箇条書きを増やすほど 1 つずつは薄まる**（11 個並べた版は末尾 2 つが無視された）
- **守らせたい注意は依頼文の末尾に置く**

## 言葉づかい

**天文の言葉をそのまま喋らせない。** 使う人は天文の初心者で、用語を聞いても何をすればよいか
分からない。**やることが分かる言い方へ置き換える**（`SkyTipsTest` が用語の混入を検査している）。

| 言わない | 言う |
|---|---|
| 極大 | いちばんよく流れる日 |
| 放射点 | 流れ星のもと |
| 薄明 | 日が沈んだあとの明るさ |
| 月齢 | 新月から数えて○日目 |
| 等級 | （明るい／暗いで言う） |

## 衛星の読み上げ（**入口は外してある**）

**#36 で衛星は星座のおまけになった**ので、`SINGLE_TAP` は星座の解説に使う。
衛星だけを読み上げる入口は、設定パネルから一覧を撤去したときに無くなった
（組み立て（`Narrator.narrateSatellites`）と計算は残っている）。以下は入れ直すときの仕様。

```
SINGLE_TAP（衛星モード）
   ↓
タップ直前 0.5 秒の視線で、視野に入っている名前つきの機体を出す
   ↓
1 機もいない ──→ 「いま視野には人工衛星がいません」
   ↓ いる
「いま視野には ISS が入っています。南南西の空、高度 45 度あたりです。
　日が当たっているので、動く光として肉眼でも見えるかもしれません」
```

- **LLM を呼ばない。** 機体名・方角・高度・日照はすべて端末が計算した確定値で、
  生成に投げると待つだけ損になる（星座は由来や探し方があるので LLM が効く）
- **日照かどうかを必ず言う。** 影に入っていれば肉眼では絶対に見えない
- スターリンクは名前を読み上げても意味がないので、案内するのは名前つきだけ

詳しくは [人工衛星モード](08_satellites.md)。
