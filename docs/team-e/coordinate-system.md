# 座標変換パイプライン

星表の「シリウスは赤経 6h45m、赤緯 −16.7°」を、グラスの「(x, y) = (120, 47) に点を打つ」へ
変換する仕様。出力側の制約は [グラス出力の制約](glass-output.md)。

**間にある基準の違いは 4 つ。** 星表は 2000 年基準 / 地球が自転している / 観測地が違う /
頭の向きが違う。

## 全体像

**グラスは表示とセンサーに徹し、計算はすべてスマホ側。**

![システム構成](diagrams/system.drawio.svg)

![座標変換パイプライン](diagrams/pipeline.drawio.svg)

| 項目 | 決定 |
|---|---|
| 投影方式 | ステレオ投影（等角） |
| FOV | 30〜40°（既定 35°・**未実測**。設定パネルで 20〜50° を 1° 刻みで入れられる） |
| ロール | 地平線を水平に固定（デッドバンド 12° の追従を実装済み・**既定オフ**） |
| 星座の判定 | 視野中心を B1875.0 へ変換し、Roman (1987) の IAU 境界で一意に決める |
| 星表 | d3-celestial（BSD-3-Clause）を 5 等でフィルタして同梱 |
| 出力 | キャンバスの画像（星図）＋ テキスト（星座名） |
| 方位 | スマホ同期を標準、精度が要るときだけ天体アライメント |

## 実装方針

### 内部表現は単位ベクトル

角度→角度で書くと**天頂で方位角が定義できない**／**`cos h` で割れない**という 2 つの罠がある。
単位ベクトルなら ①〜④ がすべて 3×3 回転行列の積になり、特異点が消える。

```
v_screen = R_attitude · R_horizon(φ) · R_hourangle(H) · R_precession · v_catalog
```

- **歳差行列は起動時に 1 回、緯度の行列は場所が変わるまで固定**なので事前に合成する
- 毎フレーム変わるのは時角と姿勢だけ。1,627 個の星を毎フレーム変換するので効く

### 座標系の規約

**符号バグの温床。** 実装では 1 箇所に定数として置く。

| 決めること | 採用 |
|---|---|
| world 座標系 | ENU（X=東, Y=北, Z=天頂）。Android の `getRotationMatrix` と同じ |
| 方位角 | 北 = 0°、東回り |
| 手系 | 右手系 |

### 時刻

- **UTC をそのまま使ってよい。** `DUT1` は最大 13″ で歳差への影響も無視できる
- **`D = JD − 2451545.0` を直接計算する。** `JD ≒ 2,460,000` を Double で持つと精度が落ちる
- **端末時計のずれは別問題。** 1 分で 0.25°、**タイムゾーンの取り違えは 9 時間 = 135°**
- `syncTime()` は時刻を**グラスへ送る**もので、こちらの計算には関係しない

## ① 歳差

自転軸が約 26,000 年周期で首を振るため赤経赤緯の原点がずれる。

| 効果 | 量 | 扱い |
|---|---|---|
| **歳差**（J2000 → 2026 年） | **約 0.36°** | **必須。** 満月の直径に近く、無視すると星座線が明らかにずれる |
| 章動 | 17″ | 無視 |
| 固有運動 | 数十″ | 無視 |
| 光行差 | 20″ | 無視 |

## ② 恒星時

```
GMST = 18.697375 + 24.065709824279 × D    （時間単位）
LST  = GMST + 経度 / 15                    （東経を正）
H    = LST − α
```

係数が 24 でなく 24.0657 なのは、**恒星日が太陽日より約 4 分短い**ため。

## ③ 地平座標変換

```
sin h = sin φ · sin δ + cos φ · cos δ · cos H
A = atan2( −cos δ · sin H,  sin δ · cos φ − cos δ · sin φ · cos H )
```

大気差は高度 0° で約 29′、10° で約 5′、45° で約 1′。描画は Bennett の標準大気近似で
見かけの高度へ補正し、視線から星座を判定するときは反復して幾何学的高度へ戻す。

## ④ 姿勢

| 量 | 可否 | 理由 |
|---|---|---|
| pitch・roll | **絶対値が取れる** | 加速度計が重力を測る |
| yaw | **絶対値が取れない** | 磁力計が無い |
| 方位の変化量 | 取れる（ドリフトする） | ジャイロの積分 |

**未知数は方位オフセット 1 つだけ。**

`imuData` の 1 サンプル = 加速度[mg] / 角速度[dps] / ピッチ[度] / ヨー[度] / AR 起動からの経過[ms]。

- **`startImuData()` を呼ぶまで何も流れない**
- **`timestampMs` で間隔を計る。受信時刻を使わない**（BLE 経由で順序と間隔が乱れる）
- **送信キューが詰まるとサンプルが捨てられる**（実測 10Hz 程度。画像を送っている間も止まらない）
- **ロールは融合値に無いので 3 軸加速度から自前で出す**（`starmap/RollEstimator.kt` に実装）。
  ピッチは取付補正済みなのに生の加速度軸は未文書なので、
  **グラスを水平に置いて加速度ベクトルを 1 回測り、基準を作る**。
  **その 1 回がまだ済んでいないので、軸の割り当ては仮（上 = −X・前方 = Z）で、既定はオフ**

#### ヨードリフト率は **約 44°/分（0.73°/秒）**（実測）

グラスを机に置いて 3 分測った。**3 通りの独立した数字が一致している**（Pixel 9a、2026-08-20）。

| 出処 | 結果 |
|---|---|
| 1 分刻みのヨーの差 | **−44.1 / −44.2 °/分** |
| `sendNaviCourse` 実験中のランプ（8 秒） | −43.5 °/分 |
| 送信ログの方位（2 分 26 秒） | −44.4 °/分 |

計測中はピッチが 5° に張り付いていたので、**グラスは動いていない**。方位だけが動いている。

**想定より 1〜2 桁大きい。** 精度要求（[⑧](#-方位合わせ)）に当てると：

| 用途 | 破れるまで |
|---|---|
| 星図を空に重ねる（±2〜3°） | **4 秒** |
| ラベルを方向に置く（±5〜10°） | 8〜14 秒 |
| 星座の同定（±20°） | **27 秒** |

- **「経過時間で信頼度を落とす」作りは成立しない。** 数秒で落ちきる
- **ドリフトだけで星図が再送され続ける。** `REDRAW_DEG`（6°）を 0.74°/秒 で割ると 8.1 秒で、
  実測の送信間隔（約 8.5 秒）と一致する。**動かしていないのに 8.5 秒ごとにグラスが 0.7 秒消える**
- `要確認` **符号が安定するか。** 一度だけ同じ大きさで **+44°/分**が出た（動かしていた区間かもしれない）

#### バイアスを引く案は否定された（実測）

**`gyroZDps` の平均はヨーのドリフト率と一致しない。** 静止した 2 分ぶんで：

| | 2 分目 | 3 分目 |
|---|---|---|
| ヨーのドリフト | −0.737 °/秒 | −0.737 °/秒 |
| **`gyroZDps` の平均** | **−0.059 °/秒** | **−0.058 °/秒** |

**12.7 倍ちがう。** ファームは**報告してこない何か**を 0.74°/秒 分ヨーに足している。
報告されるジャイロのバイアスを引いても直らない。

#### 機体座標は X 軸が鉛直（実測）

グラスを水平に保って 90° ずつ 7 回まわし、ヨーの変化と 3 軸の積分を比べた。

| 回転（ヨー） | 積分X | 比率 |
|---|---|---|
| −92.6° | −91.5° | 0.988 |
| −83.0° | −73.3° | 0.883 |
| −93.4° | −91.8° | 0.983 |
| −89.8° | −82.0° | 0.913 |
| −93.2° | −78.4° | 0.841 |
| **+74.4°** | **+69.1°** | 0.929 |
| **+89.4°** | **+75.4°** | 0.843 |

- **`gyroXDps` が鉛直軸。符号もヨーと同じ**（両方向で確認）。Y と Z は明確に小さい
- **比率は平均 0.91、一度も 1.0 を超えない。** 減る方向にしか出ないので
  **10Hz のサンプリング損失**で確定（回転が速い・カクついたときに落ちる）
- **自前積分は回転 90° あたり 5〜15° 足りない。** スケール係数では直らない（速さで変わる）

#### 採った方法 —「動いている間だけファームのヨーを足す」

**両方の弱点が逆なので組み合わせる。**

| 方式 | 静止中 | 回転 90° あたり |
|---|---|---|
| `yawDegrees` をそのまま | **44°/分** | 正確 |
| ジャイロの自前積分 | ほぼ 0 | **5〜15° 足りない** |
| **採用：動いている間だけ Δ`yawDegrees`** | **0°/分（実測）** | **正確** |

```
ジャイロの大きさ > 2°/秒  →  Δ(yawDegrees) を足す   （スケールが正しい）
それ以下                 →  何も足さない            （ドリフトを入れない）
```

- **「動いているか」はジャイロの大きさで決める。** ヨーの変化で判定すると
  ドリフトそのものを「動いている」と読む。静止中のノイズは 0.1°/秒、
  首振りは 10〜100°/秒 なので間は広い（しきい値 2°/秒）
- **スケール校正が要らない**のが効きどころ

#### 動いている間のドリフトも引く

静止中を捨てるだけだと、漏れる量が**「動いている時間 × 0.74°/秒」**になる。
**符号が一定なので右に振って左に戻しても打ち消さず**、動いた割合に比例して溜まる
（動作 5% で 2.2°/分、10% で 4.4°/分）。

**ドリフト率は静止中にそのまま測れる**ので、動いている間もそれを引く。

```
静止が 5 秒続いたら  →  ドリフト率 = ヨーの変化 / 経過（0.3 で平滑化）
動いている間        →  方位 += Δ(yawDegrees) − ドリフト率 × dt
```

アプリが自分で測った値は**−0.735〜−0.744 °/秒**で、手計算の −0.737 °/秒 と一致した（3 回）。

#### 実機で確かめた結果

**静止 4 分＋その間に 90° の回転を 8 回**はさんで測った（Pixel 9a、2026-08-20）。

| | 生の `yawDegrees` | **星図が使う方位** |
|---|---|---|
| 静止中のドリフト | **−44.5 °/分** | **+0.0 °/分** |

回転ごとの追従（生のヨーの変化 → 描いた方位の変化）：

| 生のヨー | 描いた方位 | 引かれた量 |
|---|---|---|
| −92.7° | −90° | 2.7 |
| −93.7° | −92° | 1.7 |
| −87.2° | −86° | 1.2 |
| −94.2° | −90° | 4.2 |
| +89.7° | **+95°** | 5.3 |
| +80.0° | **+82°** | 2.0 |
| +79.1° | **+80°** | 0.9 |
| +84.4° | **+88°** | 3.6 |

**マイナス方向では小さく、プラス方向では大きくなる。** ドリフト（常に負）を引いた結果として
向きが正しい。**補正が効いていなければ両方向で同じだけずれる**ので、これが効いている証拠になる。
引かれた量 1〜5° は「首振り 1.5〜2 秒 × 0.744°/秒」の見込みと合う。

- **ドリフトによる星図の再送が完全に止まった**（以前は 8.5 秒ごと。4 分で 0 回）
- 設定パネルのスイッチで生のヨーに戻せる（比較用）

#### 残っている誤差

**ボトルネックはドリフトから地磁気に移った。**

| 出どころ | 大きさ | 増えるか |
|---|---|---|
| **方位合わせ時の地磁気** | **±5〜15°** | **増えない** |
| パネルの取り付け誤差 | 未測定 | 増えない |
| 補正の残差 | 実測で 0.0°/分 | ほぼ増えない |

| 用途 | 要求 | 判定 |
|---|---|---|
| **星座の同定・AI 解説** | ±20° | **成立する** |
| ラベルを方向に置く | ±5〜10° | **ギリギリ**（地磁気しだい） |
| 星図を空に重ねる | ±2〜3° | **足りない。天体アライメントが要る** |

#### `sendNaviCourse` は答えにならない（実測）

**補正後の方位は `imuData` の `yawDegrees` に返らない。** 実機で確かめた（同上）。

- `course = 32.0°` を 2 秒おきに 5 回送っても、ヨーは **−58° → −66.7° と離れる方向**へ
  0.73°/秒 の等速で動いた ＝ ただのドリフト
- ナビページに入って `sendNaviStatus(START)` にしても同じ
- **`enterNavigationPage()` でヨーの原点がリセットされる**（−66.7° → −2.0° に 3 秒で飛んだ）。
  上流ドキュメントに無い挙動

そもそも**送る値を作る工程がキャリブレーションそのもの**なので、
返っていたとしてもこれ自体は答えにならなかった。

## ⑤ 投影

### ステレオ投影

| 方式 | 式 | 保つもの | FOV 40° の歪み |
|---|---|---|---|
| 心射図法 | `r = tan θ` | 大円が直線になる | 6.4% |
| **ステレオ投影** | `r = 2 tan(θ/2)` | **角度と形（等角）** | **0%** |

**星座の「形」を見せて同定させる**のが本質なので等角を優先した。
星座線は円弧になるが、**折れ線に分割すれば実用上の差は無い**（実装は 3° ごと）。

### FOV 30〜40°

空のサイズ：満月 0.5° / こぶし 10° / **オリオン座 20°** / 北斗七星 25° / さそり座 40°

| FOV | 528px での解像度 | 5 等まで視野内 |
|---|---|---|
| 20° | 26.4 px/度 | 15 個 |
| **30°** | 17.6 px/度 | 33 個 |
| **40°** | 13.2 px/度 | 58 個 |
| 60° | 8.8 px/度 | 129 個 |

**528px あるので、潰れを理由に FOV を狭める必要はない。** オリオン座が画面の半分〜2/3 を
占める大きさとして 30〜40°。パネルは 16:10 なので**横 40° なら縦 25° で、星座は縦に切れやすい**。

### ロールは地平線を水平に固定

**ロール誤差は視野中心を動かさない**（中心まわりの回転）ので、**⑦ の星座判定には影響しない**。
効くのは絵だけで、中心から r 離れた星が `r · sin θ` ずれる。

| | 首を傾けたとき | 転送 |
|---|---|---|
| **固定（既定）** | パネル上の絵は変わらない | **再送ゼロ** |
| 追従 | 絵が回る | 傾けるたびに全フレーム再送 |

**デッドバンド付きの追従を実装した**（`Basis(az, alt, rollDeg)` ＋ 設定パネルのスイッチ）。

- **既定はオフ。** 生の加速度軸が未文書で、符号を取り違えるとずれが 2 倍になる。
  実機で水平に置いて 1 回測るまでオンにしない
- **しきい値は 12°。** 視野端（17.5°）のずれ 2·17.5·sin(θ/2) が 3.7° に収まる大きさで、
  これ以上細かく追うと**転送のほうが体験を壊す**（1 枚 0.4 秒画面が消える）
- ロール誤差は視野中心を動かさないので、**星座判定と天体アライメント（十字は中央）には効かない**

## ⑥ ラスタライズ

上限・転送量・描き直しの条件は [グラス出力の制約](glass-output.md)。
ここでは**絵の作り方**だけ。

### 点の大きさは画素数に比例させる

**528px に描くと 1px の点が 0.064° になる。** 196px のとき（0.173°）の 1/3 で、
そのままでは実機で見えない。

| 対策 | 効果（5 等・星座線あり） |
|---|---|
| 点の半径を `width / 196` 倍にする | 光る画素が 1,236 → 6,362 |
| **点を丸く打つ**（四角をやめる） | 6,362 → 5,857。四角だと一番明るい星が 17×17 の塊に見える |

### 明るさ

**黒が透明なので、光っている画素だけが肉眼の空を邪魔する。**
**屋内で決めた明るさは屋外の暗闇では確実に明るすぎる**ので、
等級の表現（明るさ ＋ 点の大きさ）は `BRIGHTNESS_LEVEL` とセットで決める。

## ⑦ いま見ている星座を決める

星座は「点」ではなく天球上の不定形な領域なので、「この点はどの領域に属するか」の判定が要る。
**IAU の星座境界**は天球全体を 88 個で隙間なく塗り分けているので、**1 点が属する星座は一意に定まる**。

| | 状態 |
|---|---|
| **中心の星座** | **Roman (1987) の境界表**（357 行、CDS VI/42）。of-date → J2000 → B1875 と戻して一意に照合する（実装済み・JVMテスト済み） |
| **周辺の星座** | 中心の星座を先頭にし、2 個目以降だけ星座線までの角距離で並べる |

- d3-celestial の `constellations.borders.json` は閉じた多角形ではなく隣接ペアの境界線なので**描画向き**
- 生成元は `tools/build-star-catalog.py`、同梱物は `data/constellation-boundaries.json`

### ノイズ対策

判定は数学的に一意でも、生のセンサー値に当てると 2 種類のノイズが出る。

| ノイズ | 対策 |
|---|---|
| **ツルをタップすると頭が動く** | 判定は**タップ直前 0.5 秒のラッチ値**から取る（実装済み） |
| 人間の頭は常に微小に揺れている | 境界から一定角度**内側に踏み込み**、その状態が**一定時間続いたときだけ**切り替える（未実装） |

1 回きりの判定なのでヒステリシスはまだ入れていない。内側マージンと保持時間は未決定。

## ⑧ 方位合わせ

### 必要な精度は用途で桁が違う

方位オフセットの誤差 δ に対する失敗率（高度 45°、FOV 40°、実データで測定）：

| δ | 星座の名前が変わる | 答えた星座が視野の外 |
|---|---|---|
| 5° | 24% | 0% |
| 10° | 41% | 0% |
| 15° | 62% | 0% |
| 20° | 75% | 1% |
| 25° | 83% | 8% |

**±20° まで、答えた星座はほぼ必ず視野の中にある。** ユーザーは点ではなく空の一帯を見ているので、
視野に入っている星座を答えるのは正解のうち。一方 15° の誤差は星図を **10.6°** ずらす（FOV 40° の 1/4）。

| 用途 | 要求精度 |
|---|---|
| 解説する星座を決める | ±20° |
| ラベルを方向に置く | ±5〜10° |
| 星図を空に重ねる | ±2〜3° |

**解説だけならスマホ同期で足りる。星図を重ねるなら天体アライメントが要る。**

### 段階 1：スマホ同期（実装済み・標準）

**グラスの十字とスマホのマーカーを重ねる。**

1. グラスのパネル中央に十字（128×128 の画像、キャンバスの id 1）を出す
2. スマホの画面中央に同心円のマーカーを出す
3. 腕の長さで持ち、**十字がマーカーの中心に重なった**ところで押す
4. そのまま約 1 秒静止し、直近 1.2 秒の複数サンプルから方位と仰角のオフセットを取る

方位は 0/360° をまたぐため円周平均を使う。6 サンプル以上・800ms 以上を集め、方位差の標準偏差
2° 以下、仰角差 1.5° 以下で、端末とグラス自身の動きも小さい場合だけ確定できる。結果の標準偏差と
サンプル数は設定パネルに残す（実装済み・JVMテスト済み、変更後の実機確認待ち）。

重なった時点で「眼 → スマホ」の向きが視線と一致するので、**スマホの位置ずれがそのまま
方位誤差になる問題が消える**（腕の長さ 50cm で 10cm 横にずれれば 11°）。

- **持ち方は顔の正面。** 合わせているのは「スマホの背面が向いている方向」と「グラスの視線」なので、
  スマホは**視線の上（腕の長さ）**に来ていないと意味がない
  （`Compass` は `remapCoordinateSystem(AXIS_X, AXIS_Z)` で背面の方位を読んでいる）
- 見上げた角度に合わせて**スマホも同じだけ倒す**。**仰角の差が 0 に近づくのが目印**
- **真上は避ける。** 背面がほぼ真上を向くと方位が定まらない。地平線から 45° くらいがよい
- **押した瞬間の値しか使わない。** 押したあとは自由に動かせる
- **星の名前を知らなくてよい。昼でも夜でも、曇っていてもできる**
- **十字を出している間は星図を消す**（バッファに 528×330 と十字は同時に入らない）
- **残る誤差は地磁気そのもの**（屋内・鉄骨・ケースの磁石で 10° 動く）。
  磁気センサーの信頼度も出す。低いまま合わせるとその誤差がそのまま星図に乗る

スマホの磁気が示すのは**スマホの方位**なので、**常時融合する定石は使えない。**
向きを揃える瞬間を作って移すしかない。

### 段階 2：天体アライメント（精度モード・実装済み／実機確認待ち）

同じ十字を**明るい星**に合わせて、その天体の真の方位からオフセットを決める。
**ユーザーは名前も方位も知らなくてよい。** 詳しい計画と他アプリの調査は
[星図を空に重ねる精度](alignment-accuracy.md)。

アプリの実装（`starmap/CelestialAlignment.kt` / `AlignmentTargets.kt`）:

- **合わせ先はアプリが選ぶ。** 同梱の 1.6 等までの 25 星＋**月・金星・火星・木星・土星**から、
  高度 15〜60°・明るさ・首を振る量で選ぶ。**視野 35° に候補は 0〜2 個しか入らないので同定は一意**
- **月が出ていれば最優先。** 名前を知らない人が居ない唯一の目印で、**昼でも使える**
  （空が明るいあいだは月だけを候補にする）。月・惑星の位置は `starmap/Ephemeris.kt` で、
  **地心視差（月で最大 57′）と木星・土星の摂動（最大 0.8°）まで入れて 0.05° の一致**を
  日食・大接近・太陽面通過・衝で確認してある
- **「右へ 24°」と誘導する。** 段階 1 の後は方位が ±15°、仰角は加速度計でほぼ絶対なので、
  横に振る量だけ言えば目標は視野に入る。グラスにはテキスト 1 要素で矢印を出す
- **確定はボタンではなく静止で取る**（1.2 秒窓の標準偏差 0.8° 以下が 3 秒続いたら、その窓の平均）
- **2 点目は 1 点目から 40° 以上離す。** 未知は方位・仰角の 2 つだけなので、
  2 点目は精度ではなく**取り違えの検出**に効く。残差が出たら差し替えずにそのまま見せる
- **段階 2 の間だけドリフト補正後のヨーで対応点を作り、最後に生のヨー基準へ戻す**
  （`bridgeToRawYaw`）。観測画面の補正が生のヨーから始まるため
- **段階 2 は任意。** 「さらに星に合わせる（精度モード）」から入る

- **基準天体は高度 20〜40° を選ぶ。** 誤差の伝播が `1 / cos h` なので、
  高い天体で校正すると誤差が拡大する（高度 80° で 5.8 倍）
- **2.5 等まで含めればどの月でも 10 個以上**が使える高度にいる（東京で確認済み）
- 月を使うなら**地心視差の補正が必須**（最大 57′）
- 太陽は位置計算が簡単で視差も 8.8″ で**最も正確**だが、
  **グラスの視野中心に太陽を入れさせてはいけない**（直視になる）。使うならスマホのカメラ越し

| 手段 | 昼 | 夜 |
|---|---|---|
| スマホ同期 | 使える | 使える |
| 天体アライメント・太陽 | 使える（カメラ越しのみ） | — |
| 天体アライメント・恒星 | — | 使える |

別案：**グラスに星図を出して姿勢ごと凍結し、左右に首を振って空に重ねてもらう。**
名前も方位も要らず、グラス単体で完結し、調整中は画像が凍結しているので転送コストがゼロ。
**パネルの取り付け誤差も一緒に吸収できる。**

## 星表データ

`tools/build-star-catalog.py` が [d3-celestial](https://github.com/ofrohn/d3-celestial)
（BSD-3-Clause）から取得・変換し、`data/` に生成する。詳細は [`data/README.md`](https://github.com/jigintern/sabera-team-e/blob/main/data/README.md)。

| ファイル | サイズ | 中身 |
|---|---|---|
| `data/stars.json` | 49 KB | 5 等までの恒星 1,627 個 |
| `data/constellations.json` | 21 KB | 88 星座の星座線＋日本語名 |
| `data/bright-stars.json` | 3 KB | 固有名のある 25 星 |

- 元期は **J2000 を実測で確認済み**（シリウス 0.7″、ポラリス 1.8″ の差＝丸め誤差の範囲）
- 元データの座標は `[lon, lat]` で `lon` は −180〜180 に折り返されているが、**生成時に 0〜360 に直してある**
- 日本語名は `tools/names-ja.json`。**88 星座すべてが埋まっていないと生成が止まる**
- **夜空の下は電波が悪いので、外部 API は使わずアプリに同梱する**
