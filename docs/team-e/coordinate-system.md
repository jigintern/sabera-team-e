# 座標変換パイプライン

- 星表の座標から、グラスに出す 196x196 の画像上の位置までをどう変換するかの仕様
- **議論の叩き台。`要決定` の付いた項目はまだ決まっていない**

## 全体像

```
星表（ICRS / J2000.0 赤経・赤緯）
        ↓ ① 歳差（章動・固有運動は要検討）
of-date の赤道座標 (α, δ)
        ↓ ② 恒星時 — 観測地の経度 + UTC → LST、時角 H = LST − α
時角系
        ↓ ③ 地平座標変換 — 観測地の緯度 φ
地平座標（方位角 A・高度 h）※ 真北基準
        ↓ ④ 姿勢 — グラスの IMU（実装中）またはスマホの ROTATION_VECTOR + 磁気偏角補正
視線ベクトル
        ↓ ⑤ 投影 — 視線中心の接平面へ
196x196 のスクリーン座標
        ↓ ⑥ ラスタライズ（グレースケール 0-255）
sendImage(width, height, grayscale)   ※ 量子化と圧縮は SDK 0.0.12 が行う
```

## ① 星表 → of-date

- 星表は ICRS / J2000.0 元期で配布されるものが多い
- **歳差** — J2000 から 2026 年で約 0.36°。星座同定の精度要求（`要決定`）次第では省略可
- **章動** — 最大約 17″。星座同定には効かない。省略してよい
- **固有運動** — 明るい星でも年 1″ 未満。26 年で最大 数十″。省略してよい
- **年周視差・光行差** — 光行差は最大 20″。省略してよい

`要決定` 歳差を入れるか。入れるなら簡易回転行列（ζ, θ, z）で足りる。

## ② 恒星時

- `GMST = 18.697375 + 24.065709824279 × D`（時間単位、D = JD − 2451545.0）
- `LST = GMST + 経度 / 15`（東経を正）
- 時角 `H = LST − α`
- 端末時刻は NTP ずれがありうるが、1 分ずれても 0.25° なので実用上問題ない

## ③ 地平座標変換

観測地の緯度 φ、時角 H、赤緯 δ から：

```
sin h = sin φ · sin δ + cos φ · cos δ · cos H
A = atan2( −cos δ · sin H,  sin δ · cos φ − cos δ · sin φ · cos H )
```

- `A` は**真北基準・東回り**
- **大気差** — 高度 0° で約 34′、10° で約 5′、45° で約 1′。地平線近く以外は無視できる
- `要決定` 大気差を入れるか。星座同定なら不要、地平線付近の見え方を正しくしたいなら入れる

## ④ 姿勢の出所

**ここが仕様の根幹。** 何の向きを「視線」とみなすかで、他の段の要求精度まで変わる。

### グラスの IMU（実装中・仕様未公開）

- **グラスの IMU 値を取る API は現在実装中で、近々解放される予定**（チーム情報）
- 0.0.11 時点では `enterImuDebugPage()`（IMU・照度のデバッグページを開く）しかなく、値は取れない
- これが入れば「グラスをかけて空を見上げる」が成立する

`要確認` 解放されたら真っ先に確かめること：

- 生値（加速度・ジャイロ・磁力）か、融合済み（クォータニオン / 回転行列）か
- **磁力計を含む 9 軸か、加速度＋ジャイロの 6 軸か** — 後述のとおり方位の可否が変わる
- 座標系の定義（グラスのどの軸が前方・上方か）
- サンプリングレートと、**BLE 経由のレイテンシ**

### IMU が来ても方位問題は残る

- **6 軸（加速度＋ジャイロ）の場合** — 重力を基準にできるので**仰角は高精度**で取れるが、**方位（ヨー）には絶対基準が無く積分ドリフトする**
- **9 軸（磁力計込み）の場合** — 方位も取れるが、磁気誤差はグラス側でも同じく乗る。むしろ頭部装着の電子機器なので、機体自身の磁気ノイズを受けやすい

つまり **IMU の解放で改善するのは主に仰角**で、方位の不確かさは別途つぶす必要がある。

### 方位の絶対基準をどうするか

- 磁気センサーの方位精度は環境次第で **±5〜15°**
- 天文側の変換をどれだけ厳密にしても、ここが支配的な誤差になる
- `要決定` 対策
  - 何もしない（星座を大づかみに示すだけなら許容できるかもしれない）
  - **明るい星でアライメント** — 見えている 1 等星を指定してもらい、そこを基準にオフセットを決める。天体を使った校正なので原理的に最も正しい
  - ジェスチャー（`SINGLE_TAP` / `HOLD`）で表示を回転させ、見えている空に合わせてもらう
  - 磁気を使わない相対姿勢でドリフトを抑え、初期方位だけ磁気か天体で決める

### フォールバック

IMU API が間に合わない、または精度が足りない場合：

- スマホを「指し棒」として空にかざし、グラスは結果の表示器に徹する
- Android の `SensorManager.getRotationMatrixFromVector()`（`TYPE_ROTATION_VECTOR`）で回転行列を得る
- world 座標系は **ENU**（X = 東, Y = 北, Z = 天頂）
- **`ROTATION_VECTOR` の Y 軸は磁北**。`GeomagneticField.getDeclination()` で真北に直す（日本では西偏 7〜9° 程度）
- 端末の持ち方は `SensorManager.remapCoordinateSystem()` で吸収する

→ **姿勢の取得を1つのインターフェースの裏に隠し、グラス IMU とスマホセンサーを差し替えられる形にしておく。**

## ⑤ 投影

- 視線方向を中心とした接平面に投影する
- `要決定` 投影方式
  - **gnomonic (TAN)** — 大円が直線になる。視野が広いと周辺が大きく歪む
  - **stereographic (STG)** — 等角。**星座の"形"が保たれる**ので、形を見せる用途に向く
- `要決定` 画角（FOV）
  - 196x196 に何度分を入れるか
  - 星座 1 つを収めるなら 30〜40°程度が目安（オリオン座で約 20°）
  - 広くすると star hopping しやすいが、1 星あたりの画素が減る

## ⑥ ラスタライズ

出力先は `sendImage`。**0.0.12 で引数の意味が変わる破壊的変更が入る**（上流 PR #7、DRAFT）。

| 版 | シグネチャ | 渡すもの |
|---|---|---|
| 0.0.11（現在） | `sendImage(width, height, encodedBitmap)` | **自前で 3bit 量子化 + RLE 圧縮**したバイト列 |
| 0.0.12（作業中） | `sendImage(width, height, grayscale)` | **1 画素 1 バイトのグレースケール**（0-255、左上から行優先）。量子化と圧縮は SDK |

- **0.0.12 を待てば RLE エンコーダを自前で書かなくてよい。** ここは実装せずに待つ
- 上流サンプルに `GlassImage.kt` が入る予定（`toGlassGrayscale()` / `testPatternImage()`）。縮小と輝度抽出はそのまま使える
- サイズ上限は **196x196**（`GLASS_IMAGE_MAX_SIZE`）。超えるとファーム側で弾かれ、何も表示されない

残る設計判断：

- `要決定` 星の等級をどう表現するか
  - グラスは **3bit（8 階調）**。SDK が量子化するので**量子化方法は制御できない**（ディザの有無なども不明）
  - 明るさだけで等級を出すと潰れる。点の大きさ（1px / 2px / 3px）との組み合わせが現実的か
- `要決定` 星座線を描くか、線の階調をどうするか
- `要決定` 星座名の文字を画像に焼くか、テキストとして別ページに出すか
  - 196x196 に日本語を焼くのは厳しい。`enterEmptyScreenPage()` との使い分けを決める
  - **画像とテキストは同時に出せない**（ページ遷移が要る）

## 未検証・外部依存

- `sendImage` は **team-e の誰もまだ実機で試していない**
