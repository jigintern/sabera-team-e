# 画面遷移とジェスチャー

何を触ると何が起きるか、そのときグラスとスマホに何が出ているか。
出力の制約は [グラス出力の制約](glass-output.md)、座標変換は [座標変換パイプライン](coordinate-system.md)。

## 役割分担

**操作系はグラスで完結させる。スマホは見なくても使える。**

| | 役割 |
|---|---|
| **グラス** | 星図と星座名を出す。ジェスチャーで操作を受ける |
| **スマホ** | 計算する。音声を鳴らす。**同伴者に見せる**。詰まったときの整備画面 |

- グラスをかけている人は空を見ていて**スマホは見ない**
- 星を見に行くのは複数人のことが多く、**グラスは 1 人しかかけられない**ので、
  スマホ画面は同伴者のためにある
- **例外は初回の接続だけ。** `showAutomaticSelectionDialog(activity)` が Activity を要求するが、
  `connectToLastDevice()` を呼んでおけば 2 回目以降は自動接続になる
  （初回かどうかは `hasLastConnectedDevice` で分岐できる）

## ジェスチャー

使えるのは 3 つだけ。**3 枠はすべて埋まっている。**

| ジェスチャー | 割り当て | 挙動 |
|---|---|---|
| `SINGLE_TAP` | **解説の開始／停止** | 解説画面へ入る。**出しているあいだのタップは「もう終わり」**で、止めて星図へ戻る |
| `DOUBLE_TAP` | **人工衛星を重ねる／隠す** | いつでも有効。**モードの切り替えではない**（#36） |
| `HOLD` | **声で質問する**（#38） | 「聞いています」→ 黙ったら終わり → 答えを喋る |

- **「あれは何？」は視線の向きで完全に決まる**ので、**タップそのものが質問になっている**。
  最初の一言に音声入力は要らない
- **方位合わせは `HOLD` から外してスマホのボタンだけにした**（#38 に枠を渡した）。
  合わせ直しは急がないので、スマホを見られる場面で押せば足りる
- **解説画面から星図へ戻すのは 2 つだけ**（#40）。**タップ**＝止めて戻る、
  **読み上げ終了の 5 秒後**に自動。枠は増やしていない
- **首の向きでは戻さない。** 一度は「首を振ったら空を見たいということ」として入れたが、
  **解説を読んでいる途中で見上げただけで消えた**。読み終わらないまま星図に戻るほうが困る
- 自動で戻す時計の**起点はタップではなく読み上げの終わり**（合成が遅れると読む前に消える）。
  音が鳴らなかったときは 25 秒待つ（**騒がしい場所では文字が主役**なので、読み終わる前に消さない）
- もともと `DOUBLE_TAP` に当てていた「もっと詳しく」は**行き先を失った**。
  どちらかをスマホ側のボタンに追い出すことになる
- `gestureEvents` は `SharedFlow` なので、**購読前のジェスチャーは受け取れない**。
  接続完了 → 購読開始 → 「準備できました」の順を守る
- **リモコンのイベントは 0.5.0 で撤去された**ので拾えない

## グラスに何を出すか

**キャンバス（576×360）に星図画像を置き、その手前に星座名を重ねる。**

```
┌─────────────────────────── 576 ───────────────────────────┐
│   おとめ座                        しし座                    │  ← テキスト（8 要素・190B）
│         ·      ·                                           │
│      ·      ·        ·                                  360│
│         ·         ·                                        │  ← 画像（528×330 まで）
│              ·                                             │
└────────────────────────────────────────────────────────────┘
```

| 出すもの | API | 更新 |
|---|---|---|
| 星図 | `sendCanvasImage`（id 固定の 1 枚） | 首が止まってから。実測 332〜390ms＋描画待ち 200ms |
| 星座名 | `sendCanvasElements`（差分更新） | 毎フレーム。数十 ms |
| 月・惑星の名前 | 同じテキスト枠。**星座名より先に置く**（月と 8 惑星） | 画像と一緒 |
| 大三角の名前 | 同じテキスト枠を **1 つだけ**借りる | 画像と一緒 |
| 一等星の固有名 | 同じテキスト枠を **2 つまで**借りる。全天に 21 個しかなく視野には 1 つあるかないか | 画像と一緒 |
| 地平線・方位の文字 | **画像に焼く**（テキスト枠を使わない） | 画像と一緒 |
| 月の満ち欠け | 画像に焼く。**太陽のある側が光る**ので、太陽の方向を投影して向きを決める | 画像と一緒 |

**解説文もグラスに出す**（#40）。ただし**星図とは同居させず、専用ページに切り替える**。

以前は「190 バイトでは入らない」として出さない決定だったが、星図を消せば置く先ができる。

```
┌─────────────────────── 576 ───────────────────────┐
│ おとめ座 南南西 45°          ← 見出しは出したまま
│ 麦の穂を手にした、農業の女神の  ← 本文は 2 行ずつ「めくる」
│ 姿です。                                          │
└───────────────────────────────────────────────────┘
```

**8 行ぶん置いたら、実機で最初の 1〜2 行が消えて途中から始まった**（2026-08-22）。
190 バイトは 1 電文あたりの上限だと読んでいたが、**画面に置ける合計でもある**らしく、
分割して送っても後から送ったぶんに押し出される。

そこで**字幕のようにめくる**。1 枚は見出し 1 行＋本文 2 行の **189 バイト**で 1 電文に収まるので、
**何バイトまで置けるかの解釈に関わらず消えない**うえ、長い解説も切らずに最後まで出せる。

| | 値 |
|---|---|
| 1 行 | **19 文字**（`LABEL_CHAR_WIDTH` からの計算。**実測ではない**） |
| 1 枚 | 見出し 1 行＋本文 2 行＝**38 文字・189 バイト・1 電文** |
| めくり | 1 文字 150ms・最短 2.6 秒（読み上げはおよそ 7 文字／秒） |
| 上限 | 8 枚（304 文字）。解説文はこの中に収めてある |

- **1 行に何文字入るかだけが未実測。** `LABEL_CHAR_WIDTH = 28` は見積りで、実機で分かっているのは
  「120 画素に 9 文字は入らなかった」ことだけ。**数えたら定数 1 つを直せばよく、作りは変わらない**
- **同じ行は同じ場所に置き、行を組み直さない。** 組み直すとファームが前の行の末尾を残す（「る」問題）
- **見出しが空でも本文を繰り上げない。** 名前が付いた瞬間に本文が 1 行下がって全部書き直しになる
- **めくり終わるまで星図へ戻さない。** 読み上げが先に終わっても、字幕が残っていれば待つ
- **視野中心の十字はやめた。** 星見アプリはどれも出しておらず、解説画面が主役の星座を
  名前で出すようになったので、いちばん価値のある画面中央の画素を空けた

## 画面遷移

![画面遷移](diagrams/screen-flow.drawio.svg)

- **キャンバス 1 枚で回る。** ページ遷移が要らないので、状態はほぼ「観測中かどうか」だけ
- **方位合わせ中は星図を消して十字だけを出す**（バッファに同時に入らない）
- **十字は 6DoF が来るまで送り直す。** 観測画面から「方位を合わせ直す」で来ると、
  **あちらの後片付け（`stopImuData` と `closeCanvas`）がこちらの描画より後に走る**ことがあり、
  送ったばかりの十字が消えて 6DoF まで止まる（2026-08-22 実機）
- **「つながっているのに返事が無い」を出せるようにする。** BLE がつながっていれば
  `connected` は true のままなので切断ダイアログは出ない。実機では、グラスが再起動したあと
  6DoF も画像も一切返さないまま「6DoFを待っています」が出続けた（2026-08-22）。
  **10 秒たっても 6DoF が 1 件も来なければ**「グラスから返事がありません」に変え、
  **送り直す／グラスを再起動**を出す。**このグラスに電源ボタンは無い**ので、
  電源を入れ直す手段は `GlassClient.reboot()`（デバッグシェルの `dbg reboot`）しかない
- **解説中はグラスが解説画面に切り替わる**（#40）。星図の画像を消して文字だけにする。
  戻るときは星図を 1 枚送り直すので、**332〜390ms は暗いまま**

## スマホの画面

**ホーム → 接続 → 方位合わせ → 星図**の 4 画面。星図の画面が本体で、
**上部バーの「衛星モード」で星座 ⇄ 人工衛星を切り替え、「設定」で調整と記録を別ページに畳む**。

```
┌─────────────────────────────┐
│ 現在の星空   [衛星モード][設定]│  ← 衛星モード中はボタンが点く
├─────────────────────────────┤
│  グラスに表示している星空      │
│  ┌───────────────────────┐  │  ← 送った画像そのもの（緑 8 階調に寄せた色）
│  │        · ·  ·         │  │     名前はグラス側が描くのでここには出ない
│  └───────────────────────┘  │     出す前は「何を待っているか」を回して出す
│  グラスの向きを止めると更新    │
├─────────────────────────────┤
│ 星座解説                     │
│ 解説を読み上げています        │
│ さそり座                     │
│ 狩人オリオンを刺した、さそり…  │
├─────────────────────────────┤
│  [ この星空を解説する ]       │
│  [ 方位を合わせ直す ]         │
└─────────────────────────────┘
```

| 要素 | 中身 |
|---|---|
| プレビュー | グラスに送った画像そのもの。**同伴者に見せる用途にもなる** |
| 待ちの表示 | 星表・TLE・測位・転送。**何を待っているかを書く** |
| 解説／案内 | 進み具合と本文。**タップはグラス側なので出力専用** |
| いま空に出ている | 衛星モードだけ。`●` は日照、`○` は地球の影。上昇中か・最接近まで何分か |
| **いまの空** | 空の状態・**月齢と輝面**・視野の月と惑星・描いている等級・衛星の数。**同伴者が見るぶん** |
| 設定ページ | **見出しごとの区画**にする。いまの空 → いま空に出ている → 見え方（空の濃さ・星座絵・目印・人工衛星）→ グラスの明るさ → 音（声・読み上げ音量・BGM）→ 観測の状態（6DoF・方位合わせ・大きさ・観測地・いま送る／消す）→ 記録 |

明るさは手動5段階のスライダーだけを置く。SDKから現在値を読み戻せないため、表示するのは
**このアプリが最後に送った値**。段階が変わると自動調整を無効化して値を送り、直前の星図を
再送して見た目へ反映する。ドラッグ中の値をすべて転送キューへ積まないよう、最新値だけをまとめる。

- **解説のカードはボタンの上**（音声が使えない環境ではテキストが主役になる）
- **見出しの中身を見出しどおりにする。** 以前は「ログ」という 1 枚のカードの中に
  星座絵・目印・声・BGM・音量まで入っていた。**BGM を切りたい人はログを開かない**ので、
  触れるはずの設定に辿り着けなかった
- **観測中はスマホを消灯させない。** 音の出し先はスマホのスピーカーで、同伴者はここで空を見る。
  30 秒で消える既定のままだと、暗い屋外でロック解除を繰り返すことになる
- **戻るキーは 1 つ前の画面へ。** 既定のままだと戻るでアプリが終わる。
  設定パネルを開いていれば閉じるだけ、星図の画面では確認を挟む
  （**やめると方位合わせからやり直し**になるので、一度の誤操作で畳まない）。
  ホームでは受けない（**そこは終わってよい場所**）
- **画面は縦固定。** 回転で Activity が作り直されると、グラスに置いたテキスト枠の記憶が消えて
  実物のラベルだけが残る。方位合わせは顔の前にスマホをかざす操作なので、いちばん回りやすい
- **上のバーに置くのは「設定」だけ。** 衛星の切り替えはグラスのダブルタップと設定に置いた
  （空を見ている人はスマホを見ないので、常設する意味が無い）
- **「いまの空」は他の星見アプリが必ず出している情報**に合わせた（空の状態・月齢・惑星）。
  グラスには出さない（かけている人が読めるのは星図と名前まで）
- **位置と時刻を出すのは、間違っていても星図が「それらしく」出てしまうから。**
  タイムゾーンの取り違えは 135°、時計の 1 時間ずれは 15°。
  どちらもユーザーには気づけず、「AI が間違っている」と誤解される
- **衛星モードは星座モードと同じ並び**（プレビュー → 一言 → 案内のカード → ボタン 2 つ）。
  増やすのは中身だけで、要素は足さない

### 待ち時間の見せ方

**このアプリは黙る場面が多い。** 画面が切り替わったのに何も出ないと壊れたと思われる（`ui/Loading.kt`）。

| 待つもの | かかる時間 | 出す場所 |
|---|---|---|
| 人工衛星の TLE（10,748 機） | 1〜2 秒 | 画面の先頭 |
| **1 枚目の転送** | **実測 332〜390ms＋描画待ち 200ms** | **プレビューの枠の中** |
| 転送中（2 枚目以降） | 同上 | プレビューに札を重ねる |

**転送中はグラスから絵が消える。** スマホのプレビューは前の絵のままなので、
食い違いを札で明示する（`送信中（グラスは一時的に消える）`）。

## 星座の解説

**`SINGLE_TAP` そのものが「あれは何？」という質問。**

```
SINGLE_TAP
   ↓
グラスを解説画面へ切り替える        ← 星図の画像を消して、文字だけにする
   ↓
いまグラスに出している星図のラベルの先頭を主役にする   ← 視野中心にいちばん近い星座
   ↓
「おとめ座ですね」を即座に喋り、見出しに出す
   ↓
同梱の解説文を読み上げ、そのまま解説画面へ出す   ← **通信は一切しない**
```

- **解説文は端末が持っている**（`data/constellation-lore.json`・88 星座）。
  **星を見に行く場所ほど電波が届かない。** その場で AI に作らせていた頃は、
  いちばん要るときに一言も出せなかった。神話も豆知識も星座ごとに決まっていて変わらない
- **主役は「グラスに出ているもの」から決める。** 絵・ラベル・喋る星座名を
  **1 回の描画から作る**（`StarMap.constellationNames()`）。別々に計算していたときは、
  グラスに「オリオン座」と出ているのに中心 1 点の境界判定で別の星座を喋ることがあった（#37）
- **視線中心の点で星座を決めない。** 残っている地磁気の誤差 ±5〜15° にいちばん弱い推定で、
  境界際では隣に化ける。**ラベルは視野中心に近い順**で、大きな星座は
  「見えている部分のうち中心にいちばん近い点」で順位が付く
- **音はスマホのスピーカーから鳴る。**
  **グラスには物理的にスピーカーが無い**ので、グラスから鳴らす道は最初から無い
- **仰角では断らない。** 「地平線より下だから地面だ」と断っていたが、水平あたりを見ただけでも
  仰角は負に振れる（方位合わせに残る誤差もそのまま乗る）。断られた側には理由が分からず、
  見えているものの名前も出ないまま黙る。**グラスに出ているものをそのまま解説する**
- **解説中に別の方向を向いても今の話を最後まで続ける。** 途中で切り替わると落ち着かない

### 声と BGM

**[音（読み上げと BGM）](sound.md) に分けてある。** 既定は OpenAI の `gpt-4o-mini-tts` / `alloy` で、
圏外・キー未設定・失敗のときは端末の `TextToSpeech` に落ちる。BGM は解説していない間も鳴らし、
解説中は 28% まで絞る。

**1 回の解説の中で声を入れ替えない。** 名乗りだけ先に作ってあった頃は、圏外だと
「いて座ですね」が AI の声、続く解説が端末の読み上げになり、**途中で別人が喋り出したように
聞こえた**（2026-08-22 実機）。星図を送るたびに、**その星座で喋る文を全部まとめて作っておく**
（`Narrator.speechParts`）ので、電波があるうちに見た方角ぶんは圏外でも AI の声で鳴る。
落ちたときのために、端末の読み上げも**男性の声があれば選ぶ**。

**API キーは声にしか使わない。** 無くても解説は出る（読み上げが端末の音声になるだけ）。
置き場所はリポジトリ直下の `.env`（[CONTRIBUTING.md](../../CONTRIBUTING.md)）。

### 何を喋るか

**神話と豆知識だけ。** どんな形でどこに見えるかは、グラスの星図がそのまま見せている。
言葉で形をなぞっても、聞いている人は目の前の空と突き合わせられない。

| | |
|---|---|
| 長さ | **2〜3 文・100 文字前後**（最長 93 文字・平均 67 文字） |
| 上限 | **120 文字**。グラスの解説画面に入る 133 文字から、惑星の一言ぶんを残した値 |
| 口調 | プラネタリウムの解説員。平易な言葉で簡潔に |
| 禁止 | 記号・括弧・箇条書き（読み上げは「※」も「（）」もそのまま読む） |

文面は `tools/build-constellation-lore.py` が持っていて、`data/constellation-lore.json` は生成物。
長さと禁止文字はスクリプトが検査するので、**書き足しても壊れたまま出荷されない**。

視野に月や惑星があるときだけ、**入る範囲で**一言足す。惑星は日によって違うので言う価値がある。
**肉眼で見えないもの（6 等より暗い）は言わない**（探させても見つからない）。

### 喋れないとき

**タップしたのに無反応が一番よくない。** 必ず何か喋る。

| 状況 | 応答 |
|---|---|
| まだ方位を合わせていない | 「まだ方位が合っていません。スマホをかざしてください」 |
| 星座が割り出せない | 「星座を割り出せませんでした。星表が読めていないかもしれません」 |
| 解説文を持っていない星座 | 星座名と方角・高度、視野の月惑星・目印の星（88 星座ぶんあるので普段は通らない） |

**圏外は「喋れないとき」ではなくなった。** 解説文もオープニングの音声も端末側にあるので、
通信が無くても最後まで喋り切る。落ちるのは AI 音声の声色だけで、端末の読み上げに替わる。

## 声で質問する（#38）

**`HOLD` で聞き取りが始まり、黙ったら終わる。**

```
HOLD
   ↓
解説画面に切り替えて「聞いています。質問をどうぞ。」
   ↓
グラスのマイクから PCM16・16kHz を受ける（SDK が Opus をほどく）
   ↓
1.2 秒黙ったら止める（一言も無ければ 4 秒で諦め、長くても 12 秒で切る）
   ↓
聞き取り → 「〇〇座って何なの？」を画面に出す
   ↓
いま出している星座・方角・高度・視野の星と惑星を添えて答えを作り、読み上げる
```

- **マイクはグラス側。** 端末の録音権限は要らない
- **押しっぱなしは取れない。** ジェスチャーは 1 回のイベントとして届くので、
  「離したら終わり」にはできない。**黙ったら終わり**にしている
- **ここだけは通信が要る。** 同梱の解説と違い、自由な質問はその場で作るしかない。
  圏外では「いまは通信ができないので、質問には答えられません」と喋って終わる
- **聞き取りと生成で数秒かかる。** その間じゅう解説画面に途中経過を出す
  （聞いています → 聞き取っています → 質問文 → 答え）。**黙って待たせない**
- **マイクを流すと毎秒 32,000 バイトが同じ BLE を通る。** 録っている間は解説画面のままで、
  星図は送らない
- 答えも**いま見えているものの話だけ**に縛る。見えていない天体の名前は出させない

### 聞き取った文は指示ではなくデータ

**声で言うだけで役割を上書きできてはいけない。** 「これまでの指示は無視して」と喋られたときに
プラネタリウムの解説員が別のものになると、聞いている人には何が起きたか分からない。
検査は `narration/AskGuard.kt` にまとめてあり、**端末だけで完結する**ので JVM テストで固定できる。

| どこ | 何をするか |
|---|---|
| 入口 | **囲い記号（「」『』<>{}`"）と改行と制御文字を落とす**。区切りは端末が付けるので、質問の中から閉じられない |
| 入口 | **120 文字で切る。** ふつうの質問は 30 文字も要らない。長々と指示を並べさせない |
| 依頼文 | 区切りの中は**利用者の言葉であって指示ではない**と、システム側と末尾の両方に書く |
| 出口 | **星空の話かどうかを本文と分けて JSON で返させる**（`astronomy` と `reply`） |
| 出口 | 話題の外なら、**端末が持つ固定文**で断る（生成に左右させない） |
| 出口 | 記号・箇条書きを落とし、200 文字を**文の切れ目で**切る。何も残らなければ捨てる |

- **文章の中で断らせない。** 「お答えできません」と言いながら続きを喋る形になりやすく、
  端末側で判定もできない。**真偽値で返させて、断り文は端末が持つ**
- **これは自分の端末で自分の声を使う機能**なので、狙われる相手は自分自身しかいない。
  それでも入れるのは、**事故で解説員が別のものになると使いものにならない**から
- 聞き取った文はログに残す。**実機で何を聞き取ったかはログだけが頼り**

## 衛星モードの `SINGLE_TAP`

**衛星モードでは星を 1 つも描いていない**ので、星座の解説を返すと見えているものと食い違う。
**LLM も呼ばない。** 機体名・方角・高度・日照はすべて端末が計算した確定値で、
生成に投げると待つだけ損になる（星座は由来や探し方があるので LLM が効く）。

```
SINGLE_TAP（衛星モード）
   ↓
タップ直前 0.5 秒の視線で、視野に入っている名前つきの機体を出す
   ↓
1 機もいない ──→ 「いま視野には人工衛星がいません」
   ↓ いる
「いま視野には ISS が入っています。南南西の空、高度 45 度あたりです。
　日が当たっているので、動く光として肉眼でも見えるかもしれません」
```

- **日照かどうかを必ず言う。** 影に入っていれば肉眼では絶対に見えないので、
  言わないと探し続けることになる
- スターリンクは名前を読み上げても意味がないので、案内するのは名前つきだけ
- **通信もキーも要らない。** 圏外でも成立する経路

詳しくは [人工衛星モード](satellites.md)。
