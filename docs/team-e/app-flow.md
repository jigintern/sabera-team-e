# 画面遷移とジェスチャー

何を触ると何が起きるか、そのときグラスとスマホに何が出ているか。
出力の制約は [グラス出力の制約](glass-output.md)、座標変換は [座標変換パイプライン](coordinate-system.md)。

## 役割分担

**操作系はグラスで完結させる。スマホは見なくても使える。**

| | 役割 |
|---|---|
| **グラス** | 星図と星座名を出す。ジェスチャーで操作を受ける |
| **スマホ** | 計算する。音声を鳴らす。**同伴者に見せる**。詰まったときの整備画面 |

- グラスをかけている人は空を見ていて**スマホは見ない**
- 星を見に行くのは複数人のことが多く、**グラスは 1 人しかかけられない**ので、
  スマホ画面は同伴者のためにある
- **例外は初回の接続だけ。** `showAutomaticSelectionDialog(activity)` が Activity を要求するが、
  `connectToLastDevice()` を呼んでおけば 2 回目以降は自動接続になる
  （初回かどうかは `hasLastConnectedDevice` で分岐できる）

## ジェスチャー

使えるのは 3 つだけ。**3 枠はすべて埋まっている。**

| ジェスチャー | 割り当て | 挙動 |
|---|---|---|
| `SINGLE_TAP` | **解説の開始／停止** | トグル。**誤タップ対策**（ツルは触れやすく、かけ直しただけで発火する） |
| `DOUBLE_TAP` | **星座 ⇄ 人工衛星の切り替え** | いつでも有効 |
| `HOLD` | **方位を合わせる** | いつでも有効（スマホのボタンも残す） |

- **「あれは何？」は視線の向きで完全に決まる**ので、**タップそのものが質問になっている**。
  最初の一言に音声入力は要らない
- **`HOLD` を方位合わせにしたのは、いつでも呼べる必要があるから**
- もともと `DOUBLE_TAP` に当てていた「もっと詳しく」は**行き先を失った**。
  どちらかをスマホ側のボタンに追い出すことになる
- `gestureEvents` は `SharedFlow` なので、**購読前のジェスチャーは受け取れない**。
  接続完了 → 購読開始 → 「準備できました」の順を守る
- **リモコンのイベントは 0.5.0 で撤去された**ので拾えない

## グラスに何を出すか

**キャンバス（576×360）に星図画像を置き、その手前に星座名を重ねる。**

```
┌─────────────────────────── 576 ───────────────────────────┐
│   おとめ座                        しし座                    │  ← テキスト（8 要素・190B）
│         ·      ·                                           │
│      ·      ·        ·                                  360│
│         ·         ·                                        │  ← 画像（528×330 まで）
│              ·                                             │
└────────────────────────────────────────────────────────────┘
```

| 出すもの | API | 更新 |
|---|---|---|
| 星図 | `sendCanvasImage`（id 固定の 1 枚） | 首が止まってから。1 枚 1 秒近く |
| 星座名 | `sendCanvasElements`（差分更新） | 毎フレーム。数十 ms |

**解説文はグラスに出さない。** 190 バイトでは入らないし、星図の上に長文を重ねると星が読めない。
**グラスは星図と星座名まで**にして、解説はスマホと音声に逃がす。

## 画面遷移

![画面遷移](diagrams/screen-flow.drawio.svg)

- **キャンバス 1 枚で回る。** ページ遷移が要らないので、状態はほぼ「観測中かどうか」だけ
- **方位合わせ中は星図を消して十字だけを出す**（バッファに同時に入らない）
- **解説中もグラスの画面は変わらない。** 音声はスマホから鳴る

## スマホの画面

**ホーム → 接続 → 方位合わせ → 星図**の 4 画面。星図の画面が本体で、
**上部バーの「衛星モード」で星座 ⇄ 人工衛星を切り替え、「設定」で調整と記録を別ページに畳む**。

```
┌─────────────────────────────┐
│ 現在の星空   [衛星モード][設定]│  ← 衛星モード中はボタンが点く
├─────────────────────────────┤
│  グラスに表示している星空      │
│  ┌───────────────────────┐  │  ← 送った画像そのもの（緑 8 階調に寄せた色）
│  │        · ·  ·         │  │     名前はグラス側が描くのでここには出ない
│  └───────────────────────┘  │     出す前は「何を待っているか」を回して出す
│  グラスの向きを止めると更新    │
├─────────────────────────────┤
│ AI 星座解説                  │
│ 解説を読み上げています        │
│ さそり座                     │
│ さそり座は南の低い空に…       │
├─────────────────────────────┤
│  [ この星空を解説する ]       │
│  [ 方位を合わせ直す ]         │
└─────────────────────────────┘
```

| 要素 | 中身 |
|---|---|
| プレビュー | グラスに送った画像そのもの。**同伴者に見せる用途にもなる** |
| 待ちの表示 | 星表・TLE・測位・転送。**何を待っているかを書く** |
| 解説／案内 | 進み具合と本文。**タップはグラス側なので出力専用** |
| いま空に出ている | 衛星モードだけ。`●` は日照、`○` は地球の影。上昇中か・最接近まで何分か |
| 設定ページ | 6DoF・方位合わせ・いま送る／消す・ログ・観測地 |

- **解説のカードはボタンの上**（音声が使えない環境ではテキストが主役になる）
- **位置と時刻を出すのは、間違っていても星図が「それらしく」出てしまうから。**
  タイムゾーンの取り違えは 135°、時計の 1 時間ずれは 15°。
  どちらもユーザーには気づけず、「AI が間違っている」と誤解される
- **衛星モードは星座モードと同じ並び**（プレビュー → 一言 → 案内のカード → ボタン 2 つ）。
  増やすのは中身だけで、要素は足さない

### 待ち時間の見せ方

**このアプリは黙る場面が多い。** 画面が切り替わったのに何も出ないと壊れたと思われる（`ui/Loading.kt`）。

| 待つもの | かかる時間 | 出す場所 |
|---|---|---|
| 人工衛星の TLE（10,748 機） | 1〜2 秒 | 画面の先頭 |
| **1 枚目の転送** | **約 1 秒** | **プレビューの枠の中** |
| 転送中（2 枚目以降） | 1 枚 1 秒 | プレビューに札を重ねる |

**転送中はグラスから絵が消える。** スマホのプレビューは前の絵のままなので、
食い違いを札で明示する（`送信中（グラスは一時的に消える）`）。

## AI 解説（星座モード）

**`SINGLE_TAP` そのものが「あれは何？」という質問。**

```
SINGLE_TAP
   ↓
タップ直前 0.5 秒の視線から星座を決める
   ↓
喋れない理由がある ──→ 案内を喋って終了
   ↓ 決まった
「おとめ座ですね」を即座に喋る       ← 端末が知っている事実。LLM を待たない
   ↓（並行して）
OpenAI に投げる ── 星図画像 ＋ 星座名 ＋ 位置 ＋ 方位・仰角 ＋ 日時
   ↓
返ってきた解説を続けて読み上げ、同時にスマホへテキストを出す
```

- **LLM の生成は 1〜3 秒空く。** 星座名は端末が既に知っているので最初の一言は即座に出せる
- **音はスマホのスピーカーから鳴る。**
  **グラスには物理的にスピーカーが無い**ので、グラスから鳴らす道は最初から無い
- **解説中に別の方向を向いても今の話を最後まで続ける。** 途中で切り替わると落ち着かない
- **解説の本文は一括で受け取る。** ストリーミングは、最初の一言で待ち時間が埋まるので後回しにした

### 声（読み上げ）

**目指しているのはミニプラネタリウム。** 端末の `TextToSpeech` は棒読みで、
内容が合っていても雰囲気が壊れる。**普段は OpenAI の音声で喋る。**

| | 使うもの | 話し方 |
|---|---|---|
| **既定** | **`gpt-4o-mini-tts`** | `instructions` で「落ち着いたプラネタリウムの解説員」を注文する |
| 退路 | Android の `TextToSpeech` | 棒読み。**圏外・キー未設定・API 失敗のとき自動で落ちる** |

- **話し方を文章で注文できることが `gpt-4o-mini-tts` を選んだ理由。**
  `tts-1` / `tts-1-hd` は `instructions` を解さないので、指定すると棒読みに戻る
- **形式は生の PCM**（24kHz / 16bit / モノラル）。**届いたぶんから鳴らす**ので、
  全部できるまで待たない。mp3 や Opus のほうが軽いが、途中から鳴らすにはデコーダが要る
- **48KB/秒 は夜の屋外では細い。** 先頭 0.6 秒を溜めてから鳴らし始め、
  それでも駄目なら端末の読み上げに落とす。**黙るのは声の質より悪い**
- **「〇〇座ですね」はタップより先に作っておく。** 星図を送った時点で視野の星座は分かっているので、
  その一言だけ先に合成してキャッシュに置く。**短い定型文なので 2 回目からは通信も要らない**
- 声（`sage` など 11 種）は `.env` の `OPENAI_TTS_VOICE` で差し替える。
  **どれが解説員らしいかは実機で聴かないと決まらない**
- 設定パネルの「声」で AI 音声と端末の読み上げを切り替えられる（聴き比べ用）
- **キャッシュは `cacheDir`。** PCM は 1 秒 48KB あるので、**短い定型文だけ**残して 16MB で打ち切る
- `gpt-4o-audio-preview` に文章と音声を同時に作らせる案は採らなかった。
  **最初の一言を先に喋れなくなる**うえ、話し方の注文が効かない

**注文を盛るとかえって芝居になる。** 「暗い場内で静かに語りかけるように」まで書いた版は
聴き比べで落ちた。**望みは演技ではなく素の落ち着き**なので、演じないことだけ頼む。

### 何を喋るか（ロマンは中身で出す）

**わざとらしさは言い方から出て、ロマンは中身から出る。** 飾った言い回しはどの声で読んでも
芝居に聞こえるので禁じ、代わりに**事実で宇宙の大きさを出させる**。

| 入れるもの | 例 |
|---|---|
| **探し方** | 目印になる明るい星や並びを 1 つ |
| **スケールの数字** | 「アルタイルは 17 光年。いま見えている光は 17 年前に出たもの」 |
| **雑学** | 「自転が速くて、10 時間で 1 回転する。そのせいで楕円に潰れている」 |
| 神話・由来 | 一言まで |

- **箇条書きを増やすほど 1 つずつは薄まる。** 実測で 11 個並べた版は末尾 2 つが無視された。
  **守らせたい注意は依頼文の末尾に置く**（星座名を言い直させない、呼びかけで締めさせない）
- **250 文字で読み上げは 45 秒前後。** その間は次のタップを受けないので、これ以上は伸ばさない

### BGM

**解説していない間も鳴らす。** プラネタリウムの雰囲気は無音では出ない。

| 空の状態 | 曲 |
|---|---|
| 昼・薄明（太陽高度 −6° より上） | **Silver Blue Light**（明るさが移り変わる時間に合う） |
| 夜（−6° より下） | **Fluidscape**（広くて何も無い感じ） |

- **時計で切り替えない。** 同じ 19 時が夏は明るく冬は暗い。
  **太陽高度（`SkyDarkness`）なら季節と緯度を勝手に吸収する**
- **曲は 120 秒。末尾を先頭にクロスフェードして焼いてある**ので繰り返しても継ぎ目が出ない
- **解説が始まったら 0.4 秒で 28% まで絞る。** 同じ音量だと言葉が埋もれる。
  ただし 0 にはしない（曲が消えると解説だけ浮く）
- **曲の入れ替えは 3 秒かけて。** 太陽が沈むたびに切り替わるので気づかれないほうがよい
- **読み上げと BGM の音量は設定パネルのつまみ**で、値は端末に覚えさせる。
  **適正値は場所（屋外の暗騒音）と機種で変わる**うえ、合わせ直すのは夜の屋外になる
- 出処は incompetech.com（Kevin MacLeod）の **CC BY 4.0**。
  帰属は `NOTICE` と**設定パネルの両方**に出す（`NOTICE` はアプリの利用者には見えない）

### OpenAI に何を送るか

| 送るもの | 出処 |
|---|---|
| 星図の PNG | **グラスに出しているのと同じ絵** |
| 星座名 | 端末が計算した確定値。視野に近い順に最大 4 個 |
| 緯度経度・方位・仰角・日時 | 観測条件 |

- **画像だけにしない。** 緑 8 階調の点描を視覚モデルが読み違えても検知できないが、
  星座名は確定値なので併せて渡せば同定を間違えようがない。
  絵は「その星座がいまどう見えているか」を伝える役に徹させる
- **画像は 3bit に落としてから送る。** 8bit のままだと実機では見えない淡い星まで写り、
  **見えていないものの解説**が返る
- プロンプトで**記号・箇条書き・括弧を禁じている**（読み上げは「※」も「1.」もそのまま読む）

### 喋れないとき

**タップしたのに無反応が一番よくない。** 必ず何か喋る。
IAU 境界は天球を隙間なく分割しているので**「星座が無い」方向は存在しない**。
決まらないのは、そもそも空を見ていないときだけ。

| 状況 | 応答 |
|---|---|
| まだ方位を合わせていない | 「まだ方位が合っていません。スマホをかざしてください」 |
| 地平線より下を向いている | 「いまは地面を向いています。空を見上げてください」 |
| その方向に明るい星が無い | 「うみへび座のあたりですが、この方向に明るい星はありません」 |
| 圏外で AI を呼べない | 「通信ができないので詳しい解説はお預けです」＋ 星座名と方角・高度 |
| API キーが未設定 | 「AI の設定がないので解説はできません」＋ 星座名 |

### API キーの置き場所

リポジトリ直下の **`.env`**（`.gitignore` 済み）。テンプレートは `.env.example`。

```sh
cp .env.example .env   # OPENAI_API_KEY= に書き込む
```

- 探す順は **`.env` → `local.properties` → `~/.gradle/gradle.properties` → 環境変数**
- 声を変えるなら同じ `.env` の `OPENAI_TTS_MODEL` / `OPENAI_TTS_VOICE`
- **どれも無くてもビルドは通る。** 画面に「キー未設定」と出るだけ
- **どの方式でも APK にキーは埋まる。** 配布せず手元の実機で動かす前提

## 衛星モードの `SINGLE_TAP`

**衛星モードでは星を 1 つも描いていない**ので、星座の解説を返すと見えているものと食い違う。
**LLM も呼ばない。** 機体名・方角・高度・日照はすべて端末が計算した確定値で、
生成に投げると待つだけ損になる（星座は由来や探し方があるので LLM が効く）。

```
SINGLE_TAP（衛星モード）
   ↓
タップ直前 0.5 秒の視線で、視野に入っている名前つきの機体を出す
   ↓
1 機もいない ──→ 「いま視野には人工衛星がいません」
   ↓ いる
「いま視野には ISS が入っています。南南西の空、高度 45 度あたりです。
　日が当たっているので、動く光として肉眼でも見えるかもしれません」
```

- **日照かどうかを必ず言う。** 影に入っていれば肉眼では絶対に見えないので、
  言わないと探し続けることになる
- スターリンクは名前を読み上げても意味がないので、案内するのは名前つきだけ
- **通信もキーも要らない。** 圏外でも成立する経路

詳しくは [人工衛星モード](satellites.md)。

## まだ決めていないこと

- **音声質問の入り口。** `micAudio` で PCM16 / 16kHz が取れるが、
  **3 つのジェスチャー枠は埋まっている**。騒音・圏外・発話の区切りという失敗経路も増える
- 待機中の `DOUBLE_TAP` に何を割り当てるか（割り当てないのも選択肢）
- **解説をストリーミングに変えるか**（いまは一括で、待ちは「〇〇座ですね」で埋めている）
- **星座の判定を IAU 境界に差し替える**（いまは星座線までの角距離が最小の星座）
- 観測中に明るさを下げるか、通知を抑止するか
- 位置と時刻を常時出すか、異常時だけにするか
- ヒステリシスの内側マージンと保持時間
- 観測地の測位を続けるか（いまは画面に入ったとき 1 回だけ）
