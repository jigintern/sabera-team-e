# 画面遷移とジェスチャー

- ユーザーが何を触ると何が起きるか、そのときグラスとスマホに何が出ているかの仕様
- 座標変換の中身は [座標変換パイプライン](coordinate-system.md)
- **`要決定` `要確認` の付いた項目はまだ決まっていない**

## 基本方針

**操作系はグラスで完結させる。** スマホは見なくても使える。

| | 役割 |
|---|---|
| **グラス** | 星図を出す。ジェスチャーで操作を受ける |
| **スマホ** | 計算する。音声を鳴らす。**同伴者に見せる**。詰まったときの整備画面 |

- グラスをかけている人は空を見ている。**スマホは見ない**
- スマホ画面は「同伴者が同じものを見るため」と「うまくいかないときに開くため」にある
- 星を見に行くのは複数人のことが多く、**グラスは 1 人しかかけられない**

### 唯一の例外：初回の接続

- `showAutomaticSelectionDialog(activity)` は **Activity を要求する**ので、初回はスマホ操作が避けられない（SDK の制約）
- ただし `BleCompanionDeviceService.connectToLastDevice()` を呼んでおけば**2 回目以降は自動接続でダイアログが出ない**
- **`GlassManager.hasLastConnectedDevice` で「初回かどうか」を分岐できる**ので、
  ダイアログを出すかどうかをこちらで決められる（`要確認` 上流の本文は未執筆）
- `setDevicePersistence` を入れておかないと**プロセスをまたぐと忘れる**ので、ここが前提
- → **初回だけスマホ、以後は完結**

## ジェスチャー割り当て

使えるのは `SINGLE_TAP` / `DOUBLE_TAP` / `HOLD` の **3 つだけ**（`commandManager.gestureEvents`）。

| ジェスチャー | 割り当て | 状態による違い |
|---|---|---|
| `SINGLE_TAP` | **解説の開始／停止** | 待機中は開始、解説中は停止（トグル） |
| `DOUBLE_TAP` | **もっと詳しく** | 解説中・直後のみ有効 |
| `HOLD` | **方位を合わせる** | いつでも有効 |

### なぜこの割り当てか

- **`SINGLE_TAP` をトグルにしたのは誤タップ対策。** ツルは触れやすく、かけ直しただけで発火する。トグルなら**もう一度タップすれば止まる**
- **音声入力を捨てたので `HOLD` が空いた。** 「あれは何？」は視線の向きで完全に決まるため、**タップそのものが質問になっている**。マイクは使わない
- **`HOLD` を方位合わせにしたのは、いつでも呼べる必要があるから。** ジャイロはドリフトするので、状態によらず同じ意味にする

### リモコンでも 3 つ取れる

`addRemoteControllerEventListener` の `RemoteControlListener` は **`onPrev` / `onNext` / `onEsc`** の 3 つ。
上流の本文は未執筆だが、**コード例にインターフェースが出ている**ので取れるものは確定している。

- **使わない。** リモコンは別の物体なので、「操作系はグラスで完結」の方針から外れる
- ただし**無視はできない**。**戻る操作でキャンバスと分割レイアウトは閉じる**
  （`closeCanvas` / `closeLayout` の説明）。**出しっぱなしにする画面は勝手に閉じられる前提で組む**
- `要決定` 同伴者に操作させる用途で使うか

### 注意

- `gestureEvents` は `SharedFlow`。**購読を始める前のジェスチャーは受け取れない**
- 接続完了 → 購読開始 → グラスに「準備できました」を出す、の順を守る。順序を誤ると最初のタップが無反応になる

## グラスに何を出すか

**表示パネルは 576×360。** 0.2.0 のキャンバスがこの座標で要素を置くので判明した。
**画像表示ページの 196x196 はパネルの一部でしかない**（等倍なら幅の 34%）。

出せるものは 3 通りあり、**どれか 1 つしか出せない**（画面ごと切り替わる）。

| 出し方 | 中身 | 大きさ |
|---|---|---|
| **星図** | `enterImageDisplayPage` ＋ `sendImage` | 196x196・緑 8 階調 |
| **ラベル** | `sendCanvas`（0.2.0） | 576×360 の任意座標にテキスト。8 要素・190 バイトまで |
| **文章** | `sendLayout`（0.1.1）/ `sendEmptyScreenContent` | 分割 or 全画面のテキスト |

- **`sendCanvas` と `sendLayout` は送るだけで画面が切り替わる。** 先にページを開かなくてよい
- `sendCanvas` は `FEATURE_VERSION 2.1.0` 以上。**6DoF（2.0.0）が動いても動かないことがある**

### `要決定` 星図とラベルのどちらを主にするか

**新しい選択肢。** キャンバスは 576×360 の任意座標にテキストを置けるので、
**「その方向に星座名が浮かぶ」だけの表示**が作れる。

| | 星図（画像） | ラベル（キャンバス） |
|---|---|---|
| 見えるもの | 星と星座線 | 星座名だけ |
| 面積 | パネルの一部（196x196） | **パネル全体（576×360）** |
| 方位が数°ずれたら | **線が明らかに合わない** | **破綻しない**。名前が少し動くだけ |
| 実機で動くか | 0.0.11 から | **`FEATURE_VERSION 2.1.0` 以上が要る** |

- **ラベル方式はキャリブレーションの精度要求が低い。** 段階 1（スマホ同期）だけで成立する見込みが高い
- 星図は「星座の形を見せて同定させる」という当初の狙いに沿うが、精度が要る
- → **両方作れるようにして、実機で見比べて決める。** ④ までの計算は共通で、出口が違うだけ

## グラスの画面遷移

**同時には出せない**ので、**観測中は星図（またはラベル）を出しっぱなしにし、
解説はスマホと音声に逃がす**。

```
                    ┌──────────────┐
   接続             │   未接続      │  グラス標準のホーム
   ─────────────→   └──────┬───────┘
                           │ 接続完了・購読開始
                           ↓
                    ┌──────────────┐
                    │   準備中      │  enterEmptyScreenPage
                    │              │  「スマホを顔の前にかざしてください」
                    └──────┬───────┘
                           │ 方位が決まった
                           ↓
   HOLD             ┌──────────────┐
   ┌───────────────→│   観測中      │  enterImageDisplayPage
   │                │              │  星図を出しっぱなし
   │                └──────┬───────┘
   │                       │ HOLD
   │                       ↓
   │                ┌──────────────┐
   └────────────────┤ 方位合わせ中  │  enterEmptyScreenPage
                    │              │  「スマホを顔の前にかざしてください」
                    └──────────────┘
```

- **解説中もグラスの画面は変わらない。** 星図のまま。音声はスマホから鳴る
- 切断されたら未接続へ戻る
- **終わるときはグラスを元に戻す。** アプリを閉じる・バックグラウンドに回る・切断するときは
  `closeCanvas()` / `closeLayout()` か `enterHomePage()` を送る。
  **送らないと、アプリが居ないのに星図が出たまま**になる
- `enterEmptyScreenPage` を使った場合は `sendEmptyScreenStatus(READY)` で空に戻せる
- 「準備中」「方位合わせ中」のテキストは **`sendLayout(FULL, ...)` のほうが素直**。
  `enterEmptyScreenPage` と違い**ページを開く手順が要らない**（送るだけで切り替わる）
- **リモコンの戻る操作で閉じられることがある。** 閉じられた前提で送り直せるようにしておく

### 星図の更新

- 姿勢（`imuData` の `yawDegrees` / `pitchDegrees`）が変わったら描き直して送る
- **姿勢が動かなくても更新は要る。** 星は日周運動で **15″/秒**（1 分で 0.25°、4 分で 1°）動く
- `要確認` **1 枚の転送にどれだけかかるかが未実測**。ここが更新レートの上限を決める。サンプルの `ImageScreen` で今すぐ測れる
- **ラベル方式なら転送量が桁違いに軽い**（テキスト数十バイト対 196x196 の画像）。
  `sendCanvasElements` で**動いた要素だけ差分更新**もできる

## 夜空で使うためのグラス設定

**`sendSetting(name, value)` でグラス本体の設定を書き換えられる。**
上流ドキュメントにキー一覧が無いので、`sabera-app-core:0.2.1` の AAR から読み取った
（`CommandManager.SettingKey`、17 個）。**値の範囲と意味は未確認**。

このアプリの体験に直接効くものが 4 つある。

### 1. 明るさ — `BRIGHTNESS_LEVEL` / `BRIGHTNESS_AUTO`

**いちばん効く。** 星を見る目は暗順応していて、明るい緑が視界にあると**肉眼の空が見えなくなる**。

- 波導は黒が透明なので、**光っている画素だけが邪魔をする**
- 星図は線と点なので画素数は少ないが、明るいと瞳孔が閉じる
- **屋内で調整した明るさは、屋外の暗闇では確実に明るすぎる**
- `要決定` アプリが自動で下げるか、ユーザーに任せるか
- `要確認` `BRIGHTNESS_AUTO` が入っていると、暗所で勝手に上がる／下がる可能性がある

### 2. 消灯 — `SCREEN_OFF_TIME`

**このアプリは「見上げたまま何分も止まっている」使い方をする。**

- 操作しない時間が続くので、**標準の消灯時間だと途中で消える**
- 星図は送り続けているが、それが消灯を止めるかどうかは分からない
- `要確認` 送信が消灯タイマーをリセットするか。しないなら **`SCREEN_OFF_TIME` を延ばす必要がある**

### 3. 見上げでのウェイクアップ — `sendWakeupTiltThreshold(degrees)`

**ヘッドアップでグラスが起きる傾きのしきい値。** 星を見る姿勢と正面衝突する。

- **ずっと見上げている**ので、しきい値の設計次第で起きっぱなしにも、暴れ方にもなる
- 逆に噛み合わせれば、**空を見上げた瞬間に星図が出る**という自然な入り口になる
- `enterGlassAngleAdjustmentPage()` で調整ページが開く
- `要確認` 見上げっぱなしのときの実際の挙動

### 4. 通知の割り込み — `MESSAGE_DISPLAY_MODE` / `MESSAGE_DISPLAY_TIME` / `NOTIF_CONTENT_MASK`

- **観測中にスマホの通知がグラスに出ると、星図が消える**（同時には出せないので）
- 夜空の下で LINE が飛んでくるたびに星図が飛ぶのは体験として成立しない
- `要決定` 観測中だけ通知を抑止するか

### 装着状態とバッテリー — `requestSystemStatus()`

- **バッテリー残量・装着状態・充電状態**を要求できる
- **装着状態が取れると、外している間の送信を止められる**。冬の屋外で電池を残すのに効く
- ただし応答は `parseResponse(ByteArray)` 経由で、**上流の本文が未執筆**。
  パースした値がどこに出るのか公開 API から辿れない
- `要確認` 読み出しの経路。**設定値も同じ問題を抱えている**

## ファームのバージョンで出し方を変える

**`SettingKey.FEATURE_VERSION` を読めば、実行時に機能を出し分けられる。**

| 機能 | 必要バージョン |
|---|---|
| 星図（`sendImage`） | 制限なし（0.0.11 の API） |
| 分割レイアウト（`sendLayout`） | `2.0.0` |
| 6DoF（`startImuData`） | `2.0.0` |
| **ラベル（`sendCanvas`）** | **`2.1.0`** |

- **ラベル経路がいちばん新しいファームを要求する。** 6DoF が動いても使えないことがある
- → **起動時に `FEATURE_VERSION` を読み、足りなければ星図に落とす**のが素直
- **2.0.0 未満なら 6DoF も動かない**ので、そもそもこのアプリが成立しない。
  そのときは「対応していないファームです」と正直に出す
- `要確認` 上記のとおり読み出し経路が不明。**読めないなら「送ってみて反応が無ければ諦める」しかない**

## 星図を送りすぎない

- `GlassClient.cancelPendingPackets()` で**送信待ちのパケットを捨てられる**（上流の本文は未執筆）
- 首を振ると姿勢が速く変わるので、**古いフレームが順番待ちで積み上がる**
- 積んだまま送ると、**手を止めた後に過去のフレームが順に出てくる**
- → **新しいフレームを送る前に捨てる**のが素直。`要確認` 実際の挙動
- **ラベル方式ならそもそも軽い**（8 個で約 118 バイト。星図は量子化前で 38,416 バイト）

## スマホの画面

**1 枚で足りる。**

```
┌─────────────────────────────┐
│ SABERA          ● 接続済み   │
├─────────────────────────────┤
│                             │
│        （星図）              │
│                             │
│         おとめ座             │
├─────────────────────────────┤
│ AI 解説                      │
│ ───────────────────────     │
│ ───────────────────────     │
│ ───────────────────────     │
├─────────────────────────────┤
│  [ 方位を合わせる（3分前）]   │
└─────────────────────────────┘
```

| 要素 | 中身 |
|---|---|
| ヘッダー | 接続状態、デバイス名。未接続なら接続ボタン |
| 星図 | グラスと同じ図。**同伴者が見るのが主用途** |
| 星座名 | いま解説の対象になっている星座 |
| AI 解説 | 音声と同じ内容のテキスト。**音声が使えない環境ではここが主役** |
| 方位を合わせる | ボタン。**最終同期からの経過時間**をラベルに含める |

### エラー領域は異常時だけ出す

平常時は何も出さない。**次のときだけ**ヘッダー下に出す。

- 未接続・接続が切れた
- 位置が取れていない — 「前回の場所で計算しています」
- 端末時刻がずれている疑い
- 圏外で AI を呼べない

**位置と時刻をここに含めるのは、間違っていても星図が「それらしく」出てしまうから。**

- タイムゾーンの取り違え（UTC とローカルの混同）は **9 時間ずれ ＝ 135°**
- 端末時計が 1 時間ずれると **15°**
- どちらもユーザーには気づけず、「AI が間違っている」と誤解される

`要決定` 常時小さく出すか、異常時のみにするか

## AI 解説のフロー

**`SINGLE_TAP` そのものが「あれは何？」という質問。** 音声入力は使わない。

```
SINGLE_TAP
   ↓
視線方向から星座を決める
   ↓
決まらない ──→ 案内を喋って終了（後述）
   ↓ 決まった
「おとめ座ですね」を即座に喋る       ← 端末が知っている事実。LLM を待たない
   ↓（並行して）
LLM を呼ぶ
   ↓
文が完成するたび読み上げる          ← ストリーミング
   ↓
同時にスマホへテキストを出す
   ↓
待機へ戻る
```

### 喋り出しを待たせない

- LLM の生成を待つと **1〜3 秒**空く
- **星座名は端末が既に知っている**ので、最初の一言は即座に出せる
- その裏で LLM を呼び、文単位で読み上げに流す
- → 体感の待ち時間がほぼ消える

### 音声はスマホから鳴らす

- **SDK に音を鳴らす API は無い**（`openGlassMic` / `micChannel` は入力のみ）
- Android の `TextToSpeech` でスマホから鳴らす。オフラインでも動く
- イヤホンでもスピーカーでもよい。**夜の屋外でスピーカーなら同伴者にも聞こえる**
- → グラスの音声出力を待つ必要が無くなった

### 停止と深掘り

| 操作 | 挙動 |
|---|---|
| 解説中に `SINGLE_TAP` | 読み上げを止め、生成も打ち切る |
| 解説中・直後に `DOUBLE_TAP` | 続きを生成して読み上げる（もっと詳しく） |

- 追加質問ができない不足は、`DOUBLE_TAP` の深掘りで段階的に埋める
- `要決定` 待機中の `DOUBLE_TAP` に何を割り当てるか。**割り当てない**（誤操作が減る）のも選択肢

### 解説中に別の方向を向いたら

- **今の話を最後まで続ける。** 途中で切り替わると落ち着かない
- スマホに「いまおとめ座の話をしています」と出ているので混乱しない
- 話し終えてから、次のタップで新しい星座になる

## 星座が決まらないとき

**タップしたのに無反応が一番よくない。** 必ず何か喋る。

**IAU 境界は天球を隙間なく 88 分割しているので、「星座が無い」方向は存在しない。**
決まらないのは、次のように**そもそも空を見ていない**ときだけ。

| 状況 | 応答 |
|---|---|
| まだ方位を合わせていない | 「まだ方位が合っていません。スマホをかざしてください」 |
| 地平線より下を向いている | 「いまは地面を向いています。空を見上げてください」 |
| 星座は決まったが、その方向に明るい星が無い | 「うみへび座のあたりですが、この方向に明るい星はありません」 |
| 圏外で AI を呼べない | 同梱の解説文を読み上げる（[AI 解説の仕様] で詰める） |

## いま見ている星座をどう決めるか

**`決定` 視野中心が属する星座を、IAU の星座境界で判定する。**

- 「近さ」で選ぶと壊れる — **うみへび座は 95° に広がる**ので、重心が誰も見ていない空白にある
- 「視野内」も選択ルールにならない — **FOV 40° では平均 5.2 個入り、1 個だけの視野は空のどこにも無い**
- 「視野内で最大」は**エリダヌス座・おおぐま座・うみへび座**が常に勝つ
- **IAU 境界は天球を隙間なく 88 分割している**ので、1 点が属する星座は一意。
  距離もしきい値も要らず、引き分けも起きない

根拠の数字と実装の選択肢は [座標変換パイプライン ⑦](coordinate-system.md#-いま見ている星座を決める)。

### タップの反動を吸収する

- **ツルをタップすると頭が動く。** タップ時点の姿勢を使うと、押した反動でずれた方向を判定してしまう
- → 判定は **タップ直前 0.5 秒ほどのラッチ値**から取る
- 併せて、**境界から一定角内側に入り、かつ一定時間維持されたときだけ切り替える**（ヒステリシス）
- `要決定` 内側マージンと保持時間の具体値。実機で決める

### 中心に何も無いとき

- 街中で見える 3 等星までだと、**空の 20% は「中心の周り 12° に何も無い」**
- 境界判定は正解を返すが、ユーザーには何も見えていない
- → **正直に言う。**「うみへび座のあたりですが、この方向に明るい星はありません」
