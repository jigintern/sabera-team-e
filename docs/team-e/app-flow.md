# 画面遷移とジェスチャー

何を触ると何が起きるか、そのときグラスとスマホに何が出ているか。
出力の制約は [グラス出力の制約](glass-output.md)、座標変換は [座標変換パイプライン](coordinate-system.md)。

## 役割分担

**操作系はグラスで完結させる。スマホは見なくても使える。**

| | 役割 |
|---|---|
| **グラス** | 星図と星座名を出す。ジェスチャーで操作を受ける |
| **スマホ** | 計算する。音声を鳴らす。**同伴者に見せる**。詰まったときの整備画面 |

- グラスをかけている人は空を見ていて**スマホは見ない**
- 星を見に行くのは複数人のことが多く、**グラスは 1 人しかかけられない**ので、
  スマホ画面は同伴者のためにある
- **例外は初回の接続だけ。** `showAutomaticSelectionDialog(activity)` が Activity を要求するが、
  `connectToLastDevice()` を呼んでおけば 2 回目以降は自動接続になる
  （初回かどうかは `hasLastConnectedDevice` で分岐できる）

## ジェスチャー

使えるのは 3 つだけ。**3 枠はすべて埋まっている。**

| ジェスチャー | 割り当て | 挙動 |
|---|---|---|
| `SINGLE_TAP` | **解説の開始／停止** | トグル。**誤タップ対策**（ツルは触れやすく、かけ直しただけで発火する） |
| `DOUBLE_TAP` | **人工衛星を重ねる／隠す** | いつでも有効。**モードの切り替えではない**（#36） |
| `HOLD` | **方位を合わせる** | いつでも有効（スマホのボタンも残す） |

- **「あれは何？」は視線の向きで完全に決まる**ので、**タップそのものが質問になっている**。
  最初の一言に音声入力は要らない
- **`HOLD` を方位合わせにしたのは、いつでも呼べる必要があるから**
- もともと `DOUBLE_TAP` に当てていた「もっと詳しく」は**行き先を失った**。
  どちらかをスマホ側のボタンに追い出すことになる
- `gestureEvents` は `SharedFlow` なので、**購読前のジェスチャーは受け取れない**。
  接続完了 → 購読開始 → 「準備できました」の順を守る
- **リモコンのイベントは 0.5.0 で撤去された**ので拾えない

## グラスに何を出すか

**キャンバス（576×360）に星図画像を置き、その手前に星座名を重ねる。**

```
┌─────────────────────────── 576 ───────────────────────────┐
│   おとめ座                        しし座                    │  ← テキスト（8 要素・190B）
│         ·      ·                                           │
│      ·      ·        ·                                  360│
│         ·         ·                                        │  ← 画像（528×330 まで）
│              ·                                             │
└────────────────────────────────────────────────────────────┘
```

| 出すもの | API | 更新 |
|---|---|---|
| 星図 | `sendCanvasImage`（id 固定の 1 枚） | 首が止まってから。実測 332〜390ms＋描画待ち 200ms |
| 星座名 | `sendCanvasElements`（差分更新） | 毎フレーム。数十 ms |
| 月・惑星の名前 | 同じテキスト枠。**星座名より先に置く**（月と 8 惑星） | 画像と一緒 |

**解説文はグラスに出さない。** 190 バイトでは入らないし、星図の上に長文を重ねると星が読めない。
**グラスは星図と星座名まで**にして、解説はスマホと音声に逃がす。

## 画面遷移

![画面遷移](diagrams/screen-flow.drawio.svg)

- **キャンバス 1 枚で回る。** ページ遷移が要らないので、状態はほぼ「観測中かどうか」だけ
- **方位合わせ中は星図を消して十字だけを出す**（バッファに同時に入らない）
- **解説中もグラスの画面は変わらない。** 音声はスマホから鳴る

## スマホの画面

**ホーム → 接続 → 方位合わせ → 星図**の 4 画面。星図の画面が本体で、
**上部バーの「衛星モード」で星座 ⇄ 人工衛星を切り替え、「設定」で調整と記録を別ページに畳む**。

```
┌─────────────────────────────┐
│ 現在の星空   [衛星モード][設定]│  ← 衛星モード中はボタンが点く
├─────────────────────────────┤
│  グラスに表示している星空      │
│  ┌───────────────────────┐  │  ← 送った画像そのもの（緑 8 階調に寄せた色）
│  │        · ·  ·         │  │     名前はグラス側が描くのでここには出ない
│  └───────────────────────┘  │     出す前は「何を待っているか」を回して出す
│  グラスの向きを止めると更新    │
├─────────────────────────────┤
│ AI 星座解説                  │
│ 解説を読み上げています        │
│ さそり座                     │
│ さそり座は南の低い空に…       │
├─────────────────────────────┤
│  [ この星空を解説する ]       │
│  [ 方位を合わせ直す ]         │
└─────────────────────────────┘
```

| 要素 | 中身 |
|---|---|
| プレビュー | グラスに送った画像そのもの。**同伴者に見せる用途にもなる** |
| 待ちの表示 | 星表・TLE・測位・転送。**何を待っているかを書く** |
| 解説／案内 | 進み具合と本文。**タップはグラス側なので出力専用** |
| いま空に出ている | 衛星モードだけ。`●` は日照、`○` は地球の影。上昇中か・最接近まで何分か |
| 設定ページ | グラスの明るさ・6DoF・方位合わせ・いま送る／消す・ログ・観測地 |

明るさは手動5段階のスライダーだけを置く。SDKから現在値を読み戻せないため、表示するのは
**このアプリが最後に送った値**。段階が変わると自動調整を無効化して値を送り、直前の星図を
再送して見た目へ反映する。ドラッグ中の値をすべて転送キューへ積まないよう、最新値だけをまとめる。

- **解説のカードはボタンの上**（音声が使えない環境ではテキストが主役になる）
- **位置と時刻を出すのは、間違っていても星図が「それらしく」出てしまうから。**
  タイムゾーンの取り違えは 135°、時計の 1 時間ずれは 15°。
  どちらもユーザーには気づけず、「AI が間違っている」と誤解される
- **衛星モードは星座モードと同じ並び**（プレビュー → 一言 → 案内のカード → ボタン 2 つ）。
  増やすのは中身だけで、要素は足さない

### 待ち時間の見せ方

**このアプリは黙る場面が多い。** 画面が切り替わったのに何も出ないと壊れたと思われる（`ui/Loading.kt`）。

| 待つもの | かかる時間 | 出す場所 |
|---|---|---|
| 人工衛星の TLE（10,748 機） | 1〜2 秒 | 画面の先頭 |
| **1 枚目の転送** | **実測 332〜390ms＋描画待ち 200ms** | **プレビューの枠の中** |
| 転送中（2 枚目以降） | 同上 | プレビューに札を重ねる |

**転送中はグラスから絵が消える。** スマホのプレビューは前の絵のままなので、
食い違いを札で明示する（`送信中（グラスは一時的に消える）`）。

## AI 解説（星座モード）

**`SINGLE_TAP` そのものが「あれは何？」という質問。**

```
SINGLE_TAP
   ↓
いまグラスに出している星図のラベルの先頭を主役にする   ← 視野中心にいちばん近い星座
   ↓
喋れない理由がある ──→ 案内を喋って終了
   ↓ 決まった
「おとめ座ですね」を即座に喋る       ← 端末が知っている事実。LLM を待たない
   ↓（並行して）
OpenAI に投げる ── その星図画像 ＋ ラベルの星座名 ＋ 視野内の固有名星 ＋ 位置・姿勢・日時・校正誤差
   ↓
SSEで届いた解説をスマホへ逐次表示し、句点まで届いた文から続けて読み上げる
```

- **主役は「グラスに出ているもの」から決める。** 絵・ラベル・AI へ渡す名前を
  **1 回の描画から作る**（`StarMap.constellationNames()`）。別々に計算していたときは、
  グラスに「オリオン座」と出ているのに中心 1 点の境界判定で別の星座を喋ることがあった（#37）
- **視線中心の点で星座を決めない。** 残っている地磁気の誤差 ±5〜15° にいちばん弱い推定で、
  境界際では隣に化ける。**ラベルは視野中心に近い順**で、大きな星座は
  「見えている部分のうち中心にいちばん近い点」で順位が付く
- **全文の生成は 1〜3 秒かかる。** 星座名は端末が既に知っているので最初の一言は即座に出し、
  本文は全文を待たず、最初の文が届いた時点から表示と読み上げを始める
- **音はスマホのスピーカーから鳴る。**
  **グラスには物理的にスピーカーが無い**ので、グラスから鳴らす道は最初から無い
- **仰角では断らない。** 「地平線より下だから地面だ」と断っていたが、水平あたりを見ただけでも
  仰角は負に振れる（方位合わせに残る誤差もそのまま乗る）。断られた側には理由が分からず、
  見えているものの名前も出ないまま黙る。**グラスに出ているものをそのまま解説する**
- **解説中に別の方向を向いても今の話を最後まで続ける。** 途中で切り替わると落ち着かない
- **解説の本文はSSEで受け取る。** トークン単位では読み上げず、句点までまとめる。
  細切れの発話を避けながら、3〜4文すべての生成を待つ時間は無くす

### 声と BGM

**[音（読み上げと BGM）](sound.md) に分けてある。** 既定は OpenAI の `gpt-4o-mini-tts` / `alloy` で、
圏外・キー未設定・失敗のときは端末の `TextToSpeech` に落ちる。BGM は解説していない間も鳴らし、
解説中は 28% まで絞る。

### 何を喋るか（観測データを根拠にする）

モデルの記憶だけで距離・大きさ・神話・季節を補わせない。端末が確定できる次の情報だけを渡す。

- **グラスに出している星図のラベル**（視野中心に近い順・主役は先頭）。
  ラベルが 1 つも出ない方向だけ Roman (1987) の IAU 境界表で代用する
- 同梱星表から視野内と計算できた固有名星、その等級と中心からの角距離
- 方角・高度・日時・観測地と、方位合わせ時の標準偏差
- 実際にグラスへ出した星図の形

応答に視野外の既知の星名、未提供の距離・神話などが混ざった文は、読み上げキューへ入れる前に
文単位で除外する。全て除外された場合は、端末が計算した星座・方角・高度・視野内の星だけで閉じる。

- **箇条書きを増やすほど 1 つずつは薄まる。** 実測で 11 個並べた版は末尾 2 つが無視された。
  **守らせたい注意は依頼文の末尾に置く**（星座名を言い直させない、呼びかけで締めさせない）
- **180 文字・3〜4文**を目安にし、解説中に次のタップを長く待たせない

### OpenAI に何を送るか

| 送るもの | 出処 |
|---|---|
| 星図の PNG | **グラスに出しているのと同じ絵** |
| 星座名 | **グラスに出しているラベルそのもの。** 視野中心に近い順に最大 3 個（先頭が主役） |
| 視野内の固有名星 | 同梱星表から計算した名前・等級・中心からの角距離 |
| 緯度経度・方位・仰角・日時 | 観測条件 |
| 方位・仰角の標準偏差 | 方位合わせ時の複数サンプルから計算した精度情報 |

- **画像だけにしない。** 緑 8 階調の点描を視覚モデルが読み違えても検知できないが、
  星座名は確定値なので併せて渡せば同定を間違えようがない。
  絵は「その星座がいまどう見えているか」を伝える役に徹させる
- **主役は依頼文の末尾でもう一度名前で指す。** システム側の箇条書きに
  「最初に挙がっている星座を主役にする」と書いていた版では、脇役に話が移ることがあった。
  脇役を並べる数も 3 つに減らした（並べるほど選び直す余地が増える）
- **画像は 3bit に落としてから送る。** 8bit のままだと実機では見えない淡い星まで写り、
  **見えていないものの解説**が返る
- プロンプトで**記号・箇条書き・括弧を禁じている**（読み上げは「※」も「1.」もそのまま読む）

### 推論は切る（`OPENAI_REASONING_EFFORT`）

**推論するモデルでは `none` にする。** 切らないと待ち時間が伸びるうえ、**本文が空で返る**。

推論トークンは出力と**同じ枠**（`max_completion_tokens`）を食うので、思考で使い切ると
`finish_reason` が `length` になり `content` が空になる。上のプロンプトで実測した：

| 設定 | 応答時間 | 本文が空 |
|---|---|---|
| 推論あり・枠 400 | 4.5〜4.8 秒 | **4/4 が空** |
| 推論なし・枠 2000 | 2.2〜2.9 秒 | 0/4 |

- **プロンプトを厚くするほど悪化する。** 200 文字・3〜4 文だった頃は 5 回中 3 回だったが、
  250 文字・指示 9 個にしたら全滅した。**中身を良くした結果が一度も聞こえない**状態になる
- **枠は 2000 に広げてある。** 喋る長さはプロンプトで縛っているので、広げても喋る量は増えない。
  **切られないための余裕**
- **値が空なら送らない。** 推論を持たないモデル（`gpt-4o` など）に送ると 400 で弾かれるため
- それでも空で返ったときは **1 回だけ自動で頼み直す**（モデル側の都合でまれに起きる）

### 通信断と再試行

- 接続・タイムアウト・HTTP 408 / 409 / 429 / 5xx は、**本文または音声をまだ1バイトも
  受け取っていない場合だけ**350ms待って1回再試行する
- 途中まで届いたあとには再試行しない。同じ文や音声が先頭から重なるため
- 文章が途中で切れたら、句点まで届いた文は表示・読み上げに残し、不完全な末尾だけ捨てて
  **失敗案内は足さず、その文までで自然に終える**
- ログには文章・音声ごとに、試行回数・先頭到着時間・全体時間・受信バイト数・
  `x-request-id` を残す。本文やAPIキーは通信ログへ載せない

### 失敗の理由を取り違えない

**「応答が空」と「圏外」を同じ文で喋らない。** 一緒くたにしていたときは、
通信できているのに「いまは通信ができない」と喋っていて、原因の切り分けができなかった。

| 何が起きたか | 喋る内容 |
|---|---|
| 本文が空（推論が枠を使い切った・断られた） | 「解説がうまく作れませんでした」 |
| API がエラーを返した（キー・モデル名・レート制限） | 「AI につながりませんでした」 |
| そもそも届いていない（圏外・タイムアウト） | 「いまは通信ができません」 |

どれも**方角と高度は端末が知っている**ので、そこまでは必ず喋って話を閉じる。
**スマホのログには生のメッセージを出す**（`HTTP 404: The model ... does not exist` など）。

### 喋れないとき

**タップしたのに無反応が一番よくない。** 必ず何か喋る。
IAU 境界は天球を隙間なく分割しているので**「星座が無い」方向は存在しない**。
決まらないのは、そもそも空を見ていないときだけ。

| 状況 | 応答 |
|---|---|
| まだ方位を合わせていない | 「まだ方位が合っていません。スマホをかざしてください」 |
| その方向に明るい星が無い | 「うみへび座のあたりですが、この方向に明るい星はありません」 |
| 圏外で AI を呼べない | 「いまは通信ができません」＋ 星座名と方角・高度 |
| 解説が空で返った | 「解説がうまく作れませんでした」＋ 星座名と方角・高度（**圏外とは言わない**） |
| API がエラーを返した | 「AI につながりませんでした」＋ 星座名と方角・高度 |
| API キーが未設定 | 「AI の設定がないので解説はできません」＋ 星座名 |

### API キーの置き場所

リポジトリ直下の **`.env`**（`.gitignore` 済み）。テンプレートは `.env.example`。

```sh
cp .env.example .env   # OPENAI_API_KEY= に書き込む
```

- 探す順は **`.env` → `local.properties` → `~/.gradle/gradle.properties` → 環境変数**
- 声を変えるなら同じ `.env` の `OPENAI_TTS_MODEL` / `OPENAI_TTS_VOICE`
- **モデルを変えたら `OPENAI_REASONING_EFFORT` も見直す**（上記）
- **どれも無くてもビルドは通る。** 画面に「キー未設定」と出るだけ
- **どの方式でも APK にキーは埋まる。** 配布せず手元の実機で動かす前提

## 衛星モードの `SINGLE_TAP`

**衛星モードでは星を 1 つも描いていない**ので、星座の解説を返すと見えているものと食い違う。
**LLM も呼ばない。** 機体名・方角・高度・日照はすべて端末が計算した確定値で、
生成に投げると待つだけ損になる（星座は由来や探し方があるので LLM が効く）。

```
SINGLE_TAP（衛星モード）
   ↓
タップ直前 0.5 秒の視線で、視野に入っている名前つきの機体を出す
   ↓
1 機もいない ──→ 「いま視野には人工衛星がいません」
   ↓ いる
「いま視野には ISS が入っています。南南西の空、高度 45 度あたりです。
　日が当たっているので、動く光として肉眼でも見えるかもしれません」
```

- **日照かどうかを必ず言う。** 影に入っていれば肉眼では絶対に見えないので、
  言わないと探し続けることになる
- スターリンクは名前を読み上げても意味がないので、案内するのは名前つきだけ
- **通信もキーも要らない。** 圏外でも成立する経路

詳しくは [人工衛星モード](satellites.md)。

## まだ決めていないこと

- **音声質問の入り口。** `micAudio` で PCM16 / 16kHz が取れるが、
  **3 つのジェスチャー枠は埋まっている**。騒音・圏外・発話の区切りという失敗経路も増える
- 通知を抑止するか
- 位置と時刻を常時出すか、異常時だけにするか
- ヒステリシスの内側マージンと保持時間
- 観測地の測位を続けるか（いまは画面に入ったとき 1 回だけ）
