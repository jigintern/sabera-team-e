## グラスへ出す

| やってしまうこと | 何が起きるか / どうする |
|---|---|
| RLE エンコーダを自前で書く | **SDK 0.0.12 で入った。** 書かない |
| Opus のデコーダを自前で書く | **SDK 0.3.0 で入った。** 書かない |
| 画像を「枚数」で設計する | id は 8 枚までだが、先に尽きるのは**バッファ 380,000 バイト**。`width * height * 2` の合計で数える |
| `sendCanvasImage` に 576×360 を渡す | **必ず `require` で落ちる**（ファームではなく SDK の制限） |
| 星や線を減らして転送量を削る | **8 割は真っ黒な背景**（下限は面積 / 32）。**面積を変えないと減らない** |
| 回るもの（クルクル）を画像で描く | 全画面 1 枚が 332〜390ms かかり、転送中は前の絵が消えるので**点滅にしかならない**。テキスト枠なら 1 要素 15 バイト・1 電文で回せる（**全角 1 文字で幅を揃える**と消し残らない） |
| 時間を連続再生して見せる | 2 秒ごとに全画面を焼き直すことになり、**転送のたびにパネルが消えるので原理的に点滅する**（#45 で実際に「とてもチカチカする」と出て撤去した）。**動かすのは「離したときに 1 回だけ送る」形にする** |
| なめらかに追従させる | 全画面を毎回送り直す方式なので**成立しない**。視線が一定以上動いたときだけ送る |
| **止まる先へ先出しする** | 減速に入った時点で「転送が終わるころの視線」へ 1 枚送る案。実機で **首を振っている最中に何度も点滅した**（#152）。`HeadMotion.slowing`（窓の後半が前半の 0.7 倍未満）は「止まる直前」だけでなく**流し見の速度のゆらぎでも成立する**ので、止まる気のない首振り中も `PREDICT_COOLDOWN_MS = 1200` ごとに発火し、そのたび 369〜540ms の暗転が入る（5 秒見回すと約 4 回）。**上の 3 つと同じ理由**で、動いている最中に 1 枚増やすと必ず消える。**`slowing` だけでは「止まりかけ」の代わりにならない** |
| 送信を積む | 0.6.0 の直列化は「積んでよい」という意味ではない。呼び出しは積むだけで返るので、**転送が追いつかないと古いフレームが順番待ちで残る** |
| 案内の矢印を細線と薄い階調で描く | シェブロン（2px の線 2 本）と 90/150/220 の点 3 つでは、実機で**「矢印が非常に分かりにくい」**（2026-08-24）。黒が透明なので**暗い画素は屋外の空に負け**、2〜4px の点は**背後の星と見分けが付かない**。**塗った面＋最上段の階調だけ**で描く |
| 矢印の頭を軸と同じくらいの幅で描く | 145°・長さ 0.20 では**頭が軸より 5px 広いだけ**で、「棒に瘤が付いた形」にしかならない（描いて数えた）。**頭は軸の 3 倍以上ひらく**（軸 13px に対して頭 45px 幅・22px 長） |
| 案内の枠を正方形にする | `width * height * 2` がそのまま効くので、**軸に沿った細長い枠のほうが長く描ける**（同じ 13,440 バイトで、正方形 82×82 なら 72px・120×56 なら 105px）。ただし**枠が変わるときは先に消す**（大きさも位置も違う枠を同じ id へ重ねると前の枠が残る） |
| 形だけで向きを伝える | 矢印が読めなくても**文字は読める**（テキストは 2.1.0 のファームでも出た唯一の経路）。**同じことを文字でも言う。** 出すのは角距離ではなく**いまの段で詰める左右差・上下差**で、首を振ると減るので「追えている」ことまで伝わる |
| テキスト枠を数だけで打ち切る | 190 バイトは**画面に置ける合計でもある**。8 枠まで数だけで詰めると日本語の名前 8 個で 200 バイトを超え、**先頭の枠から消える**。先頭は案内のラベルなので**いちばん消えてはいけない文字が消える**。数とバイト数の両方で打ち切る |
| テキストを 8 行置く | 190 バイトは**画面に置ける合計でもある**らしく、**最初の 1〜2 行が消えた**（分割して送っても押し出される）。1 電文に収まるぶんだけ置いて、続きは流す |
| 行を増やして情報量を増やす | 要素 1 つに座標と大きさで 12 バイトかかるので、**1 行の文字数が減るだけ**（3 行 17 文字／4 行 11 文字／5 行 8 文字）。増えるのは**見出しを畳んだぶんだけ** |
| 画面を持ったらすぐ描く | **ファームは消すまでテキストを持ち続ける。** 前のアプリや前の版が置いた文字が**あとから送った画像に重なる**。**8 枠まとめて空にしてから描く**（`clearedCanvasText()`・12 バイト × 8 で 1 電文） |
| 質問画面で最初の本文を待ってから文字を消す | 星図画像だけ先に消え、質問と関係のない**前の星座名が単独で残る**。解説画面へ切り替える電文で8枠を先に空にし、そのあと画像を消す |
| テキストを上書きで書き換える | ファームは新しい矩形しか描き直さないので、**短い名前へ変えると前の名前の末尾が残る**（「る」の 1 文字が残った）。ただし**前の矩形を覆えるなら消さない**（毎フレーム消すと衛星の印がちらつく） |
| ファームの機能を前提にする | 手元のファームはキャンバス画像が動くが **`FEATURE_VERSION` は未取得**。配布先が同じとは限らないので**退路（196×196）の設計は残す** |
| `SettingKey` の値を断定する | 一覧は `sources.jar` から読み取ったもので、**値の意味と範囲は未確認** |

## 星図と方位

| やってしまうこと | 何が起きるか / どうする |
|---|---|
| `yawDegrees` をそのまま方位に使う | **静止中に 44°/分 流れる。** ジャイロの大きさで動きを判定し、**動いている間だけ差分を足す**（実装済み） |
| ドリフト率を「連続して静止した時間」で測る | 星を見ながら 3〜4 秒おきに首を動かすと**一度も測れない**。そのあいだ率は 0 のままなので、動いている間の 0.74°/秒 が丸ごと方位へ入り、**方位が増える向き＝星図の S が左へ流れていく**（#132。動作 25% で 3 分に 33°）。**静止していたサンプルの合計で測る**（間に首振りが挟まっても足し直せる）。窓を短くするほうは採らない — ノイズがそのまま率に乗る |
| 計算で出た大きさを「原因」と書く | 「ジャイロはその瞬間、ヨーの差分は 100ms の合計だから、減速の最後で首振りが消える」— **計算では 5 分で 124° 消えるのに、実機では 1 度も起きなかった**（`拾った首振り=0°`・#132）。ファームのヨーとジャイロは食い違っていなかった。**筋が通っていることと、実機で起きることは別。** 入れるなら「安全弁」と書き、**効いたかどうかは数える口をログに付けてから言う** |
| ドリフト率を一定として扱う | **観測の最初の 2 分で −0.21 → −0.35°/秒 へ上がる**（#132）。通算平均だと最初の低い値を引きずって 0.1°/秒 足りず、**10 分で 8〜11° 漏れる**（「最初はほぼ同じ、最後は目に見えて左」）。**同じ比に指数の重みを掛ける**（時定数は静止 20 秒） |
| 分ごとに割り直さずに通算値だけ見る | 通算は **−0.183 → −0.212 → −0.245** と単調に増えるだけで、**真の率が上がっているのか平均が追いついていないのか区別できない**。`止めた量` と `静止計` の**増分で割れば 1 分ごとの率が出る**（#132） |
| ドリフト率を窓ごとに測って重みで平滑化する | 窓 30 秒・重み 0.3 では**4 分ぶん静止しないと率が追いつかない**。実機ではそのあいだ**必要な量の 1/3 しか引けず**、漏れ 7°/分（#132）。**静止したサンプルの通算平均にする** — 測った全部が効き、調整する数字も減る |
| 補正の効きを「結果のずれ」だけで見る | ずれているのは分かっても**どこで漏れているか分からない**。`引くべき量（率 × 動作計）` と `引いた量（補正計）` を並べてログへ出したら、1 行で決まった（#132） |
| `sendNaviCourse` を方位問題の解決に使う | **`yawDegrees` に返らないと実測済み**（[記録](71_yaw-drift.md)） |
| 画素数から画角を決める | パネルが 576×360 と分かっても、**視野の何度を占めるかは別問題** |
| 絵と根拠を別々に計算する | グラスに出したラベルと AI へ渡す星座名を別に出していたら、**「オリオン座」と出ているのに別の星座を喋った**（#37）。**1 回の描画から作る** |
| 「焼いた絵」と「送れた絵」の状態を別々の場所で更新する | 1 回の描画から作っていても、**確定する場所が 2 つあれば同じことが起きる**。`lastMap` / `lastMapLook` / `lastMapObservation` / `bodiesShown` はバッファ超過チェックの**前**、`drawnLook` / `drawnFov` / `drawnRoll` は送信の**後**に入っていた。超過（`return null`）でも送信例外でも前者だけが新しい絵へ進むので、**グラスには前の絵が出ているのに解説は送れなかった絵の話をする**（#123）。#118 が `basisRoll` で `lastMapLook` と `drawnRoll` を組にしたとき、傾きのずれとして表に出た。**送れたことを確かめてから、1 か所でまとめて確定する**。描き直しループは最初から「`drawAndSend()` が null なら描いていない」で動いている |
| 「視野に入っているか」を半径 fov/2 の円で切る | **星図は横長。** 544×340・画角 35° なら横は ±17.5° あるが**縦は ±11.0°**しかなく、隅は 20.6° まで届く。円で切ると**中心の真上 12〜17° の惑星や星が「視野内」として AI に渡るのに、絵には描かれない**（renderer は枠で切るので）。逆に隅は絵にあるのに渡らない。**パネルの長方形で切る**（`sky.withinPanel`）。**首の傾きも渡す**（枠ごと回るので入るものが変わる） |
| ヨー → 方位の符号を呼び出し側で書く | `azimuthFromYaw` に一本化したはずが、**`latchedLook()` だけ足し算のまま残っていた**（`fix: ヨーは方位と逆に回る` が `look()` しか直していなかった）。ずれは**首を振った角度の 2 倍**。星図を 1 枚も焼く前に解説へ入ったときだけ効くので、**絵が出ている限り隠れる**のがたちが悪い。**符号を書く場所は `sky/Coordinates.kt` の 2 つだけ** |
| 描き直しのしきい値を方位の生の差で測る | `REDRAW_DEG = 6.0` は「画角 35° に対しておよそ 1/6」＝**空の上の角度**のつもりなのに、`max(|Δ方位|, |Δ高度|)` で測っていた。**高度 80° では方位 6° が空の上では 1.0°**しかなく、絵がほとんど動いていないのに**0.4 秒の暗転（転送）が走る**。逆に `STILL_DEG = 1.0` 側は、真上を見ている間わずかな揺れを「動いている」と読む。**空の上の隔たりで測る**（`glass.lookSeparationDeg`）。`HeadMotion` は最初から cos(高度) を掛けていた |
| 衛星だけ幾何学的高度のまま重ねる | 星・星座線・月惑星は `toApparentAltAz` を通っているのに、`Observer.look` は大気差を入れない。**同じ 1 枚の中で地平線際 0.48°・高度 5° で 0.17° の系統差**になる。`SatelliteScene` 側で見かけの高度へ直す（`Observer` は幾何のままにしておく） |
| 首の向きを命令に使う | 星図を出している間は**頭の向き＝見ている空**で、命令のたびに見る空が変わる。「首を振ったら星図へ戻す」を入れたら**読んでいる途中に見上げただけで消えた**ので撤去した。例外は**解説画面の字幕送りだけ**（`alignment/HeadFlick.kt`）で、そこでも**向きではなく「速く振って戻る」形**で見分ける |
| 加速度の軸を「たぶんこれ」で書く | `rollFromAccel` は **X 軸が右**だと仮定していたが、台帳の実測は**上 = +X・前 = −Y**（静止 865 件・ピッチ幅 76°）。水平に構えただけで `atan2(1000, 0) = 90°` を返し、**返っていたのは実際には (90° − ピッチ)** だった。星図が枠ごと 90° 回り、**見上げるほど回転量が変わるので目標が画面の中を動いて逃げる**。左右の傾きも区別できていなかった（+20° と −20° がどちらも 70°）。**軸は [台帳](70_measurements.md) に測ってある。仮定で書かない** |
| 空に載せる絵を「投影後の外接矩形」へ写す | **矩形の縦横比は空の位置で変わる**ので、同じ星座でも東の低いところと南中とで絵が伸び縮みする。しかも矩形は画面軸に揃っているので、**首を傾けると星だけ回って絵は立ったまま**になる。星に載せるものは**星と同じ赤道座標で持ち、同じ変換を通す**（2026-08-25） |
| 度の値に `* DEG` と書く | **`DEG = 180/π` は rad → deg、`RAD = π/180` が deg → rad。** 名前だけ見ると「度にする」と読めるので、度のまま `cos(赤緯 * DEG)` と書いても目に留まらない。入るのは**0.04〜0.99 の無関係な係数（符号つき）**で、解説画面の星座絵はこれで**21 星座が線 1 本まで潰れ、44 星座は東西が鏡像**になっていた（#135。みずがめ座の横の充填率 0.17）。**`cos` / `sin` に渡す前は `RAD`。** `* DEG` が正しいのは `atan2` / `asin` の**出口だけ** |
| 形の正しさを充填率のしきい値だけで守る | 「枠の 0.2 以上埋まる」では、**しきい値をまたがない潰れと鏡像を 1 つも拾えない**（#135 では 88 星座のうち 21 個しか赤くならず、東西の反転は 44 個すべて素通りした）。**空の縦横比そのものを画素で固定する**（`ExplanationArtTest`）。ついでに、ループの中で assert すると**最初の 1 個で止まって広がりが見えない**ので、何個壊れているかは別に数える |
| 星座絵をそのままの大きさで敷く | 星図の星座絵は**星の並びよりずっと大きい**（ペガススの馬は四辺形の 5 倍で、置くと 90° を超えて広がる）。画角 35° では「どこかの線」にしか見えないので、**星座線の広がりの 1.3 倍・最小 12°・最大 30° で切る**。**最小を忘れると**からす座のように星が 4 個しかない星座で輪郭の切れ端しか残らない |
| 仰角で解説を断る | 水平あたりでも仰角は負に振れる。「地面を向いています」で断ると、**見えているものの名前も出ないまま黙る** |
| `onAccuracyChanged` の `sensor` を捨てる | 1 つのリスナーで回転ベクトル・加速度計・磁力計を購読しているので、**ほぼ常に `HIGH` を返す加速度計が磁力計の信頼度を上書きする。** しかも初期値を配る順は登録のたびに変わるので、**「8 の字に振ってください」が画面に入り直すたびに運で素通りした**（#65）。種別で絞る |
| 判定していない動作を指示する | 「スマホを立ててください」と出していたが、見ていたのは**回転ベクトルが 1 件来たか**だけで姿勢は見ていない。しかも背面の向きは**画面法線まわりの回転に不変**なので、横に寝かせても方位も仰角も変わらない。**言われたとおり立てても何も変わらなかった**（#79）。`!= null` を「準備できたか」と「正しい姿勢か」の両方に使わない |
| 磁気精度で止めきる | 較正が上がらない端末では方位合わせから先へ一切進めない。歪みと同じで**通すが黙っては通さない**（`alignment/CompassGate.kt` が 15 秒で赤字を出して逃がす） |

## 声で聞く

| やってしまうこと | 何が起きるか / どうする |
|---|---|
| 端末の推測で録れた音を捨てる | 「声として数えた時間が 0ms なら聞き取れなかった」と返していたが、しきい値はその場の暗騒音からの推測で、**風が 1 回入るだけで上限（4,000）に張り付く**。喋って送っても**文字起こしへ行かずに「聞き取れませんでした」**（2026-08-24）。**2 回目の長押しは「これを送る」という意思表示**なので、届いた音は必ず文字起こしへ送る。0ms はログに残すだけ |
| 暗騒音を冒頭の 0.4 秒だけで決める | そこに風や物音が入ると**そのあとの声を一度も数えられない**。人は言葉の合間に必ず黙るので、**録音全体の最小値**を取り続けるほうが本当の暗騒音に寄る |
| 音量表示をしきい値で頭打ちにする | ふつうの声はしきい値の 2〜8 倍なので、**喋り出した瞬間に全点灯して以降動かない**。「枠が固まっている＝聞こえていない」ようにしか見えない。**しきい値の 0.5〜8 倍を対数で**割り当てる |
| 音量だけで「届いた」を伝える | 枠が動いても**それが自分の声なのかは分からない**。拾えた時点で**文字を書き換える**（「質問をどうぞ。」→「聞こえています」）。いちど拾えたら戻さない（**知りたいのは「届いたか」で、いま喋っているかではない**） |
| グラスの字形を当てにする | `●○` が出るかは**未確認**。**数字も添える**（「5/8」）ので、丸が無くても動いていることは伝わる |
| マイクから 1 バイトも来ないのを「聞き取れなかった」と言う | 言い直しても直らない。**別の文で返す**（「マイクから音が届きませんでした」） |

## 喋る（読み上げ）

| やってしまうこと | 何が起きるか / どうする |
|---|---|
| 次の一言を `Voice.say` で出す | `say` は仕様どおり**前の発話を捨てる**（`CloudVoice` は再生中の AudioTrack ごと止める）。ガイドの締めがこれで、**最後の星座の解説が一言も鳴らないまま「ガイドはここまでです」**になっていた（#121）。合成に 1〜3 秒かかるので、**まだ鳴り出していない解説ほど丸ごと消える**。後ろへ続けたいときは `add`（`Narrator.retell(flush = false)`）を使い、**捨ててよいときだけ `say`** |
| 読み上げの終わりを `tts.isSpeaking` で見る | 解説は**文ごとに積む**（`QUEUE_ADD`）ので、`onDone` の時点でエンジンが次の文をまだ持っていないと **false を返す**。待っている側（ガイドの進行役・解説画面の秒読み）は**読み上げの途中で先へ進む**。積んだ数を数えて、**0 になったときだけ**終わりにする |
| 捨てた発話の完了通知を数に入れる | `QUEUE_FLUSH` と `stop` で落とした発話にも、`UtteranceProgressListener.onStop` の既定実装から **`onDone` が後から届く**。数えていると**その 1 通で新しい発話まで 0 に戻る**。世代（`generation`）を付けて見分ける |
| 「喋っている」を立ててから数を増やす | その隙間で worker が前の 1 本を数え終えると **0 と見えて倒れる**。倒れたら次に積むまで戻らないので、**その解説の間ずっと「喋っていない」**ことになる。**数を先に増やす** |
| 音が鳴らないまま 5 秒で解説画面を畳む | 合成の 1〜3 秒や端末の読み上げの出遅れで、**読み始める前に消える**。`0bfc8a3` で「鳴っていなければ 25 秒」の保険（`EXPLANATION_READ_MS`）が外れていた。**騒がしい場所やイヤホンが無いときは文字が主役**なので、鳴るまでは黙読ぶんの時間を置く |

## 機能をやめるとき

| やってしまうこと | 何が起きるか / どうする |
|---|---|
| 入口だけ外して中身を残す | `DOUBLE_TAP` を「戻る」へ譲った（025c0e1）ときに一口メモの入口が消えたが、**そこへ渡すはずだったパス予報の計算は残った**。呼ぶ人がいないので**一度も動いていないのに、テストは緑・ドキュメントは「実装・JVM テスト済み」**のまま 2 日進んだ（2026-08-26 に撤去）。**入口を外すときは、その入口にしか出口が無いものを一緒に消す** |
| 残った計算を「そのうち使う」で置いておく | 使うときには**置き場所（入口）から決め直す**ことになるので、残しておいて省ける手間は計算だけ。しかも**動かないまま古びる**。消して `git log -S` から戻すほうが速い |

## Kotlin と Android

| やってしまうこと | 何が起きるか / どうする |
|---|---|
| `optString` を JSON の null に使う | Android の org.json は**文字列 "null" を返す**が、JVM テストで使う本物の org.json は空を返す。**テストで絶対に落ちず実機だけで壊れる**（OpenAI の `refusal: null` を拒否と読み、本文を毎回捨てていた）。`isNull()` で見る |
| フェードと後始末を 1 本のジョブに載せる | BGM を切る 3 秒フェードと `MediaPlayer` の解放を同じ `fade` ジョブに載せていたら、**フェード中に来た絞り（`duck`）や音量つまみが `ramp` でジョブごと差し替え、`close` に永久に届かなくなった**（#163）。切ったのに曲は音量 0 のまま鳴り続け、指名していれば永久にループする。**割り込まれてよいもの（音量の追従）と、割り込まれてはいけないもの（後始末）を別のジョブに分ける** |
| `async` を画面のスコープの素の子にする | **失敗は `await` で受け取っても親を巻き込む。** TTS が 1 回失敗しただけで 6DoF の購読とログが道連れで死に、**星図が二度と更新されなくなった**（2026-08-21・圏外）。`SupervisorJob` を挟む |
| `SupervisorJob` を `coroutineScope { }` の中で作る | 自分では完了しないので、構造化並行性が子の完了を待って**永久に止まる**。`SingleFlightTest` がこれで、**1 つのテストのせいで `:app:testDebugUnitTest` が返ってこなかった**（他のテストは 1 件も見えない） |
| 同じ周期の 2 つのループで同じ `tryLock` を取る | 星図の描き直しは「塞がっていたら諦める」なので、矢印の送信と**周期が同じだと位相が噛み合ったまま何秒も星図が描き直されない**（矢印だけ動いて空が古いままになる）。周期をずらす（100ms と 130ms） |
| SDK のソース jar に見えたクラスを manifest に名指しする | **AAR は難読化されていて、ソースにあるクラスが出荷物にあるとは限らない。** SDK 0.6.0 の `BluetoothStateReceiver`（Bluetooth を OFF にしても GATT の切断コールバックが 来ないのを補うレシーバ）はソース jar にはあるが、**AAR では名前が潰れていて dex に存在しない**（名前が残るのは `BleCompanionDeviceService` と `BleDeviceSelector` だけ）。宣言しても `assembleDebug` は通るので気づけず、**Bluetooth を切り替えた瞬間にクラスを生成できず落ちる APK**ができる。**manifest に書くクラスは APK の dex で実在を確かめる**（`unzip` して `grep -a`）。この穴のせいで `connectToLastDevice` による自動再接続は走っていない（2026-08-26） |
| リポジトリのファイルを読むテストを入力宣言せずに置く | `File(...)` で直に読むと **Gradle からは入力に見えない**ので、そのファイルだけ壊しても **テストが UP-TO-DATE のまま緑で通る**（`--rerun-tasks` で初めて落ちる）。番人のつもりのテストが番をしない。`inputs.file(...)` で入力に足す |
| 例外を各経路で握る | 解説・質問・衛星の案内は 1 か所から走らせ、`Throwable` を受けて断りを喋る（**`SupervisorJob` は未捕捉例外を止めない**） |
| 全画面の点灯画素数で描き分けを測る | 数えたいもの以外の層を切り忘れると、その画素数が比べる両方に等しく乗る。**測りたい差が一定のまま比が縮む**ので、下敷きが濃くなった日に無関係なテストが落ちる。星座絵を 7 → 88 星座にした #78 で、視野に絵が入って背景が 0 → 444 画素になり、衛星の「名前つきは群れの 2 倍」（69 対 217 で成立）が 513 対 661 になって落ちた（2026-08-25）。**測る層だけ残して他は全部切る** |
| 字幕で `Narrator.state` をそのまま `collectLatest` する | 読み上げ終了時は本文が同じでも相が変わるため、**走っている字幕ループが捨てられて 1 行目から流れ直す**（実機で発覚）。`distinctUntilChangedBy { it.text to it.constellation }` を挟み、本文か見出しが変わったときだけ組み直す |
