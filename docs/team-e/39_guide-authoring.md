# ガイドの台本を作る・配る

**作るのは電波のあるうち、使うのは空の下。** 台本の形と再生は [星座ガイド](37_guide.md)。
再生時に AI を使わない理由は [解説と声](34_narration.md)、QR に入る量は
[実測値の台帳](70_measurements.md)。

| | 誰のため | 何をする |
|---|---|---|
| **即興ガイド（toC）** | 個人 | その場で作る。**電波があれば AI が書き、無ければ同梱を組む** |
| **詳細なカスタマイズ（toB）** | 旅行会社・星空ツアー | 星座も順番も文面も自分で決める。**QR で客の端末へ配る** |

## 即興ガイドを作る（toC）

**候補を選ぶのは端末。AI に選ばせない。** 空に出ていない星座を並べられると、
再生で全部飛んで「何も起きないガイド」になる。

候補は `StarMapRenderer.guidanceTargets()`（`SkyDensity.STANDARD`）の星座だけ。
**星図に線と名前が出る星座しか候補に入らない**ので、
「台本には載っているのにグラスには何も出ない」が起きない（#37 と同じ考え方）。

| テーマ | 選び方 |
|---|---|
| 今夜のおすすめ | 高いものから。**建物と木に邪魔されない順** |
| 明るくて探しやすい | その星座でいちばん明るい星が 2.0 等より明るいものだけ |
| 神話をたどる | 同梱の本文に物語があるもの。**「神話」の語では判定できない**（ポンプ座の本文は「神話は伝わっていません」） |
| 沈む前に見ておく | 西寄りで低いものから。**待つと見られなくなる順** |

- 3〜5 段。**次はいちばん近い星座へ送る**（南 → 北 → 南と振り回すと、
  方位補正がいちばん苦手な速い首振りが毎回入る）
- **テーマで 1 つも残らないなら、テーマを諦めて見やすいものを返す。**
  「今夜は作れません」と断るより、少し外れても回れるほうがよい

### AI に本文を書かせてよい条件

AGENTS.md は「解説文を AI に生成させる」を禁じている。理由は
**「星を見に行く場所ほど電波が届かない。いちばん要るときに一言も出せなかった」**。
ガイドはこの理由を壊さない形にしてあり、**次の 4 つが揃っているときだけ例外になる。**

1. **通信するのは台本を作るときだけ。** 出来た文は台本に焼き込むので、
   **再生時は圏外でも最後まで喋る**
2. **失敗・圏外・鍵なしなら同梱の 88 星座へ落ちる**（`GuideMaker`）。断って終わらせない
3. **星座を選ぶのは端末。** AI へ渡すのは端末が確定した並びだけで、AI は文を書くだけ
4. **返ってきた文は端末が検査する。** 記号と箇条書きを落とし（`AskGuard.sanitizeAnswer`）、
   グラスの解説画面に入る長さまで**文の切れ目で**切る

**半分だけ AI の文にしない。** 1 つでも星座が欠けたら台本ごと捨てて同梱で組み直す。
途中で口調が変わると、**別人が喋り出したように聞こえる**（34_narration.md と同じ理由）。

## 詳細ガイドを作る（toB）

**旅行会社が自分のツアー用に作り込む。** 即興ガイドとの違いは、**人が全部握れる**こと。
星座を選び、順番を決め、文面を書く。AI は**候補の中から選んで文を書くだけ**。

星空ツアーは「9/12 20:00、乗鞍高原、40 分」のように**日時と場所と長さが決まっている**。
そこへ向けて組み、当日の天気を見て段を外し、客の端末へ QR で配る。

### 想定した空（**再生には使わない**）

事務所（東京）で乗鞍高原のツアーを書くので、**測位のままだと東京の空で組んでしまう**。
台本に想定を持たせるが、**使うのは作るときの検算だけ**で、再生はいまの空で引き直す
（書き置いた方角が別の夜に嘘になる、という原則は崩さない）。

| | |
|---|---|
| 日時 | 日付＋開始時刻。既定は**今夜の 20 時**（開いた瞬間に候補が空にならないように） |
| 所要時間 | **30 / 45 / 60 / 90 分**から選ぶ |
| 場所 | 既定は測位。**緯度経度を打ち替えられる**（地図は依存が重いので入れない） |

### その日に見えるかは「幅」で見る

**一点で判定しない。** 20:00 に地平線の下でも 20:40 には昇っている星座がある。
一点で見ると**東から昇るものを全部落とし**、秋のツアーで最後に冬の星座を見せる、
という一番よくある構成が作れなくなる。

さらに**段ごとの推定時刻**（`開始 + N × 所要時間 / 段数`）で見る。こうすると
「沈む前に見ておく」順番が正しいかを、作るときに検算できる。

- 追加の計算はほぼゼロ。`guidanceTargets(site, **epochMillis**)` は**すでに任意時刻を受ける**
- 下限は `GuidePlan.MIN_ALTITUDE_DEG`（20°）のまま。**下げない**
  （下げると「作れたのに再生で飛ぶ台本」ができる）
- 対象は**星座・一等星・大三角・月惑星**。**人工衛星は入れない**
  （TLE が 1 週間で 2〜3° ずれ、そもそも「30 分以内のパス」しか案内対象にならない）

### AI との対話（**4 条件は崩さない**）

```
① 日時・場所・所要時間を入れる
      ↓
② 端末がその空から候補を出す        ← GuideSchedule.candidates
      ↓ 選ぶ（自分で選んでも、AI に組ませてもよい）
③ 足りなければ相談する
      「秋の星座で 40 分」「もっと短く」「オリオン座も入れて」
      ↓
   候補に無い名前が入っていたら、**通信する前に**端末が断る
      「その時間、オリオン座はまだ低すぎます。21:40 以降なら入れられます」
```

| | |
|---|---|
| AI が選べる範囲 | **端末が作った候補の中だけ。** 候補外の名前が返ったら黙って捨てる（4 条件の③） |
| 打たれた文の判断 | **通信の前に端末が済ませる**（`guide/GuideAsk`）。渡すと AI が気を利かせて載せてしまう |
| 往復 | **10 まで**（`GuideAsk.MAX_TURNS`）。履歴は持つが**台本には残さない** |
| 返ってきた文 | `AskGuard.sanitizeAnswer` が記号と箇条書きを落とす（4 条件の④） |
| 圏外・鍵なし | **AI の口を出さない。**「通信が無いので同梱の文を入れます」と明示する |

- toC は「断らない」を優先したが、**toB は「知らないうちに中身が変わる」ほうが害が大きい**
  （作った本人が説明できないと困る。`origin` を残したのと同じ理由）
- **断るだけで終わらせない。** ずらせば入るのは端末が計算できる事実なので、代案を添える
  （行き止まりにすると、そこで人が諦める）

### 長さの上限（**黙って切らない**）

| | 上限 | 超えたら |
|---|---|---|
| 1 段の本文 | **272 字**（`GlassTextPage.pagedChars` = 16 行 × 17 字） | 赤く出し、**配るのを止める** |
| 台本ぜんぶ | QR 1 枚（下） | 残量バーを赤くし、**配るのを止める** |

`AskGuard` の 200 字は **AI の答え専用**。人が責任を持って書いた文に当てると、
「書いたのに消えた」が**実機で初めて分かる**（旅行会社が現地で気づく）。

## 配る（QR とファイル）

**QR 1 枚に、圧縮した生バイトを焼く。** 文字ではなくバイトを運ぶ。

```
段数（本文 200 字）  Deflate 後   QR 1 枚（version 40・誤り訂正 L・2,953 バイト）
      5 段            1,679       入る
     10 段            2,779       入る          ← ここが上限
     11 段            3,002       入らない
     15 段            3,827       入らない
```

| 論点 | 決定 |
|---|---|
| 焼き方 | Deflate → **生バイトのまま**。Base64 を挟むと 4 割損して**5 段が限界**になる |
| バイトモード | ZXing に **ISO-8859-1** で渡す（0〜255 を 1 バイトへ 1 対 1 で写す唯一の実用的な文字集合） |
| 段数の上限 | **固定値を置かない。** 文の長さで変わるので、**実測して残量を出し**、あふれたら止める |
| 外した段 | **QR に入れない。** 読めない段のために枠を食う余裕がない |
| 分割 | **しない。** 客に 3 枚読ませることになる。**2026-08-25 に実機で 1 枚で読めた**（画面に出したもの） |
| ファイル | **素の JSON。** 容量の理由が無いので圧縮しない。PC で文面を直す逃げ道になる |
| 読み取り | **CameraX ＋ zxing core。** カメラを断った人はファイルから入れられる |

- **ZXing Android Embedded は使わない。** 独自の Activity を持ち込み、
  **読み取り中の縦固定**（#130・[phone-ui](33_phone-ui.md)）と衝突する
- **ML Kit は使わない。** Play Services のモジュールをその場で落とすので、
  **オフラインで完結する**という土台が崩れる
- 誤り訂正を **L** にしているのは段数のため（M で 2,331・Q で 1,663 バイトまで落ちる）。
  画面に出してその場で読ませる使い方なので、汚れや破れは想定しない

### 受け取った台本をどこまで信じるか

**危険の幅は狭い。**

| | 届くか | なぜ |
|---|---|---|
| AI への指示の混入 | **届かない** | 再生時は通信ゼロ。声で質問したときも AI へ渡すのは**星座名だけ**（`AskContext.constellations`） |
| 存在しない星座名 | **届かない** | `GuidePlan` が `guidanceTargets()` と突き合わせ、一致しない段は飛ぶ |
| 任意の文章の読み上げ | **届く** | `body` は検査を通らずそのまま読まれる。**旅行会社が書いた文を勝手に壊さない**ため受け入れる |
| 巨大な入力で固める | **塞ぐ** | 段数・字数・展開後のバイト数で弾く（`GuideCodec`） |

- **形だけ見て、中身は見ない。** 記号を落とすと、意図した表記まで壊れる
- **読み込む前に中身を見せる。**「何を喋るのか分からないまま外へ持ち出させない」を
  受け取り側にも当てる。QR は誰でも作れるので、**入れる前に本人が読めるようにする**
- **圧縮爆弾を止める。** QR は 2,953 バイトしか運べないが、Deflate は千倍に膨らませられる

### 編集させるかどうか（`locked`）

支店が原本を元に少し違う解説を作ることがあるので、**配るときに選ぶ**。

| | |
|---|---|
| どこに持つか | `StarGuide.locked`。**`origin` に値を足さない**（`GuideOrigin.of()` は知らない値を `IMPROMPTU_BUNDLED` へ落とすので、知らない端末で嘘のラベルが出る） |
| 既定 | **編集できる。** 壊れた・古い台本を触れなくすると、直す手立てごと失われる |
| 編集の範囲 | **全部。原本と同じエディタが開く**（制限つきエディタは 2 つ目の画面になり、「編集できるのに直せない項目」の説明が要る） |
| 編集したあと | `origin` が **「手で書いた」に変わり、元が `derivedFrom` に残る**。「受け取った」のまま中身が変わると嘘になり、消すと辿れなくなる |
| 再配布 | **許す**（支店が直した版を自分のツアーで配るのが想定用途） |

**`locked` は鍵ではない。** QR の中身は誰でも作れるので、書き換えれば編集できてしまう。
守りたいのは「客がうっかり直す」ことであって改ざんではないので、これで足りる。
署名にすると**リース先ごとの鍵の配布・失効**まで抱え込むことになる。

## スマホの画面

| どこ | 何ができるか |
|---|---|
| ホーム／設定 →「ガイドを作る」（`ui/GuideScreen.kt`） | テーマを選んで作る・中身を読む・直す・配る・消す。**グラスは要らない**。**戻ると入ってきた画面へ返る**（観測中に作りに来た人をホームへ落とさない） |
| 同じ画面の「ガイドを受け取る」（`ui/GuideImportScreen.kt`） | QR かファイルから入れる。**入れる前に中身を見せる** |
| 同じ画面のいちばん下、畳んだ「星座も順番も文も、自分で決めて作る」（`ui/AuthoredGuideScreen.kt`） | toB の詳細エディタ。**「詳しく作る」では何が違うのか分からなかった**ので、やることをそのまま名前にした |
| 「配る」（`ui/GuideShareScreen.kt`） | 段の ON/OFF・編集の可否・QR・ファイル書き出し |

### 画面の作り

- **手順をそのまま見出しにする** — `テーマを選ぶ` → `作成する` → `作った台本`。
  説明文で書くより、いまどこにいるのかが形で分かる
- **選ぶと作るを分ける。** 行を押した瞬間に作りはじめると、読み終わる前に走り出す
- **作りの話は画面に書かない** — 「AI が書きます」「同梱の解説で組みます」「端末に残ります」は
  **使う人が決めることを変えない**。出来上がりが同じなら、どう作ったかは知らなくてよい
- **バーのすぐ下から始める。** 上に説明文を積むと、何をする画面なのかが 1 画面目から押し出される
- **横画面では作成を左、受け取りを右へ分ける。** 左端はインカメを避けて 40dp 空け、
  「受け取る」と詳細作成は右ペイン中央の最大 320dp に置く
- **受け取りの QR／ファイルボタンは最大 320dp。** 画面幅いっぱいの帯にしない
- **配る QR は右半分の中央。** QR とファイル書き出しを右、段の ON/OFF・編集可否・容量を左に置く。
  QR の一辺は右ペインの幅と、縦幅から説明 56dp・カード余白 24dp を引いた小さいほうで決める

### ボタンを並べない

- **テーマは行そのものを押させる。** 1 行に 1 つ「作る」を置くと、テーマの数だけボタンが並ぶ
- **台本カードは押すと中身が開く。** 「中身を読む」ボタンが要らなくなる
- **直す・配る・消すはアイコン 1 行。** 台本が増えるほど、文字のボタンは壁になる
- **消すだけ 2 回押させる**（アイコン →「本当に消す」）。取り消せないのに、アイコンは指が滑って当たる

- **作ったのに何も言わない画面にしない。** 何本目ができたか、AI と同梱のどちらで組んだかを出す
- 台本の中身は作った画面で読める。**何を喋るのか分からないまま外へ持ち出させない**
- 観測地は測位が取れていれば使い、無ければ既定の鯖江。
  数十 km ずれても**どの星座が空に出ているかはほとんど変わらない**
- **詳細エディタは畳んでおく。** リース先向けの機能なので、ふだんは目に入らない。
  ただし**隠し操作にはしない**（口頭で伝える運用になり、担当者が代わると失われる）
