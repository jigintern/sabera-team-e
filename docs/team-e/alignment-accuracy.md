# 星図を空に重ねる精度の詰め方（**見送った計画**）

> **この計画は採らない。** 2026-08-21 に「**精度より UX**」で決着した。
> 使う人は天文の初心者で、要るのは「どのあたりに何があるか」なので、
> **星座の同定（±20°）で足りる**。手順を増やして ±2〜3° を取りにいくと、
> **夜の屋外で初心者に星を探させる**ことになり、得るものより失うものが大きい。
>
> - **方位合わせは最初の 1 回だけ。** スマホ同期（段階 1）で確定して観測へ進む
> - **天体アライメント（段階 2）はアプリから撤去した**
>   （`CelestialAlignment.kt` / `AlignmentTargets.kt` とそのテスト 21 件）
> - **手順を増やさない精度向上は残す。** ヨードリフト補正、IAU 境界での星座判定、
>   静止区間の平均を採る確定は、ユーザーに何もさせないので入れたままにする
>
> 以下は**そのとき何を検討して何を捨てたかの記録**として残す。
> 精度を取りに戻る判断をするときは、まずここを読む。

**目標＝グラスの星図が実際の空とほぼ完全に重なること。** いまのボトルネックは方位合わせで、
その先に何を積めば「重なる」まで行けるかを、**費用対効果と初心者への UX 負担の両方**で並べた計画。

前提の数値は [座標変換パイプライン](coordinate-system.md)、出力の制約は
[グラス出力の制約](glass-output.md)。

## 0. 「完璧に重なる」を数字にする

物理的な下限があるので、先に決めておかないと終わりが無い。

| 用途 | 要求 | 到達手段 |
|---|---|---|
| 星座の同定・AI 解説 | ±20° | **いまの段階 1（スマホ同期）で成立している** |
| 星座名ラベルを方向に置く | ±5〜10° | 段階 1 ＋ 磁気の質を上げる |
| **星図を空に重ねる** | **±2〜3°** | **天体アライメントが必要** |
| **点が星に乗って見える** | **中心 ±1° / 視野端 ±2°** | 天体アライメント ＋ 画角の実測 ＋ ロール追従 |

- **1 画素 = 0.066°**（528px で横 35°）なので、描画側の丸めは誤差の話に出てこない
- **±1° より下は追わない。** グラスは鼻の上で動き、かけ直すたびにパネルと眼の相対位置が
  数 mm 変わる。**per-wear の再現性そのものが 1〜2° ある**と見ておくのが安全
- **「ずれの絶対値」より「ずれ方の質」が体験を決める。** 平行移動のずれは脳が勝手に補うが、
  **回転（ロール）と倍率（画角）のずれは形が合わないので必ず気づかれる**。
  つまり **±1° の平行移動より、5° のロール誤差のほうが「重なっていない」と見える**

## 1. いまの誤差の内訳

実測済みのものと未測定のものを分けてある。**未測定の 2 つが視野端で効く。**

| 出どころ | 中心での大きさ | 視野端（17.5°）での大きさ | 時間で増えるか | 状態 |
|---|---|---|---|---|
| **方位合わせ時の地磁気** | **±5〜15°** | 同じ | 増えない | 実測 |
| **画角（倍率）の思い込み** | 0° | **10% 違えば 1.75°** | 増えない | **未測定**（`STAR_MAP_FOV_DEG = 35.0` は仮） |
| **ロール未追従** | 0° | **首を 15° 傾けて 4.6°** | 傾けるたび | **未実装**（地平線を水平に固定中） |
| パネルの取り付け・眼の位置 | 未測定 | 未測定 | かけ直すと変わる | 未測定 |
| 首を振っている間のドリフト漏れ | 首振り 2 秒で 1.5° | 同じ | **動いた分だけ溜まる** | 補正実装済み・残差未測定 |
| 静止中のドリフト | **0.0°/分** | 同じ | 増えない | 実測で解決済み |
| 歳差・大気差・時角 | < 0.02° | < 0.02° | — | 実装済み |

**方位（±5〜15°）が支配的な間は、他を詰めても体験は変わらない。** 順番を守る。

## 2. 検討して捨てた手段

**採ったのは A だけ。** ほかは「手順が増える」か「実測の場が要る」ので、
精度より UX を採った時点で全部落ちた。効果 ÷ コストの順に並べてある。

| | 手段 | 効果 | 落とした理由 |
|---|---|---|---|
| **A** | 磁気の歪みを検知して警告する | 悪い方位合わせに気づける | **採った**（`MagneticQuality`）。止めずに警告するだけ |
| B | 同じ手順を 3 方向でやって平均する | ±5〜15° → ±3〜8° | **手順が 3 倍**。打ち消せるのは方位依存成分だけ |
| C | 画角（倍率）を実測する | 視野端のずれ 1.75°/10% | 測る場（壁と巻尺・既知の 2 星）が要る。**仮の 35° のまま** |
| **D** | **天体アライメント**（十字を明るい星に重ねる） | **±5〜15° → ±1°** | **夜の屋外で初心者に首を振らせる。** 実装・テストまで作って撤去した |
| E | ロールを追従する | 首を 15° 傾けて端 4.6° | 傾けるたび 528×330 を送り直す＝0.4 秒画面が消える |
| F | 首振り中のドリフト漏れを詰める | 2 秒の首振りで 1.5° | 閉ループにする手段が無い（カメラが無い）。溜まったら合わせ直させるだけ |
| G | 凍結した星図を手で合わせる | D と同等 | D の代替。同じソルバに乗るが、入口の手順は同じだけ増える |
| H | スマホのカメラでプレートソルブ | ±0.1° | **スマホの姿勢をグラスへ移す工程が残る**ので、関門が段階 1 と同じ |
| I | 見せ方で誤差を吸収する | 体感に効く | **一部は採った**（見えない星を描かない＝限界等級を落とす） |

**H の結論だけは覚えておく価値がある。** カメラで空を解いても、
**その姿勢をグラスへ移す工程が新しいボトルネックになる**ので、精度の天井は上がらない。

## 3. 他アプリと学術の調査（2026-08-21）

**磁気の誤差は誰も解決していない。** 我々のボトルネックは業界のボトルネックだった。

- **姿勢の取り方は全アプリ共通**（加速度＋磁力計＋ジャイロの融合）で、構造は我々と同じ
- **手動オフセットは業界標準。** しかも「**明るい天体に合わせる**」で揃っている
  （Sky Map / SkySafari / Sky Guide / Star Walk 2 / PhotoPills）。
  **どのアプリも「ドラッグで直す」退路を必ず持っている**
- **名前を知らなくていい形の完成形は望遠鏡側にある**（Celestron SkyAlign）。
  適当な 3 天体に向けるだけで機種が同定する。**2 点は大きく離す**が共通の結論
- **光学シースルー HMD の学術的な正解は SPAAM**（十字を世界の点に複数姿勢から合わせる）。
  相手が無限遠なら眼の位置の未知が式から落ちる。**人の合わせ精度は 0.25° が実証済み**
- **精度の天井はプレートソルブだが、どれも別ハードで解いている**（StarSense Explorer は
  スマホを鏡で望遠鏡に向ける）。ジャイロ相対モード（AstroHopper）は我々と同じ穴を持つ

**この調査の結論が「精度を追わない」判断の裏付けになった。** 業界が解けていない誤差に、
初心者向けの体験で正面から挑む価値は無い。
