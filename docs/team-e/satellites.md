# 人工衛星モードの調査

- **星座モードと切り替えて、いま空を通っている人工衛星を出す。**
  座標系と描き方は星図と同じだが、**画面は排他**（衛星モードでは星も星座線も星座名も出さない）
- 描画とグラスへの送り方は [座標変換パイプライン](coordinate-system.md) をそのまま使えるが、
**衛星は星と違って動く**ので、更新の作りだけが別問題になる。

調査から実装まで。**軌道計算と、星図と同じ座標系への描画は動いている**（実機での見え方は未確認）。

## いまどこまで動いているか

| できたこと | 確かめ方 |
|---|---|
| SGP4 / SDP4 の伝播 | 参照実装と **151 点で最大 4mm 差**（`Sgp4Test`） |
| 観測地から見た方位・高度 | 静止軌道の幾何の式と 0.1° 以内（`ObserverTest`・`CatalogTest`） |
| 太陽の位置と地球の影 | 分点・至点の赤緯、真夜中の衛星が影に入ること（`SunlightTest`） |
| 名前つき 24 機 ＋ スターリンク 10,748 機 | 全機を伝播できる。全機で **7ms**（`CatalogTest`） |
| 最接近までの時間 | 静止軌道では出さない・低軌道では実際に距離が縮む（`SatelliteSceneTest`） |
| 星図と同じ座標での描画 | 点と輪郭を焼いて**バッファ 355,000 / 380,000 バイト**（`SatelliteSceneTest`） |
| `DOUBLE_TAP` での切り替え | **実機未確認**（ジェスチャーはこのアプリで初めて使う） |

**まだ実機で見ていない。** グラスに点と輪郭と名前が出るか、`●`／`○` の文字が出るかは次の課題。

## 結論から

| 論点 | 調べた結果 |
|---|---|
| 軌道計算 | **SGP4 / SDP4 を自前で書いた。** 参照実装と 4mm 差で一致（151 点で検算） |
| 軌道データ | **名前で分かるもの 24 機を手で選ぶ**（ISS・天宮・ハッブル・GPS・ガリレオ・ひまわり・みちびき・だいち・NOAA・ランドサット…）＋ **スターリンク 10,748 機・1.8MB**（実測） |
| データの寿命 | TLE は 1 日 1〜5km ずれる。**角度にすると 500km 先で 0.6°/日**。数日なら実用 |
| 明るさ | 標準等級のデータはライセンスが不明。**ISS など数個だけ手で持つ** |
| 見える時間 | 低軌道は**日没後・日の出前の 1〜3 時間だけ**。**みちびきとひまわりは常に頭上**（ただし肉眼では見えない） |
| **見えない衛星** | **出す。** スターリンクは大半が肉眼の限界より暗いので、出さないと機能にならない |
| 描き方 | **点と輪郭＝画像（遅い）、いまの位置と名前＝キャンバスのテキスト（速い）に分ける** |
| 輪郭 | **2 機まで。引き出し線でつないだ枠に入れ、名前は枠の上**（実物大では 0.24 画素） |
| 切り替え | **`DOUBLE_TAP`**（決定） |

## 軌道計算 — なぜ SGP4 が要るか

TLE（Two-Line Element）に入っているのは**平均軌道要素**で、値そのものが SGP4 という
モデルの中でだけ意味を持つ。ケプラー運動として素直に外挿すると、**数時間で見当外れになる**。
TLE を使うなら SGP4 を使う、が事実上の決まり。

### ライブラリの比較

| 候補 | ライセンス | 判断 |
|---|---|---|
| [predict4java](https://github.com/davidmoten/predict4java) | **GPL**（C 版 5B4AZ の系譜） | **使えない。** このリポジトリは Apache 2.0 |
| [Orekit](https://www.orekit.org/) | Apache 2.0 | 天体力学の総合ライブラリ。**重い**うえ、うるう秒・地球姿勢のデータ束（orekit-data）を別に抱える必要があり、端末同梱に向かない |
| Vallado の参照実装を自前移植 | 公開（Celestrak 配布） | **これを推す。** 700〜1,000 行程度。`Astro.kt` を自前で書いたのと同じ考え方 |

**自前移植を推す決め手は検算できること。** Vallado の配布物には検証用の
`SGP4-VER.TLE` と期待値 `tcppver.out` が付いていて、**JVM テストで数値を突き合わせられる**。
座標変換を `AstroTest` で潰したのと同じやり方が使える。

- Android 版の有名アプリ [Look4Sat](https://github.com/rt-bishop/Look4Sat) は predict4java を使っていて、
  アプリ自体も GPL。**参考にはできるが取り込めない**

**合計 24 機で打ち止めにする。**

- **日本のものだけだと「有名な衛星」にならない。** ハッブル・GPS・ガリレオ・ランドサットは
  名前を聞けば分かる側で、**GPS は「毎日使っているものが頭上にいる」**という驚きがある
- **24 機より増やしても見え方は変わらない。** 視野に出せる名前はキャンバスのテキスト枠
  （8 個）で頭打ちになり、スマホの一覧も 12 件まで。**選ぶ基準は「名前で分かるか」だけ**
- **GPS とガリレオは中軌道なので深宇宙の分岐（SDP4）に入る。** みちびき・ひまわりと合わせて
  10 機がそちら（`CatalogTest` で確認）
- 番号は Celestrak に問い合わせて確かめた実際の値
- **みちびき初号機（37158）は入れない。** 平均運動 0.877 周/日 ＝ 周期 27.4 時間で、
  **静止軌道より上の廃棄軌道に上げられている**（後継の 1R に交代済み）。
  「みちびき」として出すと嘘になる
- 日本の衛星をもっと足すのは簡単。**名前と NORAD 番号を 1 行足すだけ**にする

### 日本の衛星は「いつでもそこにいる」

**これが効く。** みちびきとひまわりは低軌道の衛星とまるで性質が違う。

| | 低軌道（ISS・スターリンク） | **準天頂・静止（みちびき・ひまわり）** |
|---|---|---|
| 空での動き | **1 秒に 1°** | **1 時間に 15°**（静止はほぼ止まっている） |
| 見えるとき | 日没後・日の出前だけ | **常に頭上にいる**（明るさの条件は別） |
| 高さ | 300〜550km | **32,000〜36,000km** |
| 明るさ | 4〜7 等 | **11〜13 等。肉眼では絶対に見えない** |
| TLE の誤差の効き | 500km 先で 0.6°/日 | **36,000km 先なので 0.008°。無視できる** |

- **みちびきは日本の真上を通るように作られた軌道**（準天頂軌道）。傾斜角 40° 前後・
  離心率 0.07 で、1 日かけて 8 の字を描き、**8 時間ほど天頂近くに留まる**
- ひまわりは東経 140.7° の静止軌道なので、**鯖江からは南の空の決まった一点**に見える
- **つまり「いつ試しても必ず何か出る」。** 低軌道の衛星は薄暮の時間帯を待つ必要があるが、
  みちびきとひまわりは**昼でも夜でもそこにいる**ので、開発中もデモも困らない
- 肉眼では見えないので、**グラスが指し示さないと存在に気づけない**。
  「あそこにみちびきがいる」は AR でしか成立しない体験

### どこから取るか

名前を指定して 1 機ずつ問い合わせると回数が増えるので、**グループ単位で落として、
NORAD 番号で絞る**。

| グループ | 大きさ | 取れるもの |
|---|---|---|
| `stations` | 小 | ISS・天宮 |
| `gnss` | 中 | みちびき |
| `geo` | 中 | ひまわり |
| `resource` | 中 | だいち・しきさい・しずく・いぶき |
| `starlink` | **1.8MB** | スターリンク |

- **1 日 5 リクエスト**。100MB/日 の枠に対して余裕がある
- **`starlink` は「更新期間ごとに 1 回まで」**という追加の制限がある（2026-03 から）
- どの衛星がどのグループに入るかは**取得スクリプトで確かめて記録する**

### 取得の作法（[公式の説明](https://celestrak.org/NORAD/documentation/gp-data-formats.php)）

- **データの更新は 2 時間ごと。** 更新前に取り直しても意味がない
- **1 IP あたり 1 日 100MB。** 更新期間内に繰り返し落とすと **HTTP 403**
- エラーを 2 時間で 50 回出すとファイアウォールで弾かれる
- 非営利で運営されているので、**必要なときに必要なぶんだけ**

→ **1 日 1 回で十分。** さらに、[座標変換パイプライン](coordinate-system.md) で決めたとおり
**夜空の下は電波が悪い**ので、星表と同じく `data/` に同梱し、
**オンラインのときに静かに更新する**作りにする（古くても動く、が原則）。

### TLE はどれくらいで古くなるか

一般に **1 日あたり 1〜5km** ずれ、低軌道では 7〜10 日で無視できない量になる。
太陽活動で大気密度が変わると SGP4 の抵抗モデルが追随できないのが主因。

**この用途では角度に直して考える。** 誤差 5km は距離 500km の相手なら **0.6°**。
いまの画角（35° を 528px）だと **9 画素**なので、**1 日古くても見た目にはほぼ影響しない**。
1 週間で 2〜3° ＝ 35〜45 画素になり、そろそろ気になる。

- 誤差の大半は**進行方向のずれ ＝ 時刻のずれ**として出る。5km は ISS の 0.7 秒ぶん
- **「1〜2 日以内の TLE なら実用、1 週間で怪しい」**を運用の目安にする
- **古さは取得日ではなく元期（TLE 自身の時刻）で測る。** 取得スクリプトはキャッシュを
  2 時間使い回すし、落とした時点で元期はすでに数時間〜1 日前になっている。
  同梱データの実測で**取得 0.02 日前・元期 0.40 日前**だった（`SatelliteSceneTest`）

## 明るさをどう出すか

- 標準等級（1000km・半月状態での明るさ）の一覧は **McCants の `qs.mag`** が定番で、
  Stellarium の衛星プラグインなどが使っている。**ライセンスがはっきりしない**ので同梱は避ける
- **`GROUP=visual` は「肉眼で見える明るさのもの」という選抜そのもの。** 157 個に絞られているので、
  等級のデータが無くても「出す/出さない」の判断には足りる
- 相対的な明るさは、**距離と位相角**から出せる（球体近似）：

```
見かけの等級 ≒ 標準等級 - 15.75 + 2.5 * log10( 距離km^2 / 照らされている割合 )
照らされている割合 = (1 + cos(位相角)) / 2
```

  標準等級が要るので、**ISS や CSS など数個だけ手で持つ**のが現実的
  （ISS はおよそ -1.8 等）。それ以外は「明るいものリストに入っている」として一律に描く

### スターリンクは「肉眼では見えない」のが普通

**ここは期待値を揃えておきたい。** 減光対策後のスターリンクの実測平均は：

| 種類 | 平均等級 | 肉眼（6 等が限界） |
|---|---|---|
| Gen2 Mini（減光モード） | **7.06** | **見えない**（双眼鏡なら見える） |
| Direct-to-Cell（高度が低い） | **4.62** | 暗い空なら見える |
| 打ち上げ直後の「トレイン」 | 1〜3 等 | **はっきり見える。数珠つなぎで有名なやつ** |

つまり「あそこにスターリンクがある！」を肉眼だけでやろうとすると、**ほとんどの機体は見えない**。

**これはむしろグラスの出番。** 肉眼で追えないものを指し示せるのが AR の価値で、
「いま頭上を 10 機通っている」と示せること自体が体験になる。
ただし**見える機体と見えない機体は描き分ける**（肉眼で見えるものだけ塗る、など）。

## いつ見えるのか — ここが体験を決める

人工衛星が肉眼で見えるのは、**衛星が太陽に照らされていて、地上が暗いとき**だけ。

| 条件 | 内容 |
|---|---|
| 地平線より上 | 当然 |
| 衛星が日照 | **地球の影に入っていない** |
| 観測者が薄暮以上に暗い | 太陽高度が **-6° より下** |

低軌道の衛星は地上 400〜800km を飛んでいるので、**日没後・日の出前の 1〜3 時間**に集中する。
**真夜中は衛星ごと地球の影に入るので、空には何も光っていない**（夏至前後の高緯度を除く）。

### 見えないときも出すか → **出す（決定）**

- グラスは AR なので、**「見えないがそこに ISS がいる」も成立する**。
  むしろ肉眼で追えないものを示せるのがグラスの価値
- 見える／見えないを**描き分ける**（日照なら塗り、影なら輪郭だけ、など）
- こうすると**真夜中でもデモが成立する**。薄暮の 1 時間しか動かない機能は開発中に確かめづらい
- **スターリンクは大半が肉眼の限界より暗い**ので、見えるものだけに絞ると機能そのものが成立しない

そのためには**太陽の位置**が要る。`Astro.kt` に低精度の太陽位置（誤差 0.01° 程度）を足せばよく、
20 行ほどで済む。**星図の昼夜判定にも使える**（いまは昼でも星を描いている）。

## 一度に何機が視野に入るか

スターリンクを入れると数が桁違いになるので、概算しておく。

**高度 550km の衛星が地平線より上に来るのは、真下の点が観測地から 23° 以内のとき**
（`cos λ = R / (R + h)`）。地球の表面積に対する割合は 4.0%。

| 見積り | 数 |
|---|---|
| 地平線より上のスターリンク | **10,748 × 4.0% ≒ 400 機** |
| 視野（35° × 22°）に入る割合 | 全天 2π sr に対して 3.7% |
| **視野の中のスターリンク** | **10 機前後** |

- 傾斜角 53° が主力なので、**鯖江（北緯 36°）はむしろ密度が高い側**
- このうち日照されているのは時間帯しだい。日没直後はほとんど、真夜中は少数
- **10 機前後なら「空が点だらけで読めない」にはならない。** ただしテキスト枠は 8 個しかない

### 計算量 — 測ったら心配なかった

移植した SGP4 で実際に測った（JVM・10,748 機・`CatalogTest`）：

| 段 | 時間 |
|---|---|
| TLE を全部読む | **46 ms** |
| 全機の初期化 | **5 ms** |
| **全機を伝播して観測地から見た方位・高度まで出す** | **7 ms** |
| 地平線より上にいた数 | **460 機**（見積りは 400 機だった） |

**全機を毎秒回しても問題にならない。** 端末は JVM より遅いとしても数十 ms なので、
当初考えていた「30 秒ごとの粗い絞り込み ＋ 毎秒の細かい追跡」の 2 段構えは要らない。
必要になったら足せばよく、**先に複雑にしない**。

## 描き方 — 衛星は速い

**ここが一番の制約。**

ISS は秒速 7.7km で飛んでいるので、**天頂近くでは 1 秒に約 1.1° 動く**。
いまの画角と画素数（35° を 528px ＝ 15 px/°）に直すと：

| 位置 | 角速度 | 画面上の速さ |
|---|---|---|
| 天頂付近（距離 420km） | **約 1.1 °/秒** | **約 16 画素/秒** |
| 地平線近く（距離 2,000km） | 約 0.2 °/秒 | 約 3 画素/秒 |

視野 35° を横切るのに**天頂なら 33 秒**。一方、**星図の画像は 1 枚 0.5〜1 秒かかる**
（[座標変換パイプライン](coordinate-system.md)）。しかも
**転送中はグラスが前の絵を捨てる**ので、衛星を画像に焼き込むと「消えている間に進む」。

### 分ける

| 出すもの | 方法 | かかる時間 |
|---|---|---|
| 星図・星座線 | **画像**（`sendCanvasImage`） | 0.5〜1 秒。首が止まったときだけ |
| 衛星の位置・名前 | **キャンバスのテキスト**（`sendCanvasElements`） | **190 バイト＝1 パケット。数十 ms** |
| 衛星の輪郭（アイコン） | **画像に焼く** | 首が止まったときだけ。点の近くに置く |

**キャンバスのテキストは差分更新なので、画像に触らずに動かせる。** これが 0.2.0 以降の
キャンバスの効きどころで、**衛星のマーカーだけを動かせる**。

実装では **1.5 秒ごと**にテキストだけ送り直している（天頂の衛星で 20 画素ほどの遅れ）。
このとき**画像を焼いたときの視線**に対して位置を出すのが肝で、いまの視線で計算すると
絵と印がずれる。

- **印が付くのは名前つきの機体だけ**なので、印を動かすときはスターリンクを回さない
  （伝播が 10,748 機ぶんから 24 機ぶんに減る）
- **名前は短くする。** グラスの文字は 1 文字 28px 見当で、
  「みちびき1号機後継機」は印を足すと 316px になり、3 機並べると重なって消える。
  `tools/satellites-ja.json` の `ja` は短い名前（みちびき1R・ひまわり8）にしてある

- マーカーの文字は **`●`（日照）と `○`（影）**。名前を続けて 1 つの要素にする
  （枠を 2 つ使うと 8 個がすぐ埋まる）
- **テキスト要素は 8 個まで。** 星座名と枠を分け合う（例：衛星 2 ＋ 星座名 6）
- 別案として **32×32 の小さな画像を id 1〜7 に置く**手もある（1 パケット、バッファ 2KB）。
  形は自由になるが、枠は 8 枚で、星図と合わせてバッファ 380,000 バイトを分け合う

### 輪郭は「アイコン」として出す（決定）

点と線だけでは何が飛んでいるのか分からないので、**輪郭を出す。**
ただし**実物大の輪郭は成立しない。**

| 相手 | 大きさ | 距離 | 視角 | 528px / 35° での画素 |
|---|---|---|---|---|
| ISS | 110m | 400km | **0.016°** | **0.24 画素** |
| ひまわり8 | 5m | 36,000km | 0.000008° | 0.0001 画素 |

**肉眼でも点。** 見える大きさに描けば必ず 100 倍以上の嘘になり、
そのまま位置に重ねると 4〜6° を覆って「どこを見るか」が消える。

→ **位置は小さな点のまま置き、輪郭は引き出し線でつないだ枠の中に出す。**

```
 名前（●ISS 4分）        ← キャンバスのテキスト。枠の上に重なる
┌──────────┐
│  輪郭     │            ← 角丸の枠。画像に焼く
└──────────┘
      ─────┐
           ╲             ← 引き出し線（斜め ＋ 横）
            ●            ← 位置の点
```

- **枠を付けるのは「これは実景ではない」と一目で分かるため。** 輪郭は 100 倍以上の
  大きさで描いた嘘なので、空に浮いた点と同じ扱いに見えてはいけない
- **名前は枠の上。** 点のところではない（点に名前を重ねると位置が読めない）
- 引き出し線は**斜めに離してから横に振る**。斜めだけだと枠が点の真上に来て名前と近すぎる
- **2 機まで。** 視野中心に近い順で、1 機目と 2 機目は左右に振り分ける。
  **名前は枠の上に出るので、枠が近いと名前どうしが重なって片方が消える**
- **吹き出しが付かない機体には名前を出さない。** 枠の上の名前と点のところの名前が
  並ぶと、重なったほうが落ちて「枠だけ・名前だけ」になる。3 機目以降は点だけ
- 形は 3 種類だけ（緑 8 階調・96 画素でそれ以上は描き分けても読めない）
  - **有人** = 長いトラスに 4 枚のパネル（ISS・天宮）
  - **気象** = 箱＋片翼＋パラボラ（ひまわり）
  - **それ以外** = 箱＋両翼＋アンテナ（みちびき・だいち・いぶき・しきさい・しずく）
- 転送量はほぼ増えない（**輪郭 1 機で 600 画素**、圧縮後は数百バイト）
- 判定は**名前の先頭**で行う。TLE には日本語名しか入っていないため

### 軌跡の線はやめた（決定）

**この先 1〜2 分の道筋を線で焼く**作りにしていたが、実際に描くと
**画面が線で埋まって「どれが衛星か」が読めない**（星座線と同じ問題が、星を消しても残った）。

→ **出すのは「大体どの辺にいるか」の点と、そのそばに置く輪郭だけ。**

- 線をやめたので、**伝播も 1 機 1 回で済む**（前後 3 分を 10 秒刻みで 19 回 → 1 回）
- **点を同じ大きさで並べると「点々」にしか見えない。** 3 つ描き分ける
  - **名前つき** — 大きい点 ＋ 囲む輪（主役に見える）
  - **スターリンク** — 小さく暗い点（群れとして見せる。名前つきが埋もれない）
  - **動いているもの** — **30 秒後の位置へ向けた矢印**。輪の外から描き、長さは画面内で一定
    （実際の移動量そのままだと、高いところを通る機体だけ極端に長くなる）
- **静止軌道には矢印が出ない。** 30 秒で 3 画素も動かないものは向きが定まらないので描かない。
  出ないこと自体が「これは止まっている」という情報になる
- **進行方向に加えて「いつ」も出す**（次の節）。上昇中か下降中か、あと何分で最接近か

### 「いつ」を出す（決定）

**点だけでは、待てばいいのか過ぎたのかが分からない。** 線をやめたぶん、時間で補う。

**観測地からの距離がいちばん小さくなる時刻＝最接近**を探して出す。
低軌道の機体はそこがいちばん高く・いちばん明るいので、**待つ価値があるかどうかがこれで決まる**。

- 前後 **-5〜+20 分を 30 秒刻み**で当たって、距離の最小を探す（1 機 51 回の伝播＝ 0.03ms）
- 出せない場合を 2 つに分ける
  - **静止軌道** — 距離がほとんど変わらない（振れ幅 0.5% 未満）。
    数値のゆらぎで「あと 7 分」と出すと嘘になるので、「ほぼ静止」と言う
  - **窓の外** — 端が最小だった。本当の最小はもっと先（前）にあるので何も言わない
- 出す先は 3 つ
  - **グラスのラベル** — `●ISS 4分`。**近づいていて 10 分以内のときだけ**
    （文字数が増えるとラベルが重なって落ちる）
  - **読み上げ** — 「あと 4 分でいちばん近づきます」「いちばん近いところは過ぎて、遠ざかっています」
  - **スマホの一覧** — 「上昇中・最接近まで 4 分」
- **次のパスがいつ来るか（いま空にいない機体の予報）は別問題**で、まだ実装していない

### 10 機を 8 枠でどう捌くか

視野に 10 機いても、**テキスト要素は 8 個しかない**。
ただし**衛星モードは星座名を出さないので、8 枠を丸ごと衛星に使える**。

| 出すもの | 何機ぶん | 方法 |
|---|---|---|
| **いま居る場所と名前** | **8 機まで**（高い順） | テキスト（1.5 秒ごとに更新） |
| **位置の点** | 視野内の全機（スターリンク含む） | 画像に焼く。名前つきは大きい点 ＋ 輪 ＋ 矢印 |
| **輪郭（アイコン）** | **2 機まで**（視野中心に近い順） | 同じ画像に、引き出し線でつないだ枠として |

**点を全部打てば「空がスターリンクで埋まっている」ことは伝わる。**
名前と輪郭を出すのは主役だけでよく、**点の数そのものが「こんなに飛んでいるのか」になる**。

## 何を見せるか

グラス（狭い・190 バイト）とスマホ（広い）で役割を分ける。

| 出す場所 | 内容 |
|---|---|
| **グラス** | 位置の点、引き出し線と枠つきの輪郭、名前（`●ISS 4分`）、日照かどうか |
| **スマホ** | 今夜のパス一覧（時刻・最大仰角・明るさ）、選んだ衛星の詳細、高度・速度 |

**「同じように視覚化」の中身は、星座と同じ「見えているものに名前が付く」体験**にする。
星座は動かないので名前を置くだけでよかったが、衛星は**時間が主役**になる
（あと 2 分で最接近、あと 40 秒で影に入る、など）。

## モードの切り替え → **`DOUBLE_TAP`（決定）**

**ダブルタップで星座モードと人工衛星モードを行き来する。** いつでも有効。

- もともと `DOUBLE_TAP` に当てていた「もっと詳しく」は**行き先を失った**。
  AI 解説を作るときに割り当てを決め直す（[画面遷移とジェスチャー](app-flow.md)）
- 開発中はスマホ側にも切り替えを置く。実機でグラスを触らずに試せるほうが速い
- パスが近いときの**提案**（「あと 2 分で ISS が通ります」）は、切り替えとは別に足せる。
  ダブルタップが空いていないときの逃げ道として考えていたものなので、**優先度は下がる**

**2 つのモードは排他（決定）。** 衛星モードでは星・星座線・星座名を描かず、
星座モードには衛星を出さない。**表示面は緑 8 階調しかないので、星と衛星を
同じ絵に載せると「どれが衛星か」が読めない**（実装当初は重ねていた）。

- 転送量はほとんど変わらない。**528×330 の圧縮後は星ありで 6.7KB、衛星だけで 5.9KB**
  （真っ黒でも 32 画素で 1 バイト使うので、面積 / 32 = 5,445 バイトが下限）
- **視野に 1 機もいないと真っ黒になる**ので、そのときは「衛星なし」と文字で出す
- `要確認` 星が無い空で方角の手がかりが足りるか。足りなければ方位の目盛りか、
  いちばん明るい星だけを残す

## 実装の段取り（案）

1. ~~SGP4 を移植して JVM テストで検算~~ → **済んだ。** 参照実装をビルドして期待値を作り、
   **近地球と深宇宙の 151 点（うち深宇宙 113 点）で位置の最大差 4.1e-6 km**
2. ~~伝播にかかる時間を測る~~ → **済んだ。** 全機で 7ms なので絞り込みは要らない
3. 太陽の位置を `Astro.kt` に足す（日照判定・薄暮判定・昼夜判定に使う）
4. TLE を `data/` に同梱し、`tools/` に取得スクリプトを足す（星表と同じ作り）。
   **名前と NORAD 番号の対応表は `tools/satellites-ja.json` に置く**（`names-ja.json` と同じ考え方）
5. **みちびきとひまわりから作る。** ほぼ止まっていて常に頭上にいるので、
   動きの問題を後回しにして「衛星が出る」ところまで確かめられる
6. 視野内の低軌道の衛星を出す — 点と輪郭を画像に焼き、名前だけテキストで動かす
7. `DOUBLE_TAP` でモードを切り替える
8. ~~最接近までの時間~~ → **済んだ。** ラベル・読み上げ・一覧の 3 つに出している
9. パス予報（**いま空にいない**機体が次に来るのはいつか）と、接近の予告

## まだ確かめていないこと

- **テキスト要素を毎秒 2〜5 回送り続けたときに、グラスが追随するか。** 画像より軽いはずだが未検証
- **`sendCanvasElements` を高頻度で送りながら画像も送ったとき**の詰まり方
- 標準等級を手で持つ衛星をどこまで増やすか
- ~~10,748 機ぶんの SGP4 が何 ms かかるか~~ → **測った。JVM で 7ms**（端末では未計測）
- ~~準天頂・静止軌道でも精度が足りるか~~ → **SDP4 も移植して確かめた。**
  同梱の実データで、**ひまわり8号が鯖江から方位 172.4°・高度 48.0°・37,197km**。
  静止軌道の幾何の式（172.3° / 48.05°）と 0.1° 以内で合う
- パスの計算量（数時間ぶんの探索）を端末で毎回やるか、開いたときだけやるか
- ~~視野内の軌跡を 10 本描いたとき、**星座線と見分けが付くか**~~ → **線そのものをやめた。**
  モードも排他にしたので、衛星モードに星座線は出ない
- 点と輪郭で圧縮後サイズがどれだけ増えるか（**輪郭 3 機で 600 画素／機**。上限までは十分余裕がある）
