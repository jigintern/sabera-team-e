# 人工衛星モード

**星座モードと切り替えて、いま空を通っている人工衛星を出す。**
座標系と描き方は星図と同じ（[座標変換パイプライン](coordinate-system.md) /
[グラス出力の制約](glass-output.md)）だが、**衛星は動く**ので更新の作りだけが別問題になる。

**2 つのモードは排他。** 衛星モードでは星・星座線・星座名を描かず、星座モードには衛星を出さない。
**表示面は緑 8 階調しかないので、星と衛星を同じ絵に載せると「どれが衛星か」が読めない**
（実装当初は重ねていた）。

## いまどこまで動いているか

| できたこと | 確かめ方 |
|---|---|
| SGP4 / SDP4 の伝播 | 参照実装と **151 点で最大 4mm 差**（`Sgp4Test`） |
| 観測地から見た方位・高度 | 静止軌道の幾何の式と 0.1° 以内（`ObserverTest`・`CatalogTest`） |
| 太陽の位置と地球の影 | 分点・至点の赤緯、真夜中の衛星が影に入ること（`SunlightTest`） |
| 名前つき 24 機 ＋ スターリンク 10,748 機 | 全機の伝播で **7ms**（`CatalogTest`） |
| 最接近までの時間 | 静止軌道では出さない・低軌道では距離が縮む（`SatelliteSceneTest`） |
| 星図と同じ座標での描画 | 点と輪郭を焼いて**バッファ 355,000 / 380,000 バイト**（`SatelliteSceneTest`） |
| `DOUBLE_TAP` での切り替え | **実機未確認** |

**まだ実機で見ていない。** グラスに点・輪郭・名前が出るか、`●`／`○` の文字が出るかは次の課題。

## 決めたこと

| 論点 | 決定 |
|---|---|
| 軌道計算 | **SGP4 / SDP4 を自前で移植**（参照実装と 4mm 差） |
| 出す機体 | **名前で分かるもの 24 機** ＋ **スターリンク 10,748 機** |
| データ | Celestrak の TLE を `data/` に同梱。**1 日 1 回だけ静かに更新** |
| 見えない衛星 | **出す。** スターリンクは大半が肉眼の限界より暗いので、出さないと機能にならない |
| 描き方 | **点と輪郭＝画像（遅い）、名前＝キャンバスのテキスト（速い）** |
| 輪郭 | **2 機まで。引き出し線でつないだ枠に入れ、名前は枠の上** |
| 軌跡の線 | **やめた**（画面が線で埋まって「どれが衛星か」が読めない） |
| 切り替え | **`DOUBLE_TAP`** |
| 明るさ | 標準等級のデータはライセンス不明。**ISS など数個だけ手で持つ** |

## 軌道計算

TLE（Two-Line Element）に入っているのは**平均軌道要素**で、値そのものが SGP4 という
モデルの中でだけ意味を持つ。ケプラー運動として素直に外挿すると**数時間で見当外れになる**。

| 候補 | ライセンス | 判断 |
|---|---|---|
| [predict4java](https://github.com/davidmoten/predict4java) | **GPL** | **使えない**（このリポジトリは Apache 2.0） |
| [Orekit](https://www.orekit.org/) | Apache 2.0 | **重い**うえ `orekit-data` を別に抱える必要があり端末同梱に向かない |
| **Vallado の参照実装を自前移植** | 公開（Celestrak 配布） | **採用。** 700〜1,000 行。`Astro.kt` と同じ考え方 |

- Android の [Look4Sat](https://github.com/rt-bishop/Look4Sat) は predict4java 由来で GPL。
  **参考にはできるが取り込めない**
- 検算は `AstroTest` と同じやり方で `Sgp4Test`。
  **近地球と深宇宙の 151 点（うち深宇宙 113 点）で位置の最大差 4.1e-6 km**

### 計算量 — 測ったら心配なかった

JVM・10,748 機（`CatalogTest`）：

| 段 | 時間 |
|---|---|
| TLE を全部読む | 46 ms |
| 全機の初期化 | 5 ms |
| **全機を伝播して方位・高度まで出す** | **7 ms** |

**全機を毎秒回しても問題にならない。** 当初考えていた「30 秒ごとの粗い絞り込み ＋
毎秒の細かい追跡」の 2 段構えは要らない。**先に複雑にしない。**

## 出す機体 — 名前で分かるものに絞る

Celestrak の `GROUP=visual`（157 機）は「明るい順」の機械的な選抜なので、
`THOR AGENA D R/B` のような**名前を見ても何も分からないロケットの残骸**が並ぶ。
**`visual` にスターリンクは 1 機も入っていない**ので、スターリンクは別に取る。

| 種別 | 機体 | 軌道 |
|---|---|---|
| **有人** | 国際宇宙ステーション（25544）・天宮 CSS 天和（48274） | 低軌道 約 420km |
| **測位（日本）** | **みちびき 1R（49336）・2（42738）・4（42965）** | **準天頂** |
| | **みちびき 3（42917）・6（62876）** | **静止** |
| **気象** | **ひまわり 8（40267）・9（41836）** | **静止** |
| **地球観測** | だいち 2（39766）・4（60182）・しきさい（43065）・しずく（38337） | 太陽同期 |
| | いぶき（33492）・2 号（43672）・GW（64694） | 太陽同期 |
| **天文** | **ハッブル宇宙望遠鏡（20580）** | 低軌道 約 540km |
| **世界の定番** | テラ（25994）・アクア（27424）・ランドサット 9（49260）・NOAA 20（43013） | 太陽同期 |
| **測位（世界）** | **GPS III-1（43873）・III-7（62339）** | **中軌道 20,200km** |
| | **ガリレオ（37847）** | **中軌道 23,200km** |
| **群れ** | **スターリンク 10,748 機** | 低軌道 300〜550km |

**合計 24 機で打ち止め。**

- **日本のものだけだと「有名な衛星」にならない。** ハッブル・GPS・ガリレオ・ランドサットは
  名前を聞けば分かる側で、**GPS は「毎日使っているものが頭上にいる」**という驚きがある
- **24 機より増やしても見え方は変わらない。** 視野に出せる名前はテキスト枠（8 個）で頭打ち。
  **選ぶ基準は「名前で分かるか」だけ**
- **GPS・ガリレオ・みちびき・ひまわりの 10 機は深宇宙の分岐（SDP4）に入る**（`CatalogTest` で確認）
- **みちびき初号機（37158）は入れない。** 平均運動 0.877 周/日 ＝ 周期 27.4 時間で、
  **静止軌道より上の廃棄軌道に上げられている**（後継の 1R に交代済み）
- 追加は**名前と NORAD 番号を 1 行足すだけ**（`tools/satellites-ja.json`）
- **名前は短くする。** グラスの文字は 1 文字 28px 見当で、「みちびき1号機後継機」は
  印を足すと 316px になり 3 機並べると重なって消える（`ja` は「みちびき1R」「ひまわり8」）

### 日本の衛星は「いつでもそこにいる」

**これが効く。** みちびきとひまわりは低軌道の衛星とまるで性質が違う。

| | 低軌道（ISS・スターリンク） | **準天頂・静止（みちびき・ひまわり）** |
|---|---|---|
| 空での動き | **1 秒に 1°** | **1 時間に 15°**（静止はほぼ止まっている） |
| 見えるとき | 日没後・日の出前だけ | **常に頭上にいる** |
| 高さ | 300〜550km | **32,000〜36,000km** |
| 明るさ | 4〜7 等 | **11〜13 等。肉眼では絶対に見えない** |
| TLE 誤差の効き | 500km 先で 0.6°/日 | **36,000km 先なので 0.008°。無視できる** |

- **みちびきは日本の真上を通るように作られた軌道**（準天頂）。傾斜角 40° 前後・離心率 0.07 で、
  1 日かけて 8 の字を描き、**8 時間ほど天頂近くに留まる**
- ひまわりは東経 140.7° の静止軌道なので、**鯖江からは南の空の決まった一点**
- **つまり「いつ試しても必ず何か出る」。** 開発中もデモも困らない
- 肉眼では見えないので、**グラスが指し示さないと存在に気づけない**。
  「あそこにみちびきがいる」は AR でしか成立しない体験

## 軌道データ — Celestrak

```
https://celestrak.org/NORAD/elements/gp.php?GROUP=<group>&FORMAT=tle
```

名前を 1 機ずつ問い合わせると回数が増えるので、**グループ単位で落として NORAD 番号で絞る**。

| グループ | 大きさ | 取れるもの |
|---|---|---|
| `stations` | 小 | ISS・天宮 |
| `gnss` | 中 | みちびき・GPS・ガリレオ |
| `geo` | 中 | ひまわり |
| `resource` | 中 | だいち・しきさい・しずく・いぶき |
| `starlink` | **1.8MB** | スターリンク |

### 取得の作法（[公式の説明](https://celestrak.org/NORAD/documentation/gp-data-formats.php)）

| 制限 | 内容 |
|---|---|
| 更新間隔 | **2 時間ごと。** 更新前に取り直しても意味がない |
| 転送量 | **1 IP あたり 1 日 100MB。** 超えると HTTP 403 |
| エラー | 2 時間で 50 回出すとファイアウォールで弾かれる |
| `starlink` | **更新期間ごとに 1 回まで**（2026-03 から） |

**1 日 5 リクエスト・1 日 1 回で十分。** 非営利で運営されているので、必要なぶんだけ。
**夜空の下は電波が悪い**ので星表と同じく `data/` に同梱し、
**オンラインのときに静かに更新する**（古くても動く、が原則）。

### TLE はどれくらいで古くなるか

一般に **1 日あたり 1〜5km** ずれる（太陽活動で大気密度が変わり SGP4 の抵抗モデルが追随できない）。

**この用途では角度に直して考える。**

| 経過 | ずれ | 画角 35° / 528px での画素 |
|---|---|---|
| 1 日 | 0.6° | **9 画素。見た目にはほぼ影響しない** |
| 1 週間 | 2〜3° | 35〜45 画素。そろそろ気になる |

- 誤差の大半は**進行方向のずれ ＝ 時刻のずれ**（5km は ISS の 0.7 秒ぶん）
- **「1〜2 日以内なら実用、1 週間で怪しい」**を運用の目安にする
- **古さは取得日ではなく元期（TLE 自身の時刻）で測る。** 取得スクリプトはキャッシュを
  2 時間使い回すし、落とした時点で元期はすでに数時間〜1 日前になっている
  （同梱データの実測で**取得 0.02 日前・元期 0.40 日前**）

## 明るさ

- 標準等級（1000km・半月状態）の一覧は **McCants の `qs.mag`** が定番だが
  **ライセンスがはっきりしない**ので同梱は避ける
- **`GROUP=visual` は「肉眼で見える明るさのもの」という選抜そのもの**なので、
  等級のデータが無くても「出す/出さない」の判断には足りる
- 相対的な明るさは距離と位相角から出せる（球体近似）：

```
見かけの等級 ≒ 標準等級 - 15.75 + 2.5 * log10( 距離km^2 / 照らされている割合 )
照らされている割合 = (1 + cos(位相角)) / 2
```

  標準等級が要るので **ISS や CSS など数個だけ手で持つ**（ISS はおよそ -1.8 等）。

### スターリンクは「肉眼では見えない」のが普通

**期待値を揃えておきたい。** 減光対策後の実測平均：

| 種類 | 平均等級 | 肉眼（6 等が限界） |
|---|---|---|
| Gen2 Mini（減光モード） | **7.06** | **見えない**（双眼鏡なら見える） |
| Direct-to-Cell（高度が低い） | 4.62 | 暗い空なら見える |
| 打ち上げ直後の「トレイン」 | 1〜3 等 | **はっきり見える。数珠つなぎで有名なやつ** |

**これはむしろグラスの出番。** 肉眼で追えないものを指し示せるのが AR の価値で、
「いま頭上を 10 機通っている」と示せること自体が体験になる。
ただし**見える機体と見えない機体は描き分ける**。

## いつ見えるのか

肉眼で見えるのは、**衛星が太陽に照らされていて、地上が暗いとき**だけ。

| 条件 | 内容 |
|---|---|
| 地平線より上 | 当然 |
| 衛星が日照 | **地球の影に入っていない** |
| 観測者が暗い | 太陽高度が **-6° より下**（薄暮以上） |

低軌道の衛星は**日没後・日の出前の 1〜3 時間**に集中する。
**真夜中は衛星ごと地球の影に入るので空には何も光っていない**（夏至前後の高緯度を除く）。

**見えないときも出す（決定）。**

- グラスは AR なので**「見えないがそこに ISS がいる」も成立する**
- 見える／見えないを**描き分ける**（日照なら塗り、影なら輪郭だけ）
- **真夜中でもデモが成立する。** 薄暮の 1 時間しか動かない機能は開発中に確かめづらい

そのために**太陽の位置**が要る。`Astro.kt` に低精度の太陽位置（誤差 0.01° 程度）を足せば
20 行ほどで済み、**星図の昼夜判定にも使える**。

## 一度に何機が視野に入るか

**高度 550km の衛星が地平線より上に来るのは、真下の点が観測地から 23° 以内のとき**
（`cos λ = R / (R + h)`）。地球の表面積に対する割合は 4.0%。

| 見積り | 数 | 実測（`CatalogTest`） |
|---|---|---|
| 地平線より上のスターリンク | 400 機 | **460 機** |
| 視野（35° × 22°）に入る割合 | 全天 2π sr の 3.7% | — |
| **視野の中のスターリンク** | **10 機前後** | — |

- 傾斜角 53° が主力なので、**鯖江（北緯 36°）はむしろ密度が高い側**
- **10 機前後なら「空が点だらけで読めない」にはならない。** ただしテキスト枠は 8 個しかない

## 描き方 — 衛星は速い

**ここが一番の制約。** ISS は秒速 7.7km なので**天頂近くでは 1 秒に約 1.1° 動く**。

| 位置 | 角速度 | 画面上（15 px/°） |
|---|---|---|
| 天頂付近（距離 420km） | **約 1.1 °/秒** | **約 16 画素/秒** |
| 地平線近く（距離 2,000km） | 約 0.2 °/秒 | 約 3 画素/秒 |

視野 35° を横切るのに**天頂なら 33 秒**。一方**画像は 1 枚 0.5〜1 秒**かかり、
**転送中はグラスが前の絵を捨てる**ので、衛星を画像に焼き込むと「消えている間に進む」。

### 遅いものと速いものを分ける

| 出すもの | 方法 | かかる時間 |
|---|---|---|
| 位置の点・輪郭 | **画像**（`sendCanvasImage`） | 0.5〜1 秒。首が止まったときだけ |
| いまの位置と名前 | **キャンバスのテキスト**（`sendCanvasElements`） | **1 パケット。数十 ms** |

**テキストは差分更新なので、画像に触らずに動かせる。** これがキャンバスの効きどころ。

- 実装では **1.5 秒ごと**にテキストだけ送り直す（天頂の衛星で 20 画素ほどの遅れ）
- **画像を焼いたときの視線**に対して位置を出すのが肝。いまの視線で計算すると絵と印がずれる
- **印が付くのは名前つきの機体だけ**なので、印を動かすときはスターリンクを回さない
  （伝播が 10,748 機ぶんから 24 機ぶんに減る）
- マーカーの文字は **`●`（日照）と `○`（影）**。名前を続けて 1 つの要素にする
  （枠を 2 つ使うと 8 個がすぐ埋まる）
- 別案として **32×32 の小さな画像を id 1〜7 に置く**手もある（1 パケット、バッファ 2KB）

### 8 枠でどう捌くか

**衛星モードは星座名を出さないので、8 枠を丸ごと衛星に使える。**

| 出すもの | 何機ぶん | 方法 |
|---|---|---|
| **いま居る場所と名前** | **8 機まで**（高い順） | テキスト（1.5 秒ごとに更新） |
| **位置の点** | 視野内の全機（スターリンク含む） | 画像。名前つきは大きい点 ＋ 輪 ＋ 矢印 |
| **輪郭（アイコン）** | **2 機まで**（視野中心に近い順） | 同じ画像。引き出し線でつないだ枠 |

**点を全部打てば「空がスターリンクで埋まっている」ことは伝わる。**
名前と輪郭は主役だけでよく、**点の数そのものが「こんなに飛んでいるのか」になる**。

### 点は 3 つに描き分ける

**同じ大きさで並べると「点々」にしか見えない。**

| 種類 | 描き方 |
|---|---|
| **名前つき** | 大きい点 ＋ 囲む輪（主役に見える） |
| **スターリンク** | 小さく暗い点（群れとして見せる。名前つきが埋もれない） |
| **動いているもの** | **30 秒後の位置へ向けた矢印**。輪の外から描き、**長さは画面内で一定** |

- 長さを実際の移動量そのままにすると、高いところを通る機体だけ極端に長くなる
- **静止軌道には矢印が出ない**（30 秒で 3 画素も動かないものは向きが定まらない）。
  出ないこと自体が「これは止まっている」という情報になる

### 輪郭は「アイコン」として出す

点と線だけでは何が飛んでいるのか分からない。ただし**実物大の輪郭は成立しない。**

| 相手 | 大きさ | 距離 | 視角 | 528px / 35° での画素 |
|---|---|---|---|---|
| ISS | 110m | 400km | 0.016° | **0.24 画素** |
| ひまわり8 | 5m | 36,000km | 0.000008° | 0.0001 画素 |

**肉眼でも点。** 見える大きさに描けば必ず 100 倍以上の嘘になり、
そのまま位置に重ねると 4〜6° を覆って「どこを見るか」が消える。

→ **位置は小さな点のまま置き、輪郭は引き出し線でつないだ枠の中に出す。**

```
 名前（●ISS 4分）        ← キャンバスのテキスト。枠の上に重なる
┌──────────┐
│  輪郭     │            ← 角丸の枠。画像に焼く
└──────────┘
      ─────┐
           ╲             ← 引き出し線（斜め ＋ 横）
            ●            ← 位置の点
```

- **枠を付けるのは「これは実景ではない」と一目で分かるため。**
  100 倍以上の嘘なので、空に浮いた点と同じ扱いに見えてはいけない
- **名前は枠の上**（点に名前を重ねると位置が読めない）
- 引き出し線は**斜めに離してから横に振る**（斜めだけだと枠が点の真上に来て名前と近すぎる）
- **2 機まで。** 視野中心に近い順で、1 機目と 2 機目は左右に振り分ける
- **吹き出しが付かない機体には名前を出さない。** 枠の上の名前と点のところの名前が並ぶと、
  重なったほうが落ちて「枠だけ・名前だけ」になる。3 機目以降は点だけ
- 形は 3 種類だけ（緑 8 階調・96 画素でそれ以上は描き分けても読めない）。
  判定は**名前の先頭**で行う（TLE には日本語名しか入っていない）

  | 形 | 機体 |
  |---|---|
  | **有人** = 長いトラスに 4 枚のパネル | ISS・天宮 |
  | **気象** = 箱＋片翼＋パラボラ | ひまわり |
  | **それ以外** = 箱＋両翼＋アンテナ | みちびき・だいち・いぶき・しきさい・しずく |

- 転送量はほぼ増えない（**輪郭 1 機で 600 画素**、圧縮後は数百バイト）

### 軌跡の線はやめた

**この先 1〜2 分の道筋を線で焼く**作りにしていたが、実際に描くと
**画面が線で埋まって「どれが衛星か」が読めない**（星座線と同じ問題が、星を消しても残った）。

- 線をやめたので**伝播も 1 機 1 回で済む**（前後 3 分を 10 秒刻みで 19 回 → 1 回）
- 転送量は星ありで 6.7KB、衛星だけで 5.9KB。**ほとんど変わらない**
  （真っ黒でも 32 画素で 1 バイト使うので、面積 / 32 = 5,445 バイトが下限）

## 「いつ」を出す

**点だけでは、待てばいいのか過ぎたのかが分からない。** 線をやめたぶん、時間で補う。

**観測地からの距離がいちばん小さくなる時刻＝最接近**を探して出す。
低軌道の機体はそこがいちばん高く・いちばん明るいので、**待つ価値がこれで決まる**。

- 前後 **-5〜+20 分を 30 秒刻み**で当たって距離の最小を探す（1 機 51 回の伝播＝ 0.03ms）
- 出せない場合を 2 つに分ける
  - **静止軌道** — 距離がほとんど変わらない（振れ幅 0.5% 未満）。
    数値のゆらぎで「あと 7 分」と出すと嘘になるので「ほぼ静止」と言う
  - **窓の外** — 端が最小だった。本当の最小はもっと先（前）にあるので何も言わない

| 出す先 | 内容 |
|---|---|
| **グラスのラベル** | `●ISS 4分`。**近づいていて 10 分以内のときだけ**（文字数が増えるとラベルが落ちる） |
| **読み上げ** | 「あと 4 分でいちばん近づきます」「いちばん近いところは過ぎて、遠ざかっています」 |
| **スマホの一覧** | 「上昇中・最接近まで 4 分」 |

**次のパスがいつ来るか（いま空にいない機体の予報）は別問題**で、まだ実装していない。

## 何を見せるか

| 出す場所 | 内容 |
|---|---|
| **グラス** | 位置の点、引き出し線と枠つきの輪郭、名前（`●ISS 4分`）、日照かどうか |
| **スマホ** | 今夜のパス一覧（時刻・最大仰角・明るさ）、選んだ衛星の詳細、高度・速度 |

星座と同じ「**見えているものに名前が付く**」体験にする。
星座は動かないので名前を置くだけでよかったが、**衛星は時間が主役**になる
（あと 2 分で最接近、あと 40 秒で影に入る）。

- **視野に 1 機もいないと真っ黒になる**ので、そのときは「衛星なし」と文字で出す
- **開発中はスマホ側にも切り替えを置く**（実機でグラスを触らずに試せるほうが速い）
- パスが近いときの**提案**（「あと 2 分で ISS が通ります」）は切り替えとは別に足せる。
  ダブルタップが空いていないときの逃げ道だったので**優先度は下がる**
