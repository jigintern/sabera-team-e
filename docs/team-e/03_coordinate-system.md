# 座標変換パイプライン

星表の「シリウスは赤経 6h45m、赤緯 −16.7°」を、グラスの「(x, y) = (120, 47) に点を打つ」へ
変換する仕様。出力側の制約は [グラス出力の制約](02_glass-output.md)。

**間にある基準の違いは 4 つ。** 星表は 2000 年基準 / 地球が自転している / 観測地が違う /
頭の向きが違う。

## 全体像

**グラスは表示とセンサーに徹し、計算はすべてスマホ側。**

![システム構成](diagrams/system.drawio.svg)

![座標変換パイプライン](diagrams/pipeline.drawio.svg)

| 項目 | 決定 |
|---|---|
| 投影方式 | ステレオ投影（等角） |
| FOV | **35° 固定・未実測**（`ObservationDefaults.STAR_MAP_FOV_DEG`） |
| ロール | **地平線を水平に固定**（追従は実装していない） |
| 星座の判定 | 視野中心を B1875.0 へ変換し、Roman (1987) の IAU 境界で一意に決める |
| 星表 | d3-celestial（BSD-3-Clause）を 5 等でフィルタして同梱 |
| 出力 | キャンバスの画像（星図）＋ テキスト（星座名） |
| 方位 | **スマホ同期の 1 回だけ**（天体アライメントは見送り。[理由](14_alignment-accuracy.md)） |

## 実装方針

### 内部表現は単位ベクトル

角度→角度で書くと**天頂で方位角が定義できない**／**`cos h` で割れない**という 2 つの罠がある。
単位ベクトルなら ①〜④ がすべて 3×3 回転行列の積になり、特異点が消える。

```
v_screen = R_attitude · R_horizon(φ) · R_hourangle(H) · R_precession · v_catalog
```

- **歳差行列は起動時に 1 回、緯度の行列は場所が変わるまで固定**なので事前に合成する
- 毎フレーム変わるのは時角と姿勢だけ。1,627 個の星を毎フレーム変換するので効く

### 座標系の規約

**符号バグの温床。** 実装では 1 箇所に定数として置く。

| 決めること | 採用 |
|---|---|
| world 座標系 | ENU（X=東, Y=北, Z=天頂）。Android の `getRotationMatrix` と同じ |
| 方位角 | 北 = 0°、東回り |
| 手系 | 右手系 |

### 時刻

- **UTC をそのまま使ってよい。** `DUT1` は最大 13″ で歳差への影響も無視できる
- **`D = JD − 2451545.0` を直接計算する。** `JD ≒ 2,460,000` を Double で持つと精度が落ちる
- **端末時計のずれは別問題。** 1 分で 0.25°、**タイムゾーンの取り違えは 9 時間 = 135°**
- `syncTime()` は時刻を**グラスへ送る**もので、こちらの計算には関係しない

## ① 歳差

自転軸が約 26,000 年周期で首を振るため赤経赤緯の原点がずれる。

| 効果 | 量 | 扱い |
|---|---|---|
| **歳差**（J2000 → 2026 年） | **約 0.36°** | **必須。** 満月の直径に近く、無視すると星座線が明らかにずれる |
| 章動 | 17″ | 無視 |
| 固有運動 | 数十″ | 無視 |
| 光行差 | 20″ | 無視 |

## ② 恒星時

```
GMST = 18.697375 + 24.065709824279 × D    （時間単位）
LST  = GMST + 経度 / 15                    （東経を正）
H    = LST − α
```

係数が 24 でなく 24.0657 なのは、**恒星日が太陽日より約 4 分短い**ため。

## ③ 地平座標変換

```
sin h = sin φ · sin δ + cos φ · cos δ · cos H
A = atan2( −cos δ · sin H,  sin δ · cos φ − cos δ · sin φ · cos H )
```

大気差は高度 0° で約 29′、10° で約 5′、45° で約 1′。描画は Bennett の標準大気近似で
見かけの高度へ補正し、視線から星座を判定するときは反復して幾何学的高度へ戻す。

## ④ 姿勢

| 量 | 可否 | 理由 |
|---|---|---|
| pitch・roll | **絶対値が取れる** | 加速度計が重力を測る |
| yaw | **絶対値が取れない** | 磁力計が無い |
| 方位の変化量 | 取れる（ドリフトする） | ジャイロの積分 |

**未知数は方位オフセット 1 つだけ。**

`imuData` の 1 サンプル = 加速度[mg] / 角速度[dps] / ピッチ[度] / ヨー[度] / AR 起動からの経過[ms]。

- **`startImuData()` を呼ぶまで何も流れない**
- **`timestampMs` で間隔を計る。受信時刻を使わない**（BLE 経由で順序と間隔が乱れる）
- **送信キューが詰まるとサンプルが捨てられる**（実測 10Hz 程度。画像を送っている間も止まらない）
- **ロールは融合値に無い。** 3 軸加速度から出せることは実機で確かめたが、
  **いまの実装には入っていない**（地平線を水平に固定している）

#### ヨーは静止中も 44°/分 流れる（実測）

**`yawDegrees` をそのまま方位に使うと、星座の同定（±20°）が 27 秒で破れる。**

| | 実測 |
|---|---|
| 静止中のドリフト | **44°/分（0.73°/秒）** |
| `gyroZDps` のバイアスを引く案 | **効かない**（平均 0.058°/秒 で 12.7 倍ちがう） |
| 鉛直軸 | **`gyroXDps`**（符号はヨーと同じ） |
| 自前積分 | 10Hz の取りこぼしで**回転 90° あたり 5〜15° 足りない** |

**採った方法＝ジャイロの大きさが 2°/秒 を超えている間だけ Δ`yawDegrees` を足し、
そこから実測のドリフト率も引く。** 静止中は何も足さない。ドリフト率は静止 5 秒ごとに
アプリが自分で測り直す（`YawDriftCorrector`）。**実測 44.5°/分 → 0.0°/分。**

- 漏れるのは「動いている時間 × 0.74°/秒」だけ（2 秒の首振りで 1.5°）
- **`sendNaviCourse` で方位を外から入れても `yawDegrees` には返らない**（実機で確認）。
  **`enterNavigationPage()` はヨーの原点をリセットする**（3 秒で 64.7° 飛んだ）
- 測り方・生ログ・否定した案の詳細は **[ヨードリフトと機体座標の実測記録](15_yaw-drift.md)**

## ⑤ 投影

### ステレオ投影

| 方式 | 式 | 保つもの | FOV 40° の歪み |
|---|---|---|---|
| 心射図法 | `r = tan θ` | 大円が直線になる | 6.4% |
| **ステレオ投影** | `r = 2 tan(θ/2)` | **角度と形（等角）** | **0%** |

**星座の「形」を見せて同定させる**のが本質なので等角を優先した。
星座線は円弧になるが、**折れ線に分割すれば実用上の差は無い**（実装は 3° ごと）。

### FOV 30〜40°

空のサイズ：満月 0.5° / こぶし 10° / **オリオン座 20°** / 北斗七星 25° / さそり座 40°

| FOV | 528px での解像度 | 5 等まで視野内 |
|---|---|---|
| 20° | 26.4 px/度 | 15 個 |
| **30°** | 17.6 px/度 | 33 個 |
| **40°** | 13.2 px/度 | 58 個 |
| 60° | 8.8 px/度 | 129 個 |

**528px あるので、潰れを理由に FOV を狭める必要はない。** オリオン座が画面の半分〜2/3 を
占める大きさとして 30〜40°。パネルは 16:10 なので**横 40° なら縦 25° で、星座は縦に切れやすい**。

### ロールは地平線を水平に固定

**ロール誤差は視野中心を動かさない**（中心まわりの回転）ので、**⑦ の星座判定には影響しない**。
効くのは絵だけで、中心から r 離れた星が `r · sin θ` ずれる。

| | 首を傾けたとき | 転送 |
|---|---|---|
| **固定（既定）** | パネル上の絵は変わらない | **再送ゼロ** |
| 追従 | 絵が回る | 傾けるたびに全フレーム再送 |

**デッドバンド付きの追従は一度作ったが、main からは外した。** 以下は作ったときの設計。

- **しきい値は 12°。** 視野端（17.5°）のずれ 2·17.5·sin(θ/2) が 3.7° に収まる大きさで、
  これ以上細かく追うと**転送のほうが体験を壊す**（1 枚 0.4 秒画面が消える）
- ロール誤差は視野中心を動かさないので、**星座判定には効かない**

## ⑦ いま見ている星座を決める

星座は「点」ではなく天球上の不定形な領域なので、「この点はどの領域に属するか」の判定が要る。
**IAU の星座境界**は天球全体を 88 個で隙間なく塗り分けているので、**1 点が属する星座は一意に定まる**。

| | 状態 |
|---|---|
| **中心の星座** | **Roman (1987) の境界表**（357 行、CDS VI/42）。of-date → J2000 → B1875 と戻して一意に照合する（実装済み・JVMテスト済み） |
| **周辺の星座** | 中心の星座を先頭にし、2 個目以降だけ星座線までの角距離で並べる |

- d3-celestial の `constellations.borders.json` は閉じた多角形ではなく隣接ペアの境界線なので**描画向き**
- 生成元は `tools/build-star-catalog.py`、同梱物は `data/constellation-boundaries.json`

### ノイズ対策

判定は数学的に一意でも、生のセンサー値に当てると 2 種類のノイズが出る。

| ノイズ | 対策 |
|---|---|
| **ツルをタップすると頭が動く** | 判定は**タップ直前 0.5 秒のラッチ値**から取る（実装済み） |
| 人間の頭は常に微小に揺れている | 境界から一定角度**内側に踏み込み**、その状態が**一定時間続いたときだけ**切り替える（未実装） |

1 回きりの判定なのでヒステリシスはまだ入れていない。内側マージンと保持時間は未決定。

## ⑧ 方位合わせ

### 必要な精度は用途で桁が違う

方位オフセットの誤差 δ に対する失敗率（高度 45°、FOV 40°、実データで測定）：

| δ | 星座の名前が変わる | 答えた星座が視野の外 |
|---|---|---|
| 5° | 24% | 0% |
| 10° | 41% | 0% |
| 15° | 62% | 0% |
| 20° | 75% | 1% |
| 25° | 83% | 8% |

**±20° まで、答えた星座はほぼ必ず視野の中にある。** ユーザーは点ではなく空の一帯を見ているので、
視野に入っている星座を答えるのは正解のうち。一方 15° の誤差は星図を **10.6°** ずらす（FOV 40° の 1/4）。

| 用途 | 要求精度 |
|---|---|
| 解説する星座を決める | ±20° |
| ラベルを方向に置く | ±5〜10° |
| 星図を空に重ねる | ±2〜3° |

**解説だけならスマホ同期で足りる。** そして**このアプリが要るのは解説までなので、
方位合わせはスマホ同期の 1 回だけにした**（±2〜3° を取りにいく天体アライメントは
[見送った](14_alignment-accuracy.md)）。

### スマホ同期（実装済み・これだけ）

**グラスの十字とスマホのマーカーを重ねる。**

1. グラスのパネル中央に十字（128×128 の画像、キャンバスの id 1）を出す
2. スマホの画面中央に同心円のマーカーを出す
3. 腕の長さで持ち、**十字がマーカーの中心に重なった**ところで止める
4. **精度条件が揃ったまま 2 秒続いたら、押させずに自動で確定して観測へ進む**。
   使うのは直近 1.2 秒の複数サンプルから求めた方位と仰角のオフセット

方位は 0/360° をまたぐため円周平均を使う。6 サンプル以上・800ms 以上を集め、方位差の標準偏差
2° 以下、仰角差 1.5° 以下で、端末とグラス自身の動きも小さい場合だけ確定できる。結果の標準偏差と
サンプル数は設定パネルに残す（実装済み・JVMテスト済み、変更後の実機確認待ち）。

重なった時点で「眼 → スマホ」の向きが視線と一致するので、**スマホの位置ずれがそのまま
方位誤差になる問題が消える**（腕の長さ 50cm で 10cm 横にずれれば 11°）。

- **持ち方は顔の正面。** 合わせているのは「スマホの背面が向いている方向」と「グラスの視線」なので、
  スマホは**視線の上（腕の長さ）**に来ていないと意味がない
  （`Compass` は `remapCoordinateSystem(AXIS_X, AXIS_Z)` で背面の方位を読んでいる）
- 見上げた角度に合わせて**スマホも同じだけ倒す**。**仰角の差が 0 に近づくのが目印**
- **真上は避ける。** 背面がほぼ真上を向くと方位が定まらない。地平線から 45° くらいがよい
- **確定はボタンではなく静止で取る。** **押す動作そのものが精度を壊す**
  （顔の前にかざしたスマホの画面は見えず、指を伸ばせば頭とスマホの両方が動く）。
  **確定のボタンは置かない。** 押せるものがあると押しに行ってしまう。
  進み具合は**的の外周が緑で満ちる**ことで見せる（崩れたら 0 に戻る）
- **確定したあとは自由に動かせる**
- **星の名前を知らなくてよい。昼でも夜でも、曇っていてもできる**
- **十字を出している間は星図を消す**（バッファに 528×330 と十字は同時に入らない）
- **残る誤差は地磁気そのもの**（屋内・鉄骨・ケースの磁石で 10° 動く）。
  磁気センサーの信頼度も出す。低いまま合わせるとその誤差がそのまま星図に乗る

スマホの磁気が示すのは**スマホの方位**なので、**常時融合する定石は使えない。**
向きを揃える瞬間を作って移すしかない。

### 天体アライメント（見送った）

同じ十字を**明るい星**に合わせて、天体の真の方位からオフセットを決める案。
**実装して JVM テストまで通したが、2026-08-21 に撤去した。**

- **理由 = 精度より UX。** 使う人は天文の初心者で、要るのは「どのあたりに何があるか」。
  ±20°（星座の同定）で足りるところに、**夜の屋外で首を振らせる手順**を足す価値が無い
- **残したもの：** 月・惑星の位置計算（`sky/Ephemeris.kt`）は星図の描画と解説で使うので
  そのまま。ヨードリフト補正も、ユーザーに何もさせないので残す
- 検討の中身（合わせ先の選び方・残差の読み方・SPAAM との関係）は
  [星図を空に重ねる精度](14_alignment-accuracy.md) に記録として残してある

### 実測しないと決められないこと

1. **静止中の `gyroZDps` の平均**がヨーのドリフト率と一致するか。
   一致すれば**バイアスを引くだけで直る**ので、いちばん効く
2. **方位合わせの残差** — 残るのは地磁気の誤差。**±20° に収まっていれば星座の同定は成立する**
3. **グラス機体座標の軸定義** — **ロールを実装する前に必ず潰す**
4. **ドリフトの符号が安定するか**（上記）

## 星表データ

`tools/build-star-catalog.py` が [d3-celestial](https://github.com/ofrohn/d3-celestial)
（BSD-3-Clause）から取得・変換し、`data/` に生成する。詳細は [`data/README.md`](https://github.com/jigintern/sabera-team-e/blob/main/data/README.md)。

| ファイル | サイズ | 中身 |
|---|---|---|
| `data/stars.json` | 49 KB | 5 等までの恒星 1,627 個 |
| `data/constellations.json` | 21 KB | 88 星座の星座線＋日本語名 |
| `data/bright-stars.json` | 3 KB | 固有名のある 25 星 |

- 元期は **J2000 を実測で確認済み**（シリウス 0.7″、ポラリス 1.8″ の差＝丸め誤差の範囲）
- 元データの座標は `[lon, lat]` で `lon` は −180〜180 に折り返されているが、**生成時に 0〜360 に直してある**
- 日本語名は `tools/names-ja.json`。**88 星座すべてが埋まっていないと生成が止まる**
- **夜空の下は電波が悪いので、外部 API は使わずアプリに同梱する**
