# 星空の再現（#45）

**「いつ・どこの空か」を差し替える仕組み。** 何を再現でき、何を再現できないかをここに置く。
声の言い回しは [narration](06_narration.md)、画面の出方は [app-flow](05_app-flow.md)、
座標の理屈は [coordinate-system](03_coordinate-system.md)。

## 何を再現するか

| | できること | 出どころ |
|---|---|---|
| 場所 | 同梱 **18 都市**から選ぶ | `sky/CityCatalog.kt` |
| 日時 | 年月日と時刻。**都市のタイムゾーンで解釈する** | `sky/SkyCommand.kt` |
| 時刻を動かす | その夜の中を **±12 時間**。つまみ（**15 分刻み**）と **1 時間ずつのボタン**。どちらも**1 回に 1 枚だけ**送る | `ui/component/SimulationControls.kt` |
| 戻る | 現在地・現在時刻へ戻す | 同上 |

- **任意の地名検索はしない。** 通信と曖昧さを持ち込むうえ、**星を見に行く場所ほど電波が届かない**。
  聞き取った文字から座標を推測もしない（別名も `CityCatalog` に閉じる）
- **時刻のつまみは基準時刻からのずれで持つ。** 別に持った値を離すたびに 0 へ戻すと、
  **動かしてもつまみが中央へ跳ね返って「元に戻った」ように見える**（`TimeScrubTest`）

## 決めたこと

| 決めたこと | なぜ |
|---|---|
| **条件は打たせず選ばせる** | 使う人は天文の初心者で、**「紀元前 3000 年 8 月 24 日 20:30」を打ちたいわけではない**。場所・時代・時刻をそれぞれ数個の選択肢にした。**数字を打つ欄は置かない**（細かい指定は声に任せる） |
| **選択肢も声と同じパーサを通す** | 選んだものを日本語の一文へ組み立てて [SkyCommandParser] へ渡す。**解釈を 2 つ持たない**（片方だけ直すと「スマホでは出せるのに声では出せない」が起きる） |
| **自動で送り続けない** | 2 秒ごとに全画面を焼き直すことになり、**1 枚 279〜390ms の転送のたびにパネルが消えて原理的に点滅する**。**ボタンは「1 時間ずつ動かす」**に読み替えて、1 回押して 1 回描き直す形にした |
| **札に「シミュレーション」と書かない** | 現在の空では札そのものを出さないので、**出ていること自体が「作った空だ」の合図**になる。書くと 8 文字＝24 バイトを、190 バイトしかない枠から星座名の取り分として奪う |
| **つまみは目盛りをまたぐたび震わせる** | 画面を見ずに動かせる。動かすたびに震わせると、**指の細かい揺れで鳴り続けて何の合図か分からなくなる** |
| **時間送りの UI は置かない** | 見出しと説明文を置いた大きなカードは**星座解説の場所を食う**。観測中にいちばん使うのは解説なので、そこを譲らない。つまみは**「星空の条件」の中へ畳んだ**ので、閉じている間はメインが 1 画面に収まる |
| **つまみの位置は時刻から引き直す** | 別に持った値を離すたびに 0 へ戻すと、**動かしてもつまみが中央へ跳ね返って「元に戻った」ように見える**（`TimeScrubTest`） |
| **つまんでいる間は着地の時刻を出す** | **指がスライダーに乗るので、どこへ着くのか数字で見えないと離すまで分からない。** 読みは**つまみの上**に置く（下だと指で隠れる） |
| **15 分刻みで止める** | 星は **4 分で 1°** しか動かない。それより細かく選ばせても見分けられないうえ、「＋2時間37分」のような半端な読みが出る |
| **戻るは `DOUBLE_TAP` だけ**（[app-flow](05_app-flow.md)） | 画面ごとに戻り方が違うと、**戻りたいときに何を押すか毎回考えることになる**。再現中も `SINGLE_TAP` は解説のまま（**解説はタップだけ・通信なしで動くのが芯**） |
| **戻し方をその場で書く** | 「2 回タップで戻る」と知らないと戻れない。**条件を切り替える確認文に必ず添える**（星図のテキスト枠は使わない。あそこは 190 バイトを星座名と取り合っている） |
| **声で言えるのは 2 操作だけ**（再現・現在へ戻る） | AI へ操作の可否を委ねない。#38 と同じ理由で、**喋るだけで設定を書き換えられる状態を作らない** |
| **足りない条件は断らずに聞き返す** | 断ると最初から全部言い直しになる。聞き取れたところまでを **2 分**持ち越し、次の `HOLD` と合流させる。長く持つと**別の質問に混じった数字**が前の都市と合流する |
| **都市を言わなければいまいる場所を使う** | 「1 万年前の空」を見たいだけの人に、都市を言わせない |
| **判定は再現 → 案内 → 質問の順** | 「シドニーの夜空を**見せて**」の「見せて」は `GuidanceRequestParser` の案内語。逆順だと「その名前の天体は案内対象に見つかりませんでした」で潰れる |
| **確認文を見せてから適用する** | 聞き間違いのまま星図だけ変わると、**利用者は自分が何を見ているか分からない**。確認文の転送完了後 1.5 秒置く |
| **再現中はラベルを常時出す**（`LabelKind.STATUS`） | これが消えると、**作った空を本物と信じたまま実際の空を探す**ことになる。だからテキスト枠の**いちばん先**に置く |
| **再現中は時刻を止める** | 「20 時 30 分の空」は静止していてよい。動かすのは「再生」と明示したときだけ |
| **再現中に測位で上書きしない** | 「現在地を取り直す」を押しても、再現中の場所は変わらない |
| **TLE 元期から 7 日を超えたら衛星を出さない** | 軌道要素は数日しか持たない。**もっともらしい嘘の衛星を描かない**（理由はスマホに出す） |
| **夏時間の穴と重なりは勝手に埋めない** | 存在しない時刻・二通りある時刻は断って言い直してもらう |

## 時計の仕分け（いちばん危ないところ）

`System.currentTimeMillis()` は [StarMapScreen.kt](../../samples/kmp/app/src/main/kotlin/jp/jig/glasses/sample/kmp/ui/StarMapScreen.kt)
に 30 か所以上ある。**一括で差し替えると壊れる。**

| | 使うもの | 例 |
|---|---|---|
| **差し替える** | 空を計算するために渡す時刻 | 星・月惑星・衛星の位置、太陽高度（空の濃さ）、案内対象の算出 |
| **実時間のまま** | 計測・間隔・記録 | 転送の所要時間、静止判定（`STILL_MS`）、ラッチ（`LATCH_MS`）、ループ間隔、`NightRecord` / `AskHistory` の時刻 |

- 1 回の描画・解説は `ObservationSnapshot` を**組で持ち回る**。
  途中で引き直すと、**星・ラベル・喋る内容が別の瞬間の空になる**（#37 と同じ壊れ方）
- **AI へ渡す事実も再現時刻にする。** `AskFacts.localTime` を実時間のままにすると、
  グラスはシドニーの空を出しているのに **AI は今の鯖江の空の話をする**

## 深い時代（1 万年前・未来）

**動かせるのは紀元前 10000 年〜西暦 13000 年**（未来側が少し広いのは「1 万年後」を選べるようにするため）。 外は断る。3 つで成り立っている。

| | やったこと | 数字 |
|---|---|---|
| **長期歳差** | Vondrák, Capitaine & Wallace (2011) を入れ、**±3 世紀を超えたら `precess()` がそちらへ渡す** | IAU 1976 の 3 次式は T = 100 世紀で `theta` の 3 次項だけで **−41,833″（−11.6°）**。式が発散する |
| **固有運動** | Hipparcos 本表（CDS I/239）から HIP 番号で引き、`data/stars.json` へ 2 列足した | アークトゥルスは **2,310 mas/年 ＝ 1 万年で 6.4°**。**星座の形が変わることが見どころ** |
| **星座線** | **線の頂点にも固有運動を持たせた**（`data/constellations.json` の 3・4 列目） | 頂点は星の位置そのもの（**893 個中 892 個が 0.0 秒角で一致**、891 個に固有運動が付いた） |

- **星と線に同じ固有運動をかける。** 別々にすると、深い時代で**星だけ動いて線が置き去りになる**
- 固有運動は**接平面の大円移動**で入れる。赤経へ度を足す実装は**天の極のそばで破綻する**
- 視線速度を持っていないので、**見かけの固有運動が変わっていく効果は入らない**。
  近い星ほど誤差が出るが、星座の同定（±20°）には足りる
- **月・惑星は ±3 世紀の外では描かない。** `sky/Ephemeris.kt` の近似はそこまで作られていない。
  衛星と同じで、**もっともらしい嘘を描かず、何を出していないかを言う**
- **星座絵にも歳差はかける。固有運動はかけない。** 絵は星に載せて作ってあるが、
  動きの速い星でも 100 年で 0.03° と、絵の大きさ（十数度）に対して読み取れない
- **係数表は写し間違えても静かに間違った空が出るだけ**なので、`LongTermPrecessionTest` は
  係数に依存しない性質で検査する（±3 世紀で IAU 1976 と 20 秒角以内・
  黄道傾斜角が 21.5〜24.9°・極が 1 万年で 40〜48° 動く・往復して戻る）

### 星表を作り直す

```bash
python3 tools/build-star-catalog.py     # 固有運動は VizieR I/239 から HIP 番号で引く
```

**通信が要るのはここだけ。** アプリは同梱した JSON しか読まない。
固有運動の列が無い古い星表でも動く（0 として扱う）。

## タイムラプス（時代を送る演出）

**遡っている感を出す。ただしチカチカさせない。**

### 星を描かない。**年号だけを大きく出して高速でめくる**

チカチカの正体は描画の粗さではなく、**転送中にパネルが消えること**（[pitfalls](11_pitfalls.md)）。
転送時間は圧縮後のバイト数で決まり、その下限は **面積 ÷ 32**（RLE の連長上限が 32 なので、
**真っ黒な絵でもこれだけかかる**）。**星を減らしても下限は下がらない。**

| 出すもの | 画素 | 背景だけの下限 | 1 枚 | fps |
|---|---|---|---|---|
| 528×330 の星図（全画面） | 174,240 | **5,445 B**（＝面積÷32 ちょうど） | **279ms** | **3.6** |
| **320×88 の年号（採用）** | 28,160 | 880 B | **45ms** | **約 22** |

- **流れている間、星は誰も読めない。** 星座線も星も出さないほうが速く、しかも
  「時代が飛んでいる」ことは年号の変化だけで伝わる
- **文字の大きさはテキスト枠では変えられない**（`CanvasElement` に持っているのは
  座標と大きさと文字だけで、フォントの指定が無い）。**画像に焼く**（`GlassTextArt`）
- 全画面星図（348,480 B）と年号 2 枚（112,640 B）は**バッファに同居できない**。
  流している間は星図を消すのが容量的にも必然

### 何を数えるのか

**日周回転（1 日 1 回転）が歳差を完全に飲み込む。** 1 万年をそのまま時間で送ると 365 万回転で
何も見えない。**月日と時刻は目的地のものに固定し、「年」だけを送る。**
年号だけを出すので、めくれる速さがそのまま「遡っている感」になる。

### 作り

| | |
|---|---|
| 枠 | **320×88 を中央に**（星図は消す）。中身は年号の文字だけ |
| 枚数 | **72 枚・約 3.2 秒**（45ms × 72）。等速ではなく **ease-in-out** で出だしと着地を緩める |
| 消えない工夫 | **画像 id を 2 つ交互に使い、「新しいのを置いてから古いのを消す」**（ダブルバッファ） |
| 中断 | `DOUBLE_TAP` で即着地。**待たせない** |
| 速さ | **圧縮後のバイト数から待ち時間を出して送る。** 積むと転送が追いつかず、古い枚が順番待ちで残る |

- **精度は捨ててよい**（利用者の合意済み）。途中の枚は夏時間も月惑星も見ない
- **最後の 1 枚は必ず目的の時刻ちょうど**にする。演出の途中と着地がずれると、
  そのあと出す星図と食い違う

### 未確認（実機で決まる）

- **重ねた画像の前後関係が id 順か、置いた順か。** 置いた順なら上のダブルバッファで
  完全に消えない。**id 順だと交互の片方向で 1 枚ぶん透ける**ので、そのときは
  1 枚だけ使う形（`TIMELAPSE_DOUBLE_BUFFER`）へ落とす
- **320×88 で年号が読めるか。** 読めなければ広げる（なめらかさと引き換え）
